> እስካሁን በሰርቨሩ አልተረጋገጠም — በ#11661 መሠረት ግልጽ ተደርጓል)

Guardrails በOmniRoute እና በላይኛ ደረጃ አቅራቢዎች መካከል ባለው ወሰን ላይ
ደኅንነትን፣ ፖሊሲን እና የይዘት ለውጦችን ያስፈጽማሉ። እያንዳንዱ guardrail
የጥያቄ payload-ዎችን (`preCall`) እና የላይኛ ደረጃ ምላሾችን (`postCall`)
መመርመር (እንዲሁም እንደአማራጭ ውድቅ ማድረግ፣ መለወጥ ወይም ማብራሪያ መጨመር) ይችላል።

ስርዓቱ **fail-open** ነው፦ guardrail በሚፈጸምበት ጊዜ exception ካስነሳ፣ registryው
ጥያቄውን ከማሳካት ይልቅ ስህተቱን መዝግቦ ወደሚቀጥለው guardrail
ይቀጥላል። ማገድ ግልጽ ውሳኔ (`block: true`) እንጂ በአጋጣሚ የሚከሰት አይደለም።

### ቪዥን ብሪጅ (`visionBridge.ts`) — ሞዳሊቲ ብሪጅ PR-1

ወደ **ቪዥን ያልሆኑ ሞዴሎች** የሚሄዱ ምስል የያዙ ጥያቄዎችን ይቆራረጣል እና
ጠቅላላውን ጥያቄ ወደ ቪዥን ማቅረብ የሚችል ሞዴል ወይም የምስሉን ክፍሎች በተወሰነ ቪዥን ሞዴል የተሰጠ የጽሑፍ መግለጫ በመተካት ከመላው ጥያቄ በፊት ይቀይራል። ይህ ለጽሑፍ-ብቻ አቅራቢዎች በቀላሉ የተያዙ ሞዳል ጭነቶችን እንዲያስተናግዱ ያደርጋል።

የሂደት ዝርዝር፦

1. የታለመው ሞዴል ቪዥንን ከደገፈ ይዝለፍ (ካልሆነ በተግባር በተጠየቀው የቪዥን ብሪጅ ዝርዝር `isVisionBridgeForcedModel` ውስጥ ካልታየ ብቻ)።
2. የምስል ክፍሎችን በ `extractImageParts(messages)` ይውጡ
   (`visionBridgeHelpers.ts`), ይህም ለ **የተዋቀሩ ሚዲያ መቆጣጠሪያ** `detectMediaParts()` በ `open-sse/utils/mediaParts.ts` ውስጥ ይሰጣል — ከ combo compatibility filter ጋር የተጋራ አንድ ምንጭ።
   ማውጣት በ ተፈቀደ ዝርዝር ውስጥ ያሉ የቅርጸ-ቁምፊዎች ላይ ብቻ ነው የሚፈፀም (የ extract↔replace ውል): OpenAI
   `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL
   `source.type:"url"`, እና Responses API `input_image`። የተያዙ እና የምልክት-ብቻ ቅርጸ-ቁምፊዎች combo-filter ናቸው እና በፍጹም አይወጡም። ምንም ካልተገኘ ይዝለፍ።
3. የ runtime ቅንብርን በ `resolveVisionBridgeRuntimeSettings()`
   (`src/shared/constants/modalityBridgeDefaults.ts`) ይወስኑ፡ አዲሱ `modalityBridge*`
   ቅንብሮች ይቆጣጠራሉ፤ አሮጌ `visionBridge*` ቅንብሮች እንደ **አንድ-ዙር መተካት** (rollback window) ይቀሩ። ብሪጁ ከተሰናከለ በፊት ማንኛውም የሚዲያ መቆጣጠሪያ ሲደርስ ይዝለፍ።
4. የሞድ መምረጫ (`modalityBridgeVisionMode`, የታቀደውን ሰንጠረዥ ይመልከቱ) የመላኪያ ማሻሻያ እና መግለጫ ይወስናል። መላኪያ ሲሆን `modifiedPayload` በ `model` ብቻ የተቀየረ ይመለሳል፣ ከዚህም በተጨማሪ meta `{ rerouted, fromModel, toModel, imagesKept }` ይጨመራል።
5. የመግለጫ መንገድ፡ ምስሎችን በ `maxImages` ይገደቡ፣ በተጠየቀው ተግባር የተሟላ ፕሮምፕት ይዘጋጁ፣ የመግለጫ ካሽን ይመልከቱ፣ ቪዥን ሞዴሉን **በተያያዥ** ይጥሩ (`Promise.allSettled`)፣ እና `[Image N]: <description>` የሚል የጽሑፍ ክፍል በቦታው ውስጥ ያስገቡ። የተሳካ ያልሆነ መግለጫ `null` ይሆናል እና የመጀመሪያው የምስል ክፍል **ይጠበቃል** (#4012) — ነገር ግን በ combo መግለጫ መንገድ ሁሉም መግለጫ ካልተሳኩ፣ ለቪዥን ያልሆነ ከፍ ተደርጓል በሚባል የላይ አቅራቢ የተረጋገጠ ከሆነ `(unavailable — no vision-capable provider connected)` የሚል ቅድመ መልስ ይላካል (#8430)።
6. `modifiedPayload` + meta (`imagesProcessed`, `descriptions`,
   `processingTimeMs`, `visionModel`) ይመለሳል።

ዝቅተኛ ዝርዝር የሆነ ምርጫ ለትክክለኛው የጽሑፍ-ትርጉም ተግባር የዚህ ፕሮምፕት የሚጠይቀውን የOCR ትክክለኛነት ይቀንሳል፣ ስለዚህ describe ጥያቄው ራሱ ሁልጊዜ ከመጀመሪያው የገቡት ጥያቄ ምን ዝርዝር ደረጃ ቢጠቀምም በላይኛው ዝርዝር ይጠይቃል። ይህ የተጠቀመውን የdescribe የውስጥ ጥያቄ አካል ብቻ ይነካል፤ እንደ መደበኛ የተቀመጠው በOmniRoute የተጠየቀውን `image_url.detail` በዋናው ጥያቄ ላይ አይቀይርም — ያ እንደ ተለየ ይተገበራል፣ እናም በ`defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`) ለተገኙ የOpenCode ደንበኞች ብቻ ይተገበራል። የAnthropic wire-format የdescribe self-loop ቅርንጫፍ የ`detail` መስክ አልባ ነው እና በማንኛውም ነባሪ አይተገናኝም።

#### የDescribe ውጤት ገደብ (`modalityBridgeVisionMaxChars`)

| ቁልፍ                            | ነባሪ | ክልል               |
| ------------------------------ | --- | ----------------- |
| `modalityBridgeVisionMaxChars` | `0` | `0` ወይም 100–50000 |

`0` (ነባሪ) ማለት **ገደብ የለም** — በ`callVisionModel()` የተመለሰው መግለጫ ያልተቀየረ በቀጥታ ይሰጣል፣ ያለውን ባህሪ ይጠብቃል። በ100–50000 ክልል ውስጥ ማንኛውም ዋጋ መግለጫውን በ`…` ቅጥ በፊት ይቆራረጣል እና እንደ `[Image N]: <description>` በመቀየር ይመለሳል (`VisionBridgeGuardrail.preCall()` በ`src/lib/guardrails/visionBridge.ts` ውስጥ)። ለዝርዝር የሆኑ OCR ተግባራት ይህን ያሳድጉ እና የታችኛውን ወደ ታች ያስቀኑ ለተወሰኑ ቶክን አጠቃቀም በብዙ የሚናገሩ የvision ሞዴሎች። የdashboard መስኩ በVision ታብ ውስጥ በAdvanced ፓነል ላይ ይገኛል (`modality-bridge-max-chars` በ`ModalityBridgeVisionTab.tsx`) እና ማንኛውንም ዋጋ በ1 እና 99 መካከል ወደ 100 ያደርሳል እና ግልጽ `0` አይነካም — `0` በራሱ ልዩ የZod ዋጋ ነው (`z.union([z.literal(0), z.number().int().min(100).max(50000)])`), ብቻ የ"unset" ነባሪ አይደለም።

#### የሩቅ ምስል መደበኛ ማድረግ (self-loop describe/base64 fetch)

በbridge ራሱ **ሩቅ** ምስል ሲያመጣ — የAnthropic describe self-call እና የclaude-wire-format base64 ለውጥ
(`ensureBase64ImagesForClaudeWire`), ሁለቱም በ`fetchRemoteImageAsDataUri()` በ`visionBridgeHelpers.ts` — የተገኘው የdata URI በ`normalizeDataUri()` ይደርሳል
(`open-sse/utils/imageNormalize.ts`) ከመግባቱ በፊት በvision-model ጥያቄ ውስጥ ሲገባ። በጣም የተስፋፋ ምስሎች ወደ **2048px ረዥም ጠረፍ** ይቀንሳሉ (ይህ ከOpenAI/Anthropic በserver-side የሚተገበረውን የመጠን ገደብ ይዛመዳል)፣ ይህም የመጫኛ ባይቶች/የዝግጅት ጊዜ ይቆራረጣል ያለ የvision ሞዴሉ የሚያየውን ማቀየም። ማቀናበሪያ ለማቀናበር `sharp` ይጠቀማል፣ በdynamic import የተጫነ፤ በመድረኩ ላይ የተፈጥሮ ባይነሪው ማቅረብ ካልቻለ በ`normalizeDataUri()` **በፍጹም አይጣልም** — ወደ መጀመሪያው ባይቶች በቀጥታ ይመለሳል፣ ስለዚህ describe/base64-ለውጥ መንገድ ሁልጊዜ ይሰራል። የምስል ያልሆኑ ባይቶች (የተመጣው የማይታወቅ ምስል ከሆነ) እንዲሁም ያልተቀየሩ ይቀራሉ። ይህ መደበኛ ማድረግ ለbridge ራሱ ሲያመጣ ምስሎች ብቻ ይተገበራል — በፍጹም ለደንበኛው የተላከው የraw passthrough መጫኛ አይተገበርበትም፣ ከopt-in-ብቻ የሚቀየር መስፈርት ጋር ተመሳሳይ (Hard Rule #20)።

`/dashboard/settings/modality-bridge` ነው። የURL ሊገባበት የሚችሉት `Vision`, `Audio`, እና `Video` ትር በ`tab` ዋጋ ሲቀየሩ የጥያቄ መለኪያዎችን ይጠብቃሉ። የVision ትር እንደ እንቅስቃሴ፣ ዘዴ፣ የሞዴል ምርጫ (ከእነዚህ ውስጥ አውቶማቲክ ነባሪ ጨምሮ)፣ ተግባራዊ ጥያቄ መስጫ፣ የላቀ የጊዜ ገደብ/ምስል/መግለጫ-ርዝመት/ካሽ ገደቦች፣ የተከፈቱ ቆጣሪዎች፣ እና የተጠበቀ የናሙና ጥያቄ ያሳያል። የAudio ትር እንዲሁም በቀጥታ ነው፡፡ እንቅስቃሴ፣ የSTT-ብቻ የሞዴል መምረጫ ከAuto ጋር፣ የጊዜ ገደብ/ከፍተኛ ክሊፕ ገደቦች፣ የድምፅ ቆጣሪዎች፣ እና የ`input_audio` የናሙና ሙከራ ያሳያል። የVideo ትር ደግሞ ተግባራዊ ነው፡፡ የFFmpeg/ffprobe የበስተመስክ ሁኔታን ይዘጋጃል — አራት ግልጽ የUI ሁኔታዎች አንዱ (`unknown` ፡፡ ፕሮብ በመካከለኛ ሂደት ላይ ሲሆን ወይም ማጠናቀቅ ካልቻለ ፣ `restricted` በተለመዱ ያልሆኑ የዳሽቦርድ አስተናጋጆች ላይ ፕሮብ በአካባቢ ተወው ሲደርስ፣ `unavailable` ከተፈተነ እና ከጠፋ በኋላ፣ ወይም `available` ከFFmpeg/ffprobe እትም ጋር) — እንቅስቃሴ/ሞዴል/ፍሬም/ቪዲዮ/ጊዜ ገደቦችን ይጠብቃል፣ የሞዴል መምረጫውን ወደ የVision ችሎታ ያላቸው ሞዴሎች ይገልጻል፣ እና የቪዲዮ ቆጣሪዎችን ያሳያል።

የቀድሞው Vision Bridge ካርድ በAI ቅንብሮች ስር ወደ አዲሱ ገፅ የሚወስደው የተስማማ አገናኝ ብቻ ነው፤ የቅርብ ጊዜ ቅጂ የቅንብር ቅፅ አይይዝም። የሚዲያ አቅራቢዎች Image-to-Text እና Speech-to-Text ስራዎችን ወደ ተመሳሳይ Modality Bridge ትሮች ይገናኛሉ ያለ የቀድሞው Speech-to-Text playground ሳይወገድ።

**የራስ-ሊዩፕ መግቢያ መዝለል፡** የdescribe ጥሪው በOmniRoute የራሱ `/v1` ሊዩፕ ሲያልፍ (ያልተለመደ የአቅራቢ ሞዴል)፣ ንዑስ-ጥያቄው
`x-omniroute-admission-bypass: internal` ይልከዋል እና በተወሰነው የራስ-ሊዩፕ ማረጋገጫ ይማረካል — በአካባቢ ዘዴ የአካባቢው `sk_omniroute` sentinel፣ ወይም በኦፕሬተር የተዘጋጀው `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` የአካባቢ ተፈጻሚ ቁልፍ (#1350) ስለዚህ `REQUIRE_API_KEY=true` የተቀመጡ አቅራቢዎች የdescribe ጥሪውን ማስኬድ ይችላሉ። መዝለሉ ለእነዚህ ትክክለኛ ማረጋገጫዎች ብቻ ይከበራል፣ ስለዚህ ውጭ ደንበኞች አይችሉም ማስታወቂያውን በመጠቀም መግቢያ ማስወገድ።

የቀድሞው ነባሪዎች በ`src/shared/constants/visionBridgeDefaults.ts` ውስጥ ይኖራሉ፤ አዲሱ ዘዴ/ተግባር-ተወዳዳሪ/ካሽ ነባሪዎችና የቅንብር መፍትሄው በ`src/shared/constants/modalityBridgeDefaults.ts` ውስጥ ይኖራሉ። የመከላከያው በ`deps` ኮንስትራክተር አማራጭ ይገለጻል ስለዚህ ሙከራዎች የተሟሉ የ`getSettings` እና `callVisionModel` አስፈጻሚዎችን ማስገባት ይችላሉ።

### የድምፅ ብሪጅ (`audioBridge.ts`) — Modality Bridge PR-3

የድምፅ የያዙ የቻት ጥያቄዎችን ወደ ድምፅ ግቤት ማስተናገድ የማይችሉ መዳረሻዎች ሳይደርሱ ይቆራረጣል። ቻት ጥያቄውን በፍጹም አይቀየርም፤ የድምፅ ክፍሎች በአሁኑ ያለው OpenAI-ተዛማጅ multipart መድረሻ ይተረጉማሉ እና የተመረጠው የቻት ሞዴል በጽሑፍ ትርጉሞች ይቀጥላል።

የሂደቱ ደረጃዎች፡

1. `supportsAudio` በ`getResolvedModelCapabilities()` ይታወቃል። ግልጽ የአቅራቢ-መዝገብ መረጃ ይቆጣጠራል፣ ከዚያ የቆሻሻ ሞዴል መረጃ፣ ከዚያም የተዛመዱ `modalities_input`። የተገለጸ የግቤት ዝርዝር ውስጥ `audio` ካልተገኘ `false` ነው፤ ምንም የችሎታ ማስረጃ ካልቀረ `null` ነው። `false` እና `null` ሁለቱም የተጠናከረውን ብሪጅ ያነሳሉ፣ ነገር ግን `true` ይዘው ይወጡበታል።
2. የተዋቀሩትን `modalityBridgeAudio*` ቅንብሮች ይፈትሹ እና ከእያንዳንዱ መልእክት የሚቀይሩ የድምፅ ክፍሎችን በየላይኛው ደረጃ በ`detectMediaParts()` አጠቃላይ መቆጣጠሪያ ይሰብስቡ። የተደጋጋሚ የመስመር ቅርጸቶች OpenAI `input_audio`, `audio_url`, እና `source.media_type: "audio/*"` ናቸው። የተያያዙ የድምፅ ክፍሎች ለመስመር ይታወቃሉ ነገር ግን በsplice መንገድ አይወገዱም። ስራው በ`modalityBridgeAudioMaxClips` ይገደባል፤ ከዚያ በኋላ የሚመጡ ክፍሎች አይታገዱም።
3. የተዋቀሩትን `provider/model` ያከብሩ፣ ወይም `selectAudioBridgeModel()` በ`AUDIO_TRANSCRIPTION_PROVIDERS` ውስጥ በተረጋጋ የካታሎግ ቅደም ተከተል ይመራ እና በሚገባ የሚሰራ የአቅራቢ ማረጋገጫ ያለውን የመጀመሪያ ሞዴል ይምረጡ።
4. `callAudioTranscription()` የbase64/data-URI ድምፅን ወደ multipart `file` ይቀይራል፣ ወይም የሩቅ `audio_url` በህዝብ-ብቻ የወጣ መከላከያ በDNS መያዣ እና 25 MB ገደብ ይወርዳል። ከዚያ ፋይሉን እና የተመረጠውን ሞዴል ወደ አካባቢ `/v1/audio/transcriptions` ራስ-ሊዩፕ በPOST ይልካል፣ በ`resolveSelfLoopBearer()` የተማረከ ማረጋገጫ ጋር። ያለው የትርጉም መንገድ መደበኛ የማረጋገጫ ፍለጋ፣ የቀዝቃዛ/የደረሰኝነት አስተዳደር፣ እና የአቅራቢ መላኪያ ይሰጣል።
5. የተሳካ ጥሪ ክፍሎቹን `[Audio N]: <transcript>` ይቀይራል። ጥሪዎች `Promise.allSettled` ጋር ይሄዳሉ፡፡ አንዱ ብቻ ካልተሳካ የመጀመሪያው የድምፅ ክፍል ይቀየራል (#4012 ውል)። ሁሉም ጥሪዎች ካልተሳኩ እና መዳረሻው `supportsAudio === false` ተረጋግጧል ከሆነ፣ ክፍሎቹ `[Audio N]: (unavailable — no STT provider connected)` ይሆናሉ (#8430 ውል)። ለያልታወቀ መዳረሻ (`null`) ሁሉም ውድቀት ከተከሰተ የቀድሞው ይቀየራል። የተረጋገጠ ጽሑፍ-ብቻ መዳረሻ የሚገባ የSTT ማረጋገጫ ካልተገኘ በተመሳሳይ ግልጽ የተቋረጠ መልስ ያገኛል የኔትወርክ ጥሪ ሳይወጣ።

የተሳኩ ትርጉሞች በመስክ ውስጥ የተላለፈው Modality Bridge LRU/TTL ካሽ ይጠቀማሉ። ቁልፉ የድምፅ ማግኛ፣ የተረጋገጠው `audio-transcription` የክዋኔ መለያ፣ እና የተመረጠው STT ሞዴል ይዋሃዳል፤ ውድቀቶች በፍጹም አይቀመጡም። የድምፅ ሙከራዎች የተጋሩትን `bridged`, `cacheHits`, `failures`, እና `lastUsedAt` ቆጣሪዎችን ያዘምናሉ። የተቀየሩ ምላሾች
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` ይይዛሉ፤ ያልተቀየሩ ጥያቄዎች የAudio Bridge ክፍል አይይዙም።

የበስተመስክ ቅንብሮች በDB የተደገፉ ናቸው እና በZod የተረጋገጡ ናቸው፡፡

### የቪዲዮ ብሪጅ (`videoBridge.ts`, `videoBridgePipeline.ts`)

የላይኛውን የቪዲዮ ክፍሎች በChat Completions `messages` እና በAPI `input` በመድረሻ በተወዳጅ የቪዲዮ የተወሰነ የተፈጥሮ ድጋፍ አልባ አካባቢ ከመጠራት በፊት ይቆራረጣል። የተደጋጋሚ ቅርጸቶች የሚደገፉት `input_video`, `video_url`, `video_source`, የHTTPS URLs, እና `data:video/*;base64,...` የውሂብ URIዎች ናቸው። በግልጽ ጽሑፍ ውስጥ የተጻፉ ፋይል ስሞች እንደ ቪዲዮ አይቆጠሩም።

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) የጥያቄ መሻገሪያ, የችሎታ/ፖሊሲ ምርመራ, በጥያቄ ላይ የሚደረግ ማጠቃለያ, እና የምላሽ ጭነትን በተጠየቀው ይዞ ይገኛል። በቪዲዮ ላይ የሚደረግ ስራ — መያዝ, የሙሉ ውጤት ካሽ, የፍሬም ቅደም ተከተል መግለጫ (የተጠራ የድምፅ ትርጓሜ ከሆነ ይዋሃዳል), እና በሙከራ ላይ የሚደረግ መለኪያ/ማቋረጫ/ማጽዳት — በ`processVideoPart` ውስጥ ተደብቆ አለ በ`videoBridgePipeline.ts` ውስጥ፣ በ`preCall` ዙር ውስጥ በቪዲዮ ክፍል አንዳንዱ ጊዜ ይጠራል። ይህ ሞጁል እንዲሁም የተገለፀውን የፖርት ድንበር `VideoMediaBrokerPort` (ባይቶችን መያዝ እና የተመረጡ ፍሬሞችን መውጣት), `VideoAudioTranscriptionPort` (የተጠራ የድምፅ ትርጓሜን ከተመረጡ ካፕሽኖች ጋር መዋሃድ), እና `VideoDrilldownPort` (የታዋቂው የቀድሞ የተጠበቀ ቅርጸት) ይገልጻል። የምርት STT እና የፍሬም መያዣ በ`createVideoSttAdapter` እና `createVideoDrilldownAdapter` በመካከል በመግለጫ ፖርት ዙሪያ ይቀመጣሉ፤ ከዚህ ውስጥ አንዱ የተጋራ የተሰወረ አንደበት የህይወት ዙርያን ይጠቀማል።

የውጪ `/v1` የጥያቄ መንገድ ችግኝ አይጠቀምም እና ንዑስ ሂደት አይጠራም። የሩቅ ቪዲዮዎች ከ50 MiB ውስጥ ይወርዳሉ፤ የበይነ መለኪያ base64 ቪዲዮዎች በቪዲዮ ላይ የተጠናከረ 36 MiB የተቀየረ ገደብ አላቸው ስለዚህ ሞዴሉ/መልእክቶቹ/የመስተንግዶ አቅጣጫው በየህዝቡ JSON የጥያቄ መግቢያ ገደብ ውስጥ ይቆያሉ። የበይነ መለኪያ ርዝመት እና የተቀየረ መጠን ግምቶች ከመመደብ በፊት ይምረመራሉ። በመጀመሪያው የሩቅ URL ላይ እና በሁሉም እንደገና መምሪያዎች ላይ HTTPS ያስፈልጋል፣ ይህም በአሁኑ የውጪ-ብቻ መውጫ ጠባቂ ከDNS መያዣ ጋር ይጠቀማል። ባይቶቹ በትክክል የተወሰነውን የውስጥ `POST /api/modality-bridge/video/extract` የባንክ ድንበር ይሻገራሉ። ይህ መንገድ ሁሉም `LOCAL_ONLY` እና `SPAWN_CAPABLE` ነው፣ በሂደት ላይ የተሟሟ የታመነ-መመለሻ ጥያቄ ብቻ ይቀበላል፣ እና በፍጹም URL, የፋይል መንገድ, አካል ወይም የአርግመንት ዝርዝር አይቀበልም። የAPI አካል-መጠን መስመር እና የአንቀሳቃሽ አንደኛው የአካል አንቀሳቃሽ አንቀሳቃሽ በተለያዩ 50 MiB የባንክ ግብዓት ገደብ ይጠብቃሉ። የተወሰነው ተራ አንድ መውጣት በአንድ ጊዜ ይሰራል፣ አራት በመጠባበቅ ላይ ያሉ ስራዎችን ይፈቅዳል፣ እና በመጠባበቅ ላይ ያለውን ግብዓት እስከ 100 MiB ይገደባል።

በባንኩ ውስጥ፣ `ffprobe` የግል የአካባቢ ፋይል ይነባል፤ የተወሰነው ቅርጸት የተፈቀደውን ዝርዝር የፕሌይሊስት እና የማናፊስት ቅርጸቶችን ያስወግዳል። ለተፈቀደው MOV-ቤተሰብ ኮንቴነሮች፣ የውጪ MOV ውሂብ ማጣቀሻዎች በነባሪነት ተሰናክለዋል፣ እና የተወሰነው ትክክለኛ ትእዛዝ አይሰጥባቸውም። ሁለቱም `ffprobe` እና `ffmpeg` የ`file`-ብቻ ፕሮቶኮል ዝርዝር, አንድ ክፍል አስተዳደር, የተወሰኑ አርግመንት ዝርዝሮች, ምንም shell የለም, እና ከ`PATH` የተወሰኑ አካል ይጠቀማሉ። የተያያዙ ምስል አልባ የመለያ ፍሪምዎች የሚጫወቱ አይደሉም። ሁሉም የሚጫወቱ ፍሪምዎች የተወሰኑትን ገደቦች ማሟሟ አለባቸው፣ እና በግልጽ ነባሪ ፍሪም በፊት ከተወሰነው ዝቅተኛ መስመር ይወሰናሉ። ቪዲዮዎች እስከ 600 ሰከንድ፣ 8,192 ፒክስል በአንዱ ስፋት፣ እና 33,554,432 የምንጭ ፒክስሎች ይገደባሉ። FFmpeg 1–16 የመካከለኛ የJPEG ፍሬሞችን ይወስዳል፣ ረጅም ጎኑን እስከ 1,024 ፒክስል ያነሳል አነስተኛውን ግብዓት አያስፋፋም፣ እና በፍጹም URL አይቀበልም። መውጣት `uniform` በነባሪነት ነው። አማራጭ `scene_aware` እና የሙከራ `segment_aware` ፖሊሲዎች በቀድሞው የተሟሟ የአካባቢ ስትሪም ላይ ተጨማሪ የተወሰነ የFFmpeg መውጣት ያደርጋሉ፣ የተወሰኑ የ`showinfo` የትዕይንት ጊዜዎችን ይምረጣሉ፣ እና በመተንፈሻ አሳያ, ጊዜ አልቋም, የተበላሸ ውጤት, ወይም ባዶ የተመረጡ ስብስቦች ላይ በተወሰነ መንገድ ወደ ተመሳሳይ መካከለኛ መውጣት ይመለሳሉ። የሴግመንት-አዋቂ ሁኔታ መካከለኛ መውጣቶችን በተሟሟ የትዕይንት ክፍሎች ላይ በመጠን ይመድባል፤ የሴግመንት-አዋቂ ማስረጃ እና የመመለሻ ባህሪ ከታች በተገለፀው በዝርዝር ተገልጿል። የጠናከረው 16-ፍሬም ገደብ በሁሉም ፖሊሲ ከመምረጥ በኋላ ይተገበራል። ሲን-አዋቂ ጥያቄ አንድ ፍሬም ብቻ ካለው በመጠን ሲሆን፣ የአንድ ተመረጠ የትዕይንት ፍሬም ሁለቱንም የጊዜ መጨረሻዎች ማስቀመጥ አይችልም። ተጠሪ በምርጫ የተወሰነ የትክክለኛ መስክ (`start`/`end` ሰከንዶች) ማቅረብ ይችላል፤ ድንበሮች ወደ የሚዲያው ቆይታ ይገባሉ፣ የተቀየሩ ወይም ያልተወሰኑ መስኮች ይተወዳዳሉ፣ እና ሁሉም የመውጣት ፖሊሲዎች በተንቀሳቃሽ ክፍል ውስጥ ብቻ ይሰራሉ። የተወሰነው መስክ በመውጣት ሜታዳታ እና በያልታመነ መግለጫ ቅድመ አስተያየት ውስጥ ይካተታል ስለዚህ የቀጣዩ ሞዴሎች ከሙሉ የጊዜ መስመር የተለየ የተመረጠ ክፍል መለየት ይችላሉ።

የሴማንቲክ ካፕሽን ትኩረት የተለየ ግልጽ ቅንብር ነው። ነባሪው `full` የትንታኔ ሁኔታ ያለውን የፍሬም ፕሮምፕት ይጠብቃል እና የጥያቄ ጽሑፍን ወደ ካፕሽን ሞዴል በፍጹም አያልፋም። በ`focused` ሁኔታ በብሪጅ በተመሳሳይ Chat ወይም Responses ኮንቴነር ውስጥ ከተጠቀሰው የተጨማሪ ያልተቃወመ `text`/`input_text` ብቻ ይያዛል፣ ወደ NFC ይመዝገባል፣ የመቆጣጠሪያ ቁምፊዎችን እና ነጻ ነጠላ ቦታዎችን ይቀንሳል፣ እና እስከ 500 ዩኒኮድ ኮድ ነጥቦች ይገደባል። ባዶ ውጤት ወደ ትክክለኛው `full` ፕሮምፕት ይመለሳል። የሚጠቀም ምክር እንደ JSON በተወሰነ ያልታመነ-የተጠቃሚ-አውታረ ክፍል ውስጥ ይታያል እና የሚታወቀውን ዝርዝር ብቻ ሊቅድም ይችላል፤ በሚዲያው ውስጥ የሚታዩ ወይም የሚሰሙ መመሪያዎችን ማከበር የተለየ ማስጠንቀቂያ ማሻሻያ አይችልም። የጽሑፍ ትኩረት በፍጹም `start`/`end` አያስተናግድም ወይም የጊዜ መውጣትን አይቀይርም።

አስገባቢዎች ተዛማጅ ጽሑፍ ካላቸው በቪዲዮ ክፍል ላይ አማራጭ `transcript.cues` አውሬ ማካተት ይችላሉ። እያንዳንዱ cue የተወሰነ `text`፣ የተወሰነ የ`start`/`end` ክፍተት በተመረመረው ጊዜ ውስጥ፣ እና በአንዱ ከተፈቀደው የ`source` (`client`, `embedded`, ወይም `audio-bridge`) መሆን አለበት፤ `confidence` ነባሪው ወደ `1` ነው እና በ`0` እና `1` መካከል መቆየት አለበት። ትክክለኛ ቅጽበት ያላቸው cues ይደበቃሉ። OmniRoute ከዚህ ሜታዳታ መነሳት አይጀምርም፤ የተረጋገጡ cues በተገለጹት ውጤቶች ውስጥ ከsource፣ confidence እና ክፍተት ጋር ተቀይረው ይቀመጣሉ፣ እና ከframe captions ጋር እንደ ያልታመኑ ምርመራዎች ይታያሉ። የተሳሳተ፣ ከክልሉ ውጭ ወይም የማይታወቅ provenance ያለው ጽሑፍ ይተወዋል እንጂ በcaption ወንድም ውስጥ አይቀላቀልም። የrequest-body transcript ቻናሎች ሁለቱም የቀረበውን provenance ወደ `client` ያካትታሉ፣ ራሳቸው የተገለጹ `embedded` ወይም `audio-bridge` መሆናቸውን ጨምሮ። የserver ባለቤት adapter ብቻ እነዚህን የታመኑ መለያዎች በኮድ-ብቻ `trustedSource` አርጉመንት ማስያዝ ይችላል፤ የrequest JSON መስክ ወደዚያ አርጉመንት ማድረስ አይችልም። የትርጓሜ ጽሑፍ የማይታመን ከሚዲያ የተገኘ ይዞታ ብቻ ይቆያል፣ ከprovenance ጋር ቢሆንም፣ ማንኛውም የፈቃድ መድረሻ ማድረግ አይችልም።

የሚበልጥ የተሟላ አስገባቢ ለተመሳሳይ ቪዲዮ `audioTranscript` ትርጓሜ ማቅረብ ይችላል፤ እንደ ተጠቃሚ የቀረበ ጽሑፍ ይቆጠራል፣ የserver ትርጓሜ መሆኑን አይደረግም። የfusion seam የራሱ ድንበርና የመቋቋም ምልክት ላይ የቪዥዋልና የድምፅ ምርመራዎችን በአንድ ጊዜ ያስኬዳል፣ በአንድ የጊዜ መስመር ላይ ያደርጋል፣ ትክክለኛ ቅጽበት ያላቸውን ይደበቃል፣ እና አንዱ ብቻ አሳካ በሆነ ጊዜ ከፍተኛ ውጤት ይሰጣል። የተሳሳተ `audioTranscript` ወደዚያ ከፍተኛ ውጤት ይወርዳል — የቪዥዋል መግለጫው ይቀመጣል እና የድምፅ branch የተንጻ የውድቀት ኮድ ይመዝገባል — ከቪዲዮው ሁሉ ማቋረጥ ይበልጣል። የbranch ተገኝነት፣ የከፍተኛ ምልክት፣ እና የተንጻ የውድቀት ኮዶች በተገለጹት ውጤቶች፣ በguardrail ሜታዳታ (`audioFusionRuns`/`audioFusionPartials`/`audioFusionFailureCodes`)፣ በresult-cache ሜታዳታ እና በbridge fusion ቆጣሪዎች ውስጥ ይጠበቃሉ። ነባሪው የቪዲዮ ብሪጅ መንገድ ንግግር-ወደ-ጽሑፍ አይጠራም ወይም ሁለተኛ የሚዲያ ቅጂ አይወስድም፤ ያ ትክክለኛ ትርጓሜ ካልተሰጠ ቪዲዮ ብቻ ይቆያል።

### PII Masker (`piiMasker.ts`)

በ**ሁለቱም** ደረጃዎች ላይ ይሰራል።

- **`preCall`** የpayload ኮፒ ይፈጥራል፣ `system`፣ `messages`፣ `input`፣ እና
  `prompt` (ቀላል የሆኑ የstring እቃዎችን ጨምሮ) ይመላለሳል፣ እና `processPII()` (ከ
  `@/shared/utils/inputSanitizer`) በstring `content`/`text` መስኮቶች ላይ ይተግበራል። `PII_REDACTION_ENABLED=true` ሲሆን፣ የተገኘው PII በወጪ payload ውስጥ ይቀይራል። ይህ ከ`INPUT_SANITIZER_MODE` ጋር በተለየ ነው (ይህ ብቻ የprompt-injection ፖሊሲን ይቆጣጠራል)። የቀይር ከተዘጋ ጊዜ፣ ጥሪው የተገኙትን ቁጥር ይመዝግባል ያለ ይዘቱን ማቀየር በስተቀር።
- **`postCall`** ምላሹን በጥልቀት ይኮፒያል፣ `sanitizePIIResponse()` እና የResponses-API-shape masker (`maskResponsesOutput` — `output_text` እና `output[].content[].text` ይሸፍናል) ይሰራል። ማንኛውም የቀይር ከተፈጸመ፣ የተሻሻለው ምላሽ ኦሪጅናሉን ይቀይራል።

Guardrail በፍጹም አይከልክልም፤ ማብራሪያ ብቻ ይጨምራል (`meta.detections`, `meta.redacted`) ወይም ይቀይራል።

### Prompt Injection (`promptInjection.ts`)

በተጠቃሚ የቀረበ ይዘት ውስጥ የጠላት መዋቅሮችን ያግናል እና የተዘጋጀውን ፖሊሲ ይተግበራል። ባህሪው በenvironment variable እና በconstructor አማራጮች ይመራል፦

| ቅንብር       | የአካባቢ ተለዋዋጭ (Env var)                                                                                | ነባሪ    | ተፅእኖ                                                                                                                                          |
| ---------- | ---------------------------------------------------------------------------------------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| ተችሏል       | `INPUT_SANITIZER_ENABLED`                                                                            | `true` | ሲሆን `false` ከሆነ፣ መከላከያው በቀጥታ ይቋረጣል።                                                                                                           |
| ዘዴ         | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                      | `warn` | የመግቢያ ፖሊሲ፡ `block`, `warn`, ወይም `log`። (`redact` ለኋላ-ተስማሚነት ይቀበላል ግን የመግቢያ ጽሑፍን አይወግድም፤ የጥያቄ PII እንደገና መፃፊያ በ`PII_REDACTION_ENABLED` ይቆጣጠራል።) |
| የመከለከያ መጠን | `blockThreshold` አማራጭ / `INPUT_SANITIZER_BLOCK_THRESHOLD` (የተባወሰው `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high` | ለመከለከል የሚያስፈልገው ዝቅተኛ ከባድነት። መካከለኛ በነባሪ በመጠንቀቅ ብቻ ይጠቀማል።                                                                                       |

**የዘዴ ቅደም ተከተል** (`getMode`): የጠራቢው `options.mode` →
`INJECTION_GUARD_MODE` **የዳታቤዝ ባለባት ባለብቃት ባለብቃት** (Dashboard → ቅንብሮች →
Feature Flags) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env →
`warn`። ስለዚህ የዳሽቦርድ ባለብቃት ከአካባቢ ተለዋዋጮች በላይ ይሆናል፣ ስለዚህ Feature
Flags UI በቀጥታ የሚሰራውን መከላከያ ይቆጣጠራል (እንደገና ማስጀመር አያስፈልግም)። የDB ንባብ ደህና የተጠበቀ ነው፡
በሚስተው ጊዜ መከላከያው ወደ አካባቢ ተለዋዋጭ ባለመሆኑ ይመለሳል፣ እና ባለብቃት ሲል ባለብቃት የአካባቢ ተለዋዋጭ አንደኛ ይሆናል።

የማወቅ ምንጮች፦

1. `sanitizeRequest()` ከ `@/shared/utils/inputSanitizer` (በሌሎች ቦታዎች የሚጠቀምበት የተጋራ መረጃ ሰብሳቢ)።
2. የተገናኘው `DEFAULT_GUARD_PATTERNS` (በአሁኑ ጊዜ `system_override_inline` እና
   `markdown_system_block`, ሁለቱም `high` ከባድነት)።
3. በመምሪያ አማራጮች የሚሰጡ `customPatterns` (የጽሑፍ ሐረጎች፣ regex፣
   ወይም `{ name, pattern, severity }` መዝገቦች)።

ሲሆን `mode === "block"` **እና** ቢያንስ አንድ ማወቅ የተወሰነውን የከባድነት መጠን ከሚያሟሟ ጊዜ፣ `preCall` ይመልሳል `{ block: true, message: "Request rejected: suspicious content detected" }`። በ`warn`/`log` ዘዴዎች መከላከያው ይመዝግባል ግን ጥሪውን ይፈቅዳል። የተጋራው አጋዥ `evaluatePromptInjection()` እንዲሁም ለተጠራቢዎች ያስመዝግባል፣ በማህደሩ ውስጥ ሳይያል።

**የመቃኘት ድንበር (v3.8.20):** መረጃ ሰብሳቢው የተያያዙትን የመጀመሪያ **16 KB** የተያያዙ የጥያቄ ጽሑፎችን ብቻ ይመርመራል — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 bytes) በ`src/shared/utils/inputSanitizer.ts` ውስጥ። `detectInjection()` እና
`evaluatePromptInjection()` ሁለቱም `slice(0, MAX_INJECTION_SCAN_BYTES)` ከመስመሩ በፊት ይሰራሉ። የመግቢያ መመሪያዎች በግብዣ አካባቢ ላይ ስለሚገኙ፣ ይህ በብዙ መቶ-KB የሚሆኑ ጭነቶች ላይ የregex አሰራር/GC ይገደባል እና የማወቅ ኃይል አይደክምም (cf.
#3932, #4041)።

### የመለያ መደበቂያ (Credential Masker) (`credentialMasker.ts`)

በ**ሁለቱም** ደረጃዎች ይሰራል፣ በነባሪ ሰንሰለቱ መጨረሻ (priority `95`)።
የታወቀ የAPI-ቁልፍ / የሚስጥር-ምልክት አቀማመጦችን ከወጪ ጭነት (የመልእክት ይዘት፣ የመሳሪያ ጥሪ አርግሞች፣ የመሳሪያ ውጤቶች) **እና** ከአቅራቢ ምላሽ ይወግዳል፣ ስለዚህ መለያ በጥያቄ ውስጥ ቢገባ (ወይም በመሳሪያ ውጤት ቢመለስ) ወደ ከፍተኛ አቅራቢ ወይም ወደ ደንበኛ አይፈልቅም።

- **በፈቃድ ብቻ**፣ ከPII የመደበቂያ ጋር ተመሳሳይ ልምድ (የጠንካራ ደንብ #20-ቅርብ)፡
  ካልተነቃቃ `settings.credentialRedactionEnabled === true` **ወይም**
  `CREDENTIAL_REDACTION_ENABLED=true` ካልተደረገ፣ መከላከያው ምንም አይሰራም —
  በፍጹም አይከልከልም እና አይደግፍም።
- `redactCredentials()` ሙሉ ጭነት/ምላሽ ዛፉን ይመራራል (`walkValue()`,
  የprototype-pollution ደህንነት ያለው፣ በ`WeakSet` የዙር መከላከያ) እና የተያዙትን ቦታዎች በ`[REDACTED:<type>]` ቦታ ይቀይራል፣ ተለዋዋጩ የተለዋዋጩ ቅርንጫፎችን ብቻ ይቅዳል።
- `CREDENTIAL_PATTERNS` የLLM አቅራቢ ቁልፎችን ይያዛል (OpenAI, OpenAI-proj,
  Anthropic, Google, Hugging Face, Replicate), VCS/SaaS ምልክቶች (GitHub, Slack,
  Linear, Notion, npm, Postman, Discord), የክፍያ ቁልፎች (Stripe, Square), የደመና ቁልፎች (AWS access key, Twilio, SendGrid, Mailgun), የግል ቁልፎች / JWTs,
  መለያ የያዙ የግንኙነት ሐረጎች (`mongodb://user:pass@...`, ወዘተ), እና
  አጠቃላይ `Authorization`/`x-api-key`/`api-key`/`apikey` የራስ-አካል አቀማመጥ። የheader ቅርጸት ቁልፎች (`authorization`, `x-api-key`, `api-key`,
  `apikey`) በመዋቅር ይወገዳሉ (ዋጋ ብቻ፣ የscheme ቅድመ-ቃል እንደ
  `Bearer `/`Basic ` የተጠበቀ) እንጂ በአጠቃላይ የጽሑፍ regex አይወገድም።
- መከላከያው በፍጹም አይከልከልም፤ የሚያደርገው ብቻ መደገፍ (`modifiedPayload` /
  `modifiedResponse`) እና ማስታወቂያ ማድረግ (`meta.credentialsRedacted`, `meta.count`) ነው።

የተመለሰ መከላከያ፡ `tests/unit/credential-masker-guardrail.test.ts`።

## መሠረታዊ ውል (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(
    payload: unknown,
    context: GuardrailContext,
  ): Promise<GuardrailResult | void>;

  async postCall(
    response: unknown,
    context: GuardrailContext,
  ): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true ሰንሰለቱን ወዲያውኑ ያቋርጣል
  message?: string; // ሲታገድ ይታያል
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // ጥያቄውን እንደገና ለመጻፍ በ-preCall ይመለሳል
  modifiedResponse?: TValue; // ምላሹን እንደገና ለመጻፍ በ-postCall ይመለሳል
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

አንድ guardrail `void`፣ `{}` ወይም `{ block: false }` በመመለስ "ለውጥ የለም" የሚል ምልክት ይሰጣል። `modifiedPayload`/`modifiedResponse` መመለስ በሰንሰለቱ ውስጥ ወደ ታችኛዎቹ guardrails የሚተላለፈውን እሴት ይተካል።
`signal?: AbortSignal` የጠሪውን የሕይወት ዑደት ወደ guardrails ያስተላልፋል። የጥያቄ ማቋረጥ ሆን ተብሎ የተደረገው ክፍት-በመተው የሚሳካ ልዩ ሁኔታ ነው፦ የሚዲያ ማገናኛዎች ሥራቸውን ያቆማሉ እና ያጸዳሉ፤ ጥሬ ሚዲያን እንደማይደግፈው ወደሚታወቅ ዒላማ ግን አይመልሱም።

## መዝገብ (`registry.ts`)

ብቸኛው `guardrailRegistry` የሚከተሉትን ያቀርባል፦

- `register(guardrail)` — guardrail ያክላል (ወይም በመደበኛ የስም ቅርጹ መሠረት ይተካል)፣ ከዚያም በ`priority` ከዝቅተኛ ወደ ከፍተኛ እንደገና ይደረድራል።
- `clear()` / `list()` — የአስተዳደር ረዳት መሣሪያዎች።
- `runPreCallHooks(payload, context)` — ንቁ guardrailsን በየተራ ያካሂዳል፣ payloadን በ`modifiedPayload` በኩል ያስተላልፋል፣ እና በመጀመሪያው `block: true` ላይ ያቆማል።
- `runPostCallHooks(response, context)` — በምላሹ በኩል ተመሳሳይ ፍሰትን ይከተላል።
- `resetGuardrailsForTests({ registerDefaults })` — ለንጹሕ የሙከራ ማግለል ሁኔታውን ያጸዳል፣ እና እንደ አማራጭ ነባሪዎቹን እንደገና ይመዘግባል።

ሁለቱም አስኪያጆች `{ blocked, payload|response, results, guardrail?, message? }` ይመልሳሉ፤ በዚህ ውስጥ `results` ለእያንዳንዱ guardrail `blocked`፣ `skipped`፣ `modified`፣ `error` እና `meta` መስኮችን የሚያካትቱ የ`GuardrailExecutionResult` መዝገቦች ድርድር ሲሆን፣ ለክትትል ጠቃሚ ነው።

### Guardrailsን በእያንዳንዱ ጥያቄ ማሰናከል

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` ለአሁኑ ጥያቄ መዝለል ያለባቸውን የguardrail ስሞች ድግግሞሽ የተወገደለት ዝርዝር ያሰባስባል። ምንጮቹ (ሁሉም አማራጭ፣ ሁሉም የሚዋሃዱ)፦

- `apiKeyInfo.disabledGuardrails`
- የጥያቄ አካል `disabledGuardrails` (ከፍተኛ ደረጃ)
- የጥያቄ አካል `metadata.disabledGuardrails`
- ራስጌ `x-omniroute-disabled-guardrails` (ወይም የቀድሞው
  `x-disabled-guardrails`)

## የአፈጻጸም ቅደም ተከተል

   ደረጃቸው ከዝቅተኛ ወደ ከፍተኛ ቅደም ተከተል ያስኬዳል፦
   - የተሰናከሉ guardrails እንደ `skipped` ይመዘገባሉ።
   - የእያንዳንዱ guardrail `preCall` በ`modifiedPayload` አማካኝነት payloadን እንደገና ሊጽፍ ይችላል።
   - የመጀመሪያው `block: true` ሰንሰለቱን ወዲያውኑ ያቋርጣል፣ እና handlerው
     የguardrail ውድቅ ማድረጊያ ምላሽ ይመልሳል።
3. (ሊሻሻል የሚችለው) payload ወደ combo routing እና upstream
   dispatch ይገባል።
4. ምላሹ ከተዋቀረ በኋላ፣ `guardrailRegistry.runPostCallHooks(...)`
   በምላሹ ላይ ያንኑ ሰንሰለት ያስኬዳል። እዚህ ያለ `block: true` የupstream
   ምላሹን ይጥላል።

ስህተት የሚያስነሱ guardrails በ`error: <message>` ይመዘገባሉ፣ እንዲሁም በ

## ብጁ መከላከያዎች

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

ደረጃዎች፦

1. `BaseGuardrail`ን የሚወርስ `src/lib/guardrails/myGuardrail.ts` ይፍጠሩ።
2. `preCall` እና/ወይም `postCall`ን ይተግብሩ።
3. በመጫን ጊዜ ይመዝግቡ (`registerDefaultGuardrails` ውስጥ ያክሉ) ወይም
   በአሂድ ጊዜ `guardrailRegistry.register(...)`ን ይጥሩ — መዝገቡ ተመሳሳይ መደበኛ የተደረገ ስም ያለውን
   ቀደምት መከላከያ ይተካል።
4. ሙከራዎችን በ`tests/unit/` ስር ያክሉ (ያሉ ምሳሌዎች፦
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`)።
