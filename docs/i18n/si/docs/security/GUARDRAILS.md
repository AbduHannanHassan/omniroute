Guardrails මඟින් OmniRoute සහ upstream සැපයුම්කරුවන් අතර සීමාවේදී ආරක්ෂාව, ප්රතිපත්ති සහ අන්තර්ගත පරිවර්තන බලාත්මක කරයි. සෑම guardrail එකකටම ඉල්ලීම් payload (`preCall`) සහ upstream ප්රතිචාර (`postCall`) පරීක්ෂා කිරීමටත් (සහ විකල්ප ලෙස ප්රතික්ෂේප කිරීමට, පරිවර්තනය කිරීමට හෝ සටහන් එක් කිරීමටත්) හැකිය.

පද්ධතිය **fail-open** ආකාරයෙන් ක්රියා කරයි: ක්රියාත්මක වන අතරතුර guardrail එකක් දෝෂයක් නිකුත් කළහොත්, registry එක එම දෝෂය වාර්තා කර ඉල්ලීම අසාර්ථක කිරීම වෙනුවට ඊළඟ guardrail එක සමඟ ඉදිරියට යයි. අවහිර කිරීම යනු පැහැදිලි තීරණයකි (`block: true`), කිසිවිටෙකත් අහම්බයක් නොවේ.

### දෘෂ්ටිය බ්‍රිජ් (`visionBridge.ts`) — මොඩාලිටි බ්‍රිජ් PR-1

**නොදෘෂ්ටිය ආකෘති** වෙත ඉලක්ක කර ඇති රූප සහිත ඉල්ලීම් අත්අඩංගුවට ගන්නා අතර
සම්පූර්ණ ඉල්ලීමක් දෘෂ්ටියට හැකියාව ඇති ආකෘතියකට නැවත යොමු කරයි හෝ රූප
අංශ පෙර පියවර ඇමතුමට පෙර විකල්ප කළ දෘෂ්ටිය ආකෘතියක් මගින් නිෂ්පාදිත පෙළ විස්තර සමඟ
අපිටම වෙනස් කරයි. මෙය පෙළ පමණක් සපයන්නන්ට බහුමාන පණිවිඩ සම්පූර්ණයෙන්ම
සම්බන්ධ කර ගැනීමට ඉඩ සලසයි.

ප්‍රවාහය:

1. ඉලක්ක ආකෘතිය දෘෂ්ටියට සහය දක්වන විට අත්හරිනු (ඉදිරියට යොමු කරන ලද
   ලැයිස්තුවේ පෙනී නොසිටිය හැකි නම් `isVisionBridgeForcedModel`).
2. රූප අංශ `extractImageParts(messages)` මගින් ලබා ගන්න
   (`visionBridgeHelpers.ts`), එය **එකීකෘත මාධ්‍ය
   සොයාගන්නා** `detectMediaParts()` වෙත පවරයි `open-sse/utils/mediaParts.ts` —
   සම්පූර්ණ සත්‍යය එකට බෙදාගන්නා සම්පූර්ණ සත්‍යය.
   ලබා ගැනීම `replaceImageParts` ආකාරයට නැවත සම්බන්ධ කළ හැකි
   ආකෘති වල ඉහළ මට්ටමේ අංශ සඳහා අවසර දී ඇත (ලබා ගැනීම↔නැවත සම්බන්ධ කිරීම
   ගිවිසුම): OpenAI `image_url`, Anthropic base64 `source.type:"base64"`,
   Anthropic URL `source.type:"url"`, සහ Responses API `input_image`.
   අන්තර්ගත පහසුකම් සහ සංකේත පමණක් ආකෘති සම්බන්ධිත ද්‍රව්‍ය වේ
   සහ කිසිවිටෙකත් ලබා ගන්නා ලදි. කිසිවක් නොමැති නම් අත්හරිනු.
3. ක්‍රියාකාරී සැකසුම් විසඳන්න `resolveVisionBridgeRuntimeSettings()`
   (`src/shared/constants/modalityBridgeDefaults.ts`): නව `modalityBridge*`
   සැකසුම් යතුරු ජයග්‍රහණය කරයි; පරණ `visionBridge*` යතුරු **එක-සංචාරක
   ආපසු යාමක්** (පසුබැසීමේ කාලය). බ්‍රිජ් අක්‍රිය වූ විට කිසිදු මාධ්‍ය
   ගමනකට පෙර අත්හරිනු.

   නැවත යොමු කිරීම හෝ විස්තර කිරීම තීරණය කරයි. නැවත යොමු කිරීම `modifiedPayload`
   පමණක් `model` වෙනස් කරමින්, එයට අමතරව මැටා `{ rerouted, fromModel, toModel, imagesKept }`

#### Remote image normalization (self-loop describe/base64 fetch)

bridge එක **remote** image එකක් තමන්ම ලබා ගන්නා විට — Anthropic describe self-call සහ claude-wire-format base64 conversion

(`open-sse/utils/imageNormalize.ts`) මඟින් පසුබැසීමක් කරයි, vision-model request එකේ ඇතුළත් කිරීමට පෙර. Oversized images **2048px long edge** එකට අඩු කරයි (OpenAI/Anthropic දැනටමත් server-side එකේ යෙදෙන resize cap එකට සමාන), එය upload bytes/latency අඩු කරයි, vision model එකට දැක්වෙන දේ වෙනස් නොකරයි. Resizing එක `sharp` භාවිතා කරයි, dynamic import මඟින් ලැබෙනවා: එහි ස්වාභාවික binary එක load වන්නේ නැති platform එකකදී, `normalizeDataUri()` **කවදාවත් යටත් නොවේ** — එය මුල් bytes වලින් පසුබැසීමක් කරයි, එබැවින් describe/base64-conversion මාර්ගය සෑම විටම ක්‍රියාත්මක වේ. Non-image bytes (decodable image එකක් නොමැති fetch එකක්) ද untouched ලෙස පසුබැසෙයි. මෙම normalization එක bridge එක තමන්ගේ self-call එක සඳහා ලබා ගන්නා images වලට සීමා වේ — caller එකේ raw passthrough payload එකට කිසිවිටෙකත් යෙදෙන්නේ නැහැ, opt-in-only mutation principle එකට අනුකූලව (Hard Rule #20).

### Video Bridge (`videoBridge.ts`, `videoBridgePipeline.ts`)

Chat Completions `messages` සහ Responses API `input` හි ඉහළ මට්ටමේ වීඩියෝ කොටස් අත්අඩංගුවට ගනී, ඉලක්කයක් හඳුනා ගැනීමේදී දේශීය වීඩියෝ සහය නොමැතිව ඇමතුම් සිදු වේ. සහය දක්වන ආකාරයන් වන්නේ `input_video`, `video_url`, `video_source`, HTTPS URLs, සහ `data:video/*;base64,...` දත්ත URI වේ. පෙරළි නාමයන් පෙළේ වීඩියෝ ලෙස සැලකෙන්නේ නැහැ.

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) ඉල්ලීම් ගමන, හැකියාව/පොලීසිය පරීක්ෂාව, ඉල්ලීම් ප්‍රමාණය, සහ ප්‍රතිචාර පූර්ණතාවය හිමිකරයි. වීඩියෝ සම්බන්ධ කාර්ය — ලබා ගැනීම, සම්පූර්ණ ප්‍රතිඵල කෑෂ්, කාඩ්පතක් විස්තර කිරීම (ඇමතුම්කරු විසින් ප්‍රකාශිත ශබ්ද පරිවර්තනය එකතු කරන), සහ උත්සාහය අනුව මිනුම්/අත්හිටුවීම්/සමන්විත කිරීම — `processVideoPart` හි පසුපස සඟවා ඇත, එය `preCall` හි වටයේදී එක් වරක් වීඩියෝ කොටසකට ඇමතුම් කරයි. එම මොඩියුලය `VideoMediaBrokerPort` (බයිට් ලබා ගැනීම සහ සාම්පල ගන්නා කාඩ්පත් ඉවත් කිරීම), `VideoAudioTranscriptionPort` (ඇමතුම්කරු විසින් ප්‍රකාශිත ශබ්ද පරිවර්තනය සාම්පල ගන්නා ශීර්ෂ සමඟ එකතු කිරීම), සහ `VideoDrilldownPort` (පැරණි කාඩ්පත ආකාරය) යන පැහැදිලි වරාය සීමා නිර්මාණය කරයි. නිෂ්පාදන STT සහ කාඩ්පත රැඳවීම විස්තර කරන වරාය වටා `createVideoSttAdapter` සහ `createVideoDrilldownAdapter` මඟින් සම්පාදනය කරයි; පසුගිය එකතුව බෙදාගන්නා අඳුරු-සම්බන්ධ ජීවන චක්‍රය භාවිතා කරයි.

සමාන්‍ය ශීර්ෂ අවධානයක් වෙනම, පැහැදිලි සැකසීමක් වේ. පෙරනිමි `full` විශ්ලේෂණ ආකාරය පවතින කාඩ්පත ප්‍රෝම්ප්ට් රැක ගනී සහ කිසිදාම ඉල්ලීම් පෙළ ශීර්ෂ ආකාරයට යොමු කරන්නේ නැහැ. `focused` ආකාරයේදී, බ්‍රිජ් එකම චැට් හෝ ප්‍රතිචාර කන්ටේනරයෙන් පසුගිය නොහිස් පරිශීලක-ලියන `text`/`input_text` පමණක් කියවයි, එය NFC වෙත සාමාන්‍ය කරයි, පාලන අක්ෂර සහ හිස් ස්ථාන අඩු කරයි, සහ එය 500 Unicode කේත ලක්ෂ්‍යයන්ට සීමා කරයි. හිස් ප්‍රතිඵලය නිවැරදි `full` ප්‍රෝම්ප්ටයට ආපසු යයි. භාවිතා කළ හැකි සංකේතය JSON ලෙස විශේෂිත විශ්වාස නොකරන-පරිශීලක-සන්දර්භ කුටියක සිරස් කරයි සහ observable විස්තර ප්‍රමුඛ කරයි; එය මාධ්‍යයේ දැක්මට හෝ ශබ්දයට පෙනෙන උපදෙස් අනුගමනය කිරීමට වෙනම අනතුරු ඇඟවීමක් අභිබවා නොහැක. පෙළ අවධානය කිසිදාම `start`/`end` හෝ කාල සම්පලය වෙනස් කරන්නේ නැහැ.

`segment_aware` දැනටමත් වලංගු දේශීය වීඩියෝ ප්‍රවාහය මත සීමාගත පෙර-විශ්ලේෂණ ගමනක් භාවිතා කරයි. ස්ථිර පෙරහුරු කඩදාසි පළමුව 320 පිකසල් පළලට අඩු කරයි, දර්ශන වෙනස්කම් සහ අසාර්ථක කාල සීමා හඳුනා ගනී, පසුව තුවාල, සාමාන්‍ය ලුමා, සහ ස්ථායි/කාලීන තොරතුරු සඳහා තත්පරයකට 1 කාඩ්පතක් සාම්පල කරයි. මෙම ගමන 600 ව්‍යුහමය සාම්පල, එක් FFmpeg/පෙරහුරු ත්‍රෙඩ්, එකම `file`-පමණක් ප්‍රොටෝකෝල් සහ කන්ටේනර් අනුමත ලැයිස්තු, 1 MiB ප්‍රකාර-ආදාන සීමාව, සහ බ්‍රෝකර්ගේ බෙදාගත් අත්හිටුවීම්/අවසාන කාලය තුළ උපරිම 30 තත්පරයක් යටතේ සීමා කරයි. එය කිසිදාම ඉල්ලීමෙන් විධානයක්, පෙරහුරු, පථයක්, හෝ URL එකක් භාර නොගනී.

සංරචන අගයන් යනු නියමිත නියෝජන සාක්ෂි වේ, සමාජීය වීඩියෝ අවබෝධය නොවේ. එය විෂය, ක්‍රියාවන්, ශීර්ෂ, කතා, හෝ පරිශීලක අරමුණු අනුමාන කරන්නේ නැහැ. දර්ශන සහ නවතා ඇති සීමා කොටස් නිර්මාණය කරයි; නවතා ඇති ආවරණය, මැදුරු, ප්‍රකාරණය, අවකාශීය විශේෂාංග, සහ කාලීන වෙනස්කම් පවතින 1–16 ෆ්‍රේම් බජට් එක කොහොමද යන්න පමණක් බලපායි. සම්පූර්ණයෙන්ම නවතා ඇති කොටසක් එක ෆ්‍රේමයකින් සීමා කරයි, එනම් නවතා නොකළ කොටස් ඉතිරි බජට් එක සඳහා තරඟය කරයි. සීමා ෆ්‍රේම් වලට වඩා වැඩි නම්, සමාන්‍ය කාලසටහන ආවරණය තබා ගන්නා අතර, වේගවත් ආරම්භක කපා දැමීම් දිගු පසුබැසීමක් සඟවා ගන්නා බවක් නැහැ. නවතා ඇති සීමාවේ 1-තත්පර විශ්ලේෂණ ප්‍රතිපත්ති තුළ දර්ශන සීමා එකට එකතු කරයි.

ඇමතුම්කරුවන්ට සම්බන්ධිත වීඩියෝ කොටසකට විකල්ප `transcript.cues` අරය එක් කිරීමට හැකියාව ඇත, එය සම්බන්ධිත පෙළක් දැනටමත් තිබේ. එක් කුයියක් `text`, පරීක්ෂා කරන කාලය තුළ සීමිත `start`/`end` කාලසීමාව සහ සුදුසුකම් ලැයිස්තුවේ `source` (`client`, `embedded`, හෝ `audio-bridge`) එකක් ගෙන යා යුතුය; `confidence` පෙරනිමිය `1` වේ සහ `0` සහ `1` අතර පවතී. නිවැරදි පිටපත් කුයියන් එකට එකතු කරයි. OmniRoute මෙම මැඩටා දත්ත වලින් පරිවර්තනය ආරම්භ නොකරයි: සත්‍යාපිත කුයියන් විස්තර කළ ප්‍රතිඵලයට සොයාගන්නා ලද, විශ්වාසය සහ කාලසීමාව සමඟ පිටපත් කරයි, සහ පින්තූර ශීර්ෂ ලේඛන සමඟ අවිශ්වාසිත නිරීක්ෂණ ලෙස ප්‍රදර්ශනය කරයි. අසත්‍ය, පරාසයෙන් පිටත, හෝ ආශ්‍රිත නොවන පෙළ ප්‍රතික්ෂේප කරයි, එය ශීර්ෂ ලේඛන ප්‍රවාහයට මිශ්‍ර නොවේ. ඉල්ලීම-ශරීර පරිවර්තන චැනල් දෙකම ලබා දී ඇති ආශ්‍රිතතාවය `client` ලෙස සාමාන්‍ය කරයි, ස්වයං-පිළිගත් `embedded` හෝ `audio-bridge` ලේබල් ඇතුළුව. විශ්වාසිත ලේබල් ලබා දිය හැකි එකම සේවාදායකයාගේ අඩුකිරීමක් `trustedSource` යන කේත-පමණක් ආර්ථිකය හරහා පමණක් වෙන් කරයි; ඉල්ලීම JSON ක්ෂේත්‍රයක් එම ආර්ථිකයට ළඟා විය නොහැක. පරිවර්තන පෙළ විශ්වාසිත මාධ්‍ය-අවශ්‍ය අන්තර්ගතයක් වන අතර, එහි ආශ්‍රිතතාවය කෙසේ හෝ බලය තීරණය කළ නොහැක.

ඉහළ ඇමතුම්කරුවෙකුට එකම වීඩියෝ සඳහා `audioTranscript` පටයක් ලබා දිය හැක; එය සේවාදායක පරිවර්තනයේ සාක්ෂියක් නොවෙයි, පාරිභෝගිකයා විසින් ලබා දී ඇති පෙළක් ලෙස සැලකේ. ඒකාබද්ධ seam එක දිගු කාලයක් යටතේ දෘශ්‍ය සහ ශබ්ද නිරීක්ෂණ ක්‍රියාත්මක කරයි, ඒවා එක් කාලසටහනක යටතේ ඇණවුම් කරයි, නිවැරදි පිටපත් එකට එකතු කරයි, සහ එක් පැත්තක් පමණක් සාර්ථක වූ විට අර්ධ ප්‍රතිඵලයක් වාර්තා කරයි. අසත්‍ය `audioTranscript` එම අර්ධ ප්‍රතිඵලයට පහත වැටේ — දෘශ්‍ය විස්තරය රැඳී ඇත සහ ශබ්ද ශාඛාව සම්පූර්ණ වූ අසාර්ථක කේතයක් වාර්තා කරයි — සම්පූර්ණ වීඩියෝව අසාර්ථක නොකරයි. ප්‍රතිශාඛාවන්ට අනුව, අර්ධ ලාංඡනය සහ සම්පූර්ණ වූ අසාර්ථක කේතයන් විස්තර කළ ප්‍රතිඵලයේ, ආරක්ෂිත මැඩටා දත්තයේ (`audioFusionRuns`/`audioFusionPartials`/`audioFusionFailureCodes`), ප්‍රතිඵල-කැෂේ මැඩටා දත්තයේ, සහ බ්‍රිජ් ඒකාබද්ධ ගණකයන්හි රැඳී ඇත. පෙරනිමිය වීඩියෝ බ්‍රිජ් මාර්ගය කතා-ටෙක්ස් පරිවර්තනයක් ආරම්භ නොකරයි හෝ දෙවන මාධ්‍ය පිටපතක් බාගත කරයි; එම විකල්ප පටයක් නොමැතිව, එය වීඩියෝ පමණක් වේ.

**පරිවර්තන රැඳවුම (#12150 P1).** වීඩියෝ බ්‍රිජ් (ඇත්තෙන්ම විකල්ප) පරිවර්තන කුයියක් නිර්මාණය කරන විට මෙය ස්වයංක්‍රීයව යෙදී ඇත — වෙනම රැඳවුම් ලාංඡනයක් නොමැත. ඉල්ලීමක් ඕනෑම පරිවර්තන කුයියක් නිර්මාණය කරන විට (ඇමතුම්කරුවෙකු විසින් ප්‍රකාශිත `transcript` හෝ ඒකාබද්ධ `audioTranscript`), ආරක්ෂිත මැඩටා දත්තය එය `videoBridgeObserved` ලෙස සලකයි සහ වීඩියෝ විස්තරයේ රහස්‍ය සෙවනක් නිර්මාණය කරයි — සෑම කුයියකම නිදහස්-පෙළ ශරීරය `[redacted-video-transcript]` යනුවෙන් වෙනස් කරන සමාන නිර්මාණයක්, වාසියන්ගේ වාසියන්ගේ ක්ෂේත්‍රය පෙරනිමියෙන් වෙනස් කිරීමෙන් නිර්මාණය කරයි (සමහර විට සම්පූර්ණ පෙළ විකල්පය, එබැවින් කිසිදු කුයියක අන්තර්ගතය — විරුද්ධ හෝ සාමාන්‍ය, `]` ඇතුළුව ශරීරයන් ඇතුළුව `[`[inaudible]`/`[music]`— ජීවත් විය නොහැක). රැඳී ඇති ඇමතුම් ලොග් ඉල්ලීමේ ශරීරය සෑම වීඩියෝ-අවශ්‍ය පෙළ කොටසක් සඳහා එම රහස්‍ය සෙවන සඳහා වෙනස් කරයි, අන්තර්ගත සමානතාවය මගින් ගැලපේ;`fullText` ඇන්කර් එක අවසන් පෙර-ඇමතුම් ආරක්ෂිත මැඩටා දත්තයෙන් නැවත කියවයි, එබැවින් ගැලපීම පසුව සංකේතකාරක මැඩටා දත්ත (PII සහ ණය ආවරණය, ප්‍රමුඛතා 10/95) විස්තර පෙළ ස්ථානයේ නැවත ලිවීමෙන් පසු සාර්ථක වේ. ආකෘතියට යවන ශරීරය වෙනස් නොවේ. නිරීක්ෂණය කළ ඉල්ලීමක් ද කුඩා මතකයක් පිරවීමක් නොකරයි (ඉල්ලීම සහ ප්‍රතිචාරයෙන් ලබා ගන්නා ලද නිර්මාණය ඉක්මවා යයි), එබැවින් ආකෘතියේම පිළිතුරක් මතකයට පරිවර්තන පෙළ ප්‍රතිචාරය කළ නොහැක.

පාරිභෝගිකයා සත්‍යාපිත යතුරෙන් හිමිකම ලබා ගනී, යතුරු ප්‍රතිපත්තිය යෙදවයි, සහ නොදන්නා, කල් ඉකුත් වූ සහ වෙනත් යතුරු කුලක සඳහා එකම 404 ආපසු ලබා දේ. එය `variant=preview|standard|detail` (උපරිම JPEG විශාලත්වය 320/640/1280, කිසිදාම වැඩි නොකරයි), `limit=1..8` (හෝ පුරාණ `frames` සමාන, කිසිදාම දෙකම නොවේ), ශුන්‍ය-මූලික `page`, සහ විකල්ප `start`/`end` අවධානයේ තත්පර ලබා දේ. අනුපිළිවෙලේ ප්‍රශ්න යතුරු සහ විපරිත අවධි කවුළුව ප්‍රතික්ෂේප කරයි. සෑම ආපසු ලබා දෙන විකල්පයක්ම එහි වාසිය සහ සත්‍ය විසාලත්වය මූලික දත්ත වල හැෂ් එකක් ඇත, රැඳී සිටින මූලාශ්‍රයට සම්බන්ධ වේ. විකල්ප කියවීමේදී නිර්මාණය කරයි, අතිරේක රැඳීම් පිටපත් ලෙස ගබඩා නොකරයි. JSON ප්‍රතිචාරය, Base64/ආවරණය ඇතුළුව, 32 MiB කුඩුකාරකය සීමා කරයි; අධික පිටුවක් 413 ආපසු ලබා දේ සහ පාරිභෝගිකයා අඩු පින්තූර ඉල්ලිය යුතුය. කියවීම් සෑම ප්‍රමාණය සහ නැවත පරීක්ෂා කිරීමේදී අවලංගු කිරීම පරීක්ෂා කරයි, ප්‍රතිචාර ලබා දීමට පෙර. හිමිකරු විසින් `DELETE` අයිඩම්පොටෙන්ටි වේ; මකීම හෝ TTL කල් ඉකුත් වීම රැඳී සිටින මූලික සහ භාවිතා ගණනය නිදහස් කරයි.

සाझා කරන ලද ගබඩාව ක්‍රියාවලිය-දේශීය වේ: කුලක නැවත ආරම්භ කිරීමේදී කල් ඉකුත් වේ සහ ස්වාධීන OmniRoute ක්‍රියාවලීන් අතර මාරු කළ නොහැක. කළමනාකරණ සංඛ්‍යාලේඛන ප්‍රතිඵලදායක රැඳීම්/දුරස්ථ ප්‍රතිපත්තිය සහ එකතුවෙන් රැඳී සිටින ඇතුළුවීම්/බයිට් පමණක් ප්‍රකාශ කරයි, මාධ්‍ය, යොමු, ප්‍රධාන ID හෝ කුලක නොවේ. වීඩියෝ සැකසුම් පැනලය එම අගයන් පෙන්වයි සහ එකඟතාව සවිස්තර කරයි. මෙම ක්‍රියාත්මක ලේඛනය සජීවී ආරම්භය හෝ ප්‍රවර්ධන සාක්ෂියක් නොවේ; යථාර්ථ ආකෘතියේ පිළිගැනීම වෙනම සටහන් කර ඇත.

Frames are captioned sequentially with the configured Video model. An empty
Video override inherits the Vision setting; if both are empty, the Vision
auto-router selects the effective vision-capable model. Successful captions
replace the original part with a stable `[Video description:` prefix that also
marks the text as an untrusted media-derived observation and tells downstream
models not to follow instructions found in the media. Frame-caption cache keys
include the JPEG bytes, prompt, timestamp, and effective model; only successful
captions are cached. Cache entries retain the actual successful producer model,
including a fallback model; the bridge reports `mixed` when different frames
were produced by different models. A cache hit reuses that producer identity
instead of relabeling it as the requested routing plan. The whole-video result
cache is keyed on every input that changes the output — prompt, effective
model, sampling policy, frame count, semantic analysis mode, the SHA-256
fingerprint of the normalized focus hint, focus window, `transcript`,
`audioTranscript`, and the contact-sheet flag — so changing any of those
dimensions is a cache miss, never a stale reuse. The visual dedup policy
version, threshold, and bounded candidate-frame count are also explicit in the
result-cache key and metadata; a policy change therefore cannot reuse a stale
whole-video description. Result-cache v4 metadata keeps the mode and
fingerprint, never the raw user task. Guardrail metadata reports both the
requested and effective analysis modes; a requested `focused` mode without
usable user text is reported as effectively `full`.

The guardrail extracts every supported video part but describes no more than
`modalityBridgeVideoMaxVideos`. For a target proven to have
`supportsVideo === false`, failed and over-limit videos become explicit safe
text markers so no raw video survives. When capability is unknown, those parts
remain untouched. Targets with `supportsVideo === true` bypass the bridge.
The client request abort signal propagates through download, broker queue,
subprocesses, and caption calls; aborts stop between videos and never fail open
to raw media.

Runtime settings are DB-backed and Zod-validated:

| Key                                 | Default     | Range / behavior                                                                                    |
| ----------------------------------- | ----------- | --------------------------------------------------------------------------------------------------- |
| `modalityBridgeVideoEnabled`        | `false`     | Optional runtime, opt-in                                                                            |
| `modalityBridgeVideoAnalysisMode`   | `"full"`    | `full` preserves generic captions; `focused` uses bounded, untrusted latest-user context            |
| `modalityBridgeVideoModel`          | `""`        | Inherit the Vision Bridge model                                                                     |
| `modalityBridgeVideoFrameCount`     | `8`         | 1–16                                                                                                |
| `modalityBridgeVideoSamplingPolicy` | `"uniform"` | `uniform`, `scene_aware`, or proportional `segment_aware`; detector failure falls back to `uniform` |
| `modalityBridgeVideoMaxVideos`      | `1`         | 1–4                                                                                                 |
| `modalityBridgeVideoTimeout`        | `120000`    | 1000–120000 ms                                                                                      |

Legacy persisted Video timeout values above 120 seconds are clamped to the
broker deadline; new settings writes above that limit are rejected.
`GET /api/modality-bridge/video/runtime` requires trusted stamped loopback
locality before authentication or runtime probing, then requires management
auth. It returns only `available`, sanitized FFmpeg/ffprobe versions, and a fixed
reason when the runtime is unavailable. The internal extraction endpoint is not
a public upload API: queue saturation returns `503` plus `Retry-After`, a caller
disconnect returns `499`, and the fixed broker deadline returns `504`. Converted responses add
`video->text;model=<visionModel>;parts=<videos>` to the central
`x-omniroute-modality-bridge` header without removing Vision or Audio segments.

### PII Masker (`piiMasker.ts`)

Runs on **both** stages.

- **`preCall`** clones the payload, walks `system`, `messages`, `input`, and
  `prompt` (including plain string items), and applies `processPII()` (from
  `@/shared/utils/inputSanitizer`) to string `content`/`text` fields. When
  `PII_REDACTION_ENABLED=true`, detected PII is redacted in the outbound
  payload. This is independent of `INPUT_SANITIZER_MODE` (which only controls
  prompt-injection policy). When redaction is off, the call records detection
  counts without rewriting content.
- **`postCall`** deep-clones the response, runs `sanitizePIIResponse()` plus
  the Responses-API-shape masker (`maskResponsesOutput` — covers
  `output_text` and `output[].content[].text`). If any redaction occurs, the
  modified response replaces the original.

The guardrail never blocks; it only annotates (`meta.detections`,
`meta.redacted`) or rewrites.

### Prompt Injection (`promptInjection.ts`)

Detects adversarial structures in user-supplied content and enforces the
configured policy. Behavior is driven by environment variables and constructor
options:

| සැකසුම         | Env var                                                                                                  | පෙරනිමිය | බලපෑම                                                                                                                                                                              |
| -------------- | -------------------------------------------------------------------------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| සක්‍රීය        | `INPUT_SANITIZER_ENABLED`                                                                                | `true`   | `false` නම්, ගාර්ඩ්රේල් කෙටි සක්‍රීය වේ.                                                                                                                                           |
| ආකාරය          | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                          | `warn`   | ඇතුළත් ප්‍රතිපත්තිය: `block`, `warn`, හෝ `log`. (`redact` පසුබැසීම සඳහා පිළිගනු ලැබේ නමුත් ඇතුළත් පෙළ ඉවත් නොකරයි; ඉල්ලීමේ PII නැවත ලිවීම `PII_REDACTION_ENABLED` මගින් පාලනය වේ.) |
| බ්ලොක් තිරසාරය | `blockThreshold` විකල්පය / `INPUT_SANITIZER_BLOCK_THRESHOLD` (ආලියාස් `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`   | බ්ලොක් කිරීමට අවශ්‍ය අවම තරම. මධ්‍යමය සාමාන්‍යයෙන් පරීක්ෂා කිරීම සඳහා පමණි.                                                                                                        |

**ආකාරය ප්‍රමුඛත්වය** (`getMode`): caller `options.mode` →
`INJECTION_GUARD_MODE` **DB විශේෂාංග-ඇතුළත් කිරීම** (Dashboard → Settings →
Feature Flags) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env →
`warn`. එබැවින්, Dashboard override එක env vars වලට වඩා ජයග්‍රහණය කරයි, එබැවින් Feature
Flags UI ක්‍රියාත්මක ගාර්ඩ් එක පාලනය කරයි (නැවත ආරම්භ කිරීමක් නැත). DB කියවීම අසාර්ථක නම්:
එය දෝෂයක් ඇති වුවහොත්, ගාර්ඩ් එක env-පදනම් වූ හැසිරීමකට පසුබැසෙයි, සහ කිසිදු
උපකාරයක් සකස් නොකළහොත් හැසිරීම env-පදනම් වූ විසඳුමට සමාන වේ.

හඳුනාගැනීමේ මූලාශ්‍ර:

1. `sanitizeRequest()` from `@/shared/utils/inputSanitizer` (pipeline එකේ වෙනත් ස්ථාන වල භාවිතා කරන බෙදාගත් හඳුනාගැනුම් සෙට් එක).
2. Built-in `DEFAULT_GUARD_PATTERNS` (දැනට `system_override_inline` සහ
   `markdown_system_block`, දෙකම `high` තරම).
3. Optional `customPatterns` constructor options මඟින් ලබා දෙන (ස්ත්‍රීන්ග්, regex,
   හෝ `{ name, pattern, severity }` වාර්තා).

`mode === "block"` **හා** අවම වශයෙන් එකක් හඳුනාගැනීමේ තරම
තිරසාරය සම්පූර්ණ වූ විට, `preCall` `{ block: true, message: "Request rejected:
suspicious content detected" }` ආපසු ලබා දේ. `warn`/`log` ආකාර වලදී ගාර්ඩ්රේල් ලොග් කරයි නමුත්
ඉල්ලීම ඉඩ දෙයි. බෙදාගත් උපකාරක `evaluatePromptInjection()` ද ලියාපදිංචි මඟින් නොයන
ඉල්ලුම් සඳහා ඇගයීමට අපේක්ෂා කරයි.

**Scan bound (v3.8.20):** හඳුනාගැනුම්කරු **පළමු 16 KB** පමණක් පරීක්ෂා කරයි
එකතු කළ ප්‍රොම්ප්ට් පෙළ — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 bytes) in
`src/shared/utils/inputSanitizer.ts`. `detectInjection()` සහ
`evaluatePromptInjection()` `slice(0, MAX_INJECTION_SCAN_BYTES)` ක්‍රියාත්මක කිරීමට පෙර.
ඇතුළත් උපදෙස් ඇතුළුවීම් වල ඉහළින් සිටී, එබැවින් මෙය regex CPU/GC කුඩා කිරීමේදී
බලපාන බවක් නැත (cf. #3932, #4041).

### ණයපත් මස්කර් (`credentialMasker.ts`)

**දෙකම** අදියරවල ක්‍රියාත්මක වේ, පෙරනිමිය සම්මත දාමයේ අවසන් (ප්‍රමුඛත්වය `95`).
පිටතට යන payload එකෙන් (පණිවිඩ අන්තර්ගතය, මෙවලම්-ඉල්ලීම් ආර්ථික, මෙවලම් ප්‍රතිඵල)
හොඳින් දන්නා API-කී / රහස්-ටෝකන් ආකාරයන් ඉවත් කරයි **හා** සැපයුම්කරුගේ ප්‍රතිචාරය,
එබැවින් ප්‍රොම්ප්ට් එකකට ඇතුළත් කරන ලද ණයපතක් (හෝ මෙවලම් ප්‍රතිඵලයක් මඟින් ආපසු ප්‍රකාශිත)
ඉහළ සැපයුම්කරුට හෝ ගනුදෙනුකරුට සොයා නොගනු ඇත.

- **Opt-in පමණක්**, PII ඉවත් කිරීමේ සමාන සම්ප්‍රදාය (Hard Rule #20-සම්බන්ධ):
  `settings.credentialRedactionEnabled === true` **හෝ**
  `CREDENTIAL_REDACTION_ENABLED=true` නොමැතිනම් අක්‍රීය වේ. එය අක්‍රීය කළහොත්,
  ගාර්ඩ්රේල් එකක් නොවේ — එය කිසිදා බ්ලොක් නොකරයි සහ කිසිදා නැවත ලිවීමක් නොකරයි.
- `redactCredentials()` සම්පූර්ණ payload/ප්‍රතිචාර ගසනවා (`walkValue()`,
  prototype-pollution-safe, cycle-safe via `WeakSet`) සහ ගැලපීම් `[REDACTED:<type>]`
  ස්ථානයකින් වෙනස් කරයි, සත්‍යයෙන් වෙනස් වූ ශාඛා පමණක් පිටපත් කරයි.
- `CREDENTIAL_PATTERNS` LLM සැපයුම්කරු කී (OpenAI, OpenAI-proj,
  Anthropic, Google, Hugging Face, Replicate), VCS/SaaS ටෝකන් (GitHub, Slack,
  Linear, Notion, npm, Postman, Discord), ගෙවීම් කී (Stripe, Square), වාසිය
  කී (AWS access key, Twilio, SendGrid, Mailgun), පෞද්ගලික කී / JWTs,
  ණයපත් අඩංගු සම්බන්ධතා වාසිය (`mongodb://user:pass@...`, ආදිය), සහ
  සාමාන්‍ය `Authorization`/`x-api-key`/`api-key`/`apikey` හිඩ්ර්-අගුළු
  ආකාරය ආවරණය කරයි. හිඩර්-ආකාර කී (`authorization`, `x-api-key`, `api-key`,
  `apikey`) ව්‍යුහමය ලෙස ඉවත් කරයි (අගය පමණක්, යෝජනා පෙරනිමියක් ලෙස
  `Bearer `/`Basic ` පවත්වාගෙන යයි) සාමාන්‍ය පෙළ regex මඟින් නොව.
- ගාර්ඩ්රේල් එක කිසිදා බ්ලොක් නොකරයි; එය පමණක් නැවත ලිවීමක් කරයි (`modifiedPayload` /
  `modifiedResponse`) සහ සටහන් කරයි (`meta.credentialsRedacted`, `meta.count`).

ප්‍රතිපත්ති ආරක්ෂකය: `tests/unit/credential-masker-guardrail.test.ts`.

## මූලික ගිවිසුම (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true මඟින් දාමය කෙටි මාර්ගයෙන් අවසන් කරයි
  message?: string; // අවහිර කිරීමේදී පෙන්වනු ලැබේ
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // ඉල්ලීම නැවත ලිවීම සඳහා preCall විසින් ආපසු ලබා දෙයි
  modifiedResponse?: TValue; // ප්රතිචාරය නැවත ලිවීම සඳහා postCall විසින් ආපසු ලබා දෙයි
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ආරක්ෂක සීමාවක් `void`, `{}`, හෝ `{ block: false }` යන ඒවායින් එකක් ආපසු ලබා දීමෙන් "වෙනසක් නැත" යන්න සංඥා කරයි. `modifiedPayload`/`modifiedResponse` එකක් ආපසු ලබා දීමෙන්, දාමය හරහා පහළින් ඇති ආරක්ෂක සීමා වෙත ගලා යන අගය ප්රතිස්ථාපනය කරයි.
`signal?: AbortSignal` මඟින් ඇමතුම්කරුගේ ජීවන චක්රය ආරක්ෂක සීමා වෙත ගෙන යයි. ඉල්ලීමක් අවලංගු කිරීම හිතාමතාම යොදා ඇති fail-open ව්යතිරේකයයි: මාධ්ය පාලම්, එයට සහාය නොදක්වන බව දන්නා ඉලක්කයකට අමු මාධ්ය යළි පිහිටුවීමකින් තොරව, කාර්යය නවතා පිරිසිදු කිරීම සිදු කරයි.

## ලේඛනය (`registry.ts`)

තනි අවස්ථාවක් වන `guardrailRegistry` පහත දෑ නිරාවරණය කරයි:

- `register(guardrail)` — ආරක්ෂක සීමාවක් එක් කරයි (හෝ සාමාන්යකරණය කළ නම අනුව ප්රතිස්ථාපනය කරයි) සහ
  ආරෝහණ `priority` අනුව නැවත අනුපිළිවෙළට සකසයි.
- `clear()` / `list()` — පරිපාලන උපකාරක.
- `runPreCallHooks(payload, context)` — සක්රිය ආරක්ෂක සීමා හරහා පුනරාවර්තනය කරමින්,
  `modifiedPayload` හරහා payload එක යොමු කර, පළමු `block: true` හිදී නවතී.
- `runPostCallHooks(response, context)` — ප්රතිචාර පැත්තේද එම ප්රවාහයම ක්රියාත්මක කරයි.
- `resetGuardrailsForTests({ registerDefaults })` — පිරිසිදු පරීක්ෂණ හුදකලාකරණයක් සඳහා තත්ත්වය ඉවත් කර, විකල්පයක් ලෙස
  පෙරනිමි නැවත ලියාපදිංචි කරයි.

ධාවක දෙකම `{ blocked, payload|response, results, guardrail?, message? }`
ආපසු ලබා දෙයි. මෙහි `results` යනු, ලුහුබැඳීම සඳහා ප්රයෝජනවත් වන,
එක් එක් ආරක්ෂක සීමාවට අදාළ `blocked`, `skipped`, `modified`, `error`, සහ `meta` ක්ෂේත්ර ඇතුළත්
`GuardrailExecutionResult` වාර්තා මාලාවකි.

### එක් එක් ඉල්ලීම අනුව ආරක්ෂක සීමා අක්රිය කිරීම

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` වත්මන්
ඉල්ලීම සඳහා මඟහැරිය යුතු ආරක්ෂක සීමා නාමවල අනුපිටපත් ඉවත් කළ ලැයිස්තුවක්
එක්රැස් කරයි. මූලාශ්ර (සියල්ල විකල්ප වන අතර සියල්ල ඒකාබද්ධ කෙරේ):

- `apiKeyInfo.disabledGuardrails`
- ඉල්ලීම් body හි `disabledGuardrails` (ඉහළම මට්ටමේ)
- ඉල්ලීම් body හි `metadata.disabledGuardrails`
- `x-omniroute-disabled-guardrails` header එක (හෝ පැරණි
  `x-disabled-guardrails`)

අගයන් string මාලා හෝ කොමා මඟින් වෙන් කළ string එකක් විය හැක; නම්
සිම්පල් අකුරු සහිත kebab-case ආකාරයට සාමාන්යකරණය කෙරේ (`pii_masker` → `pii-masker`). ප්රතිඵලය
`context.disabledGuardrails` හරහා registry වෙත යවනු ලබන අතර, එය
ගැළපෙන ආරක්ෂක සීමා මඟහරියි (`results` තුළ `skipped: true`).

## ක්රියාත්මක කිරීමේ අනුපිළිවෙළ

`src/sse/handlers/chat.ts` සහ `open-sse/handlers/chatCore.ts` හරහා ගලා යන සෑම ඉල්ලීමක් සඳහාම:

1. `resolveDisabledGuardrails(...)` API යතුර, body එක සහ headers වෙතින් මඟහැරීමේ ලැයිස්තුව සාදයි.
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ප්රමුඛතා අනුපිළිවෙළ අනුව guardrails ක්රියාත්මක කරයි:
   - අක්රිය කළ guardrails `skipped` ලෙස සටහන් කෙරේ.
   - සෑම guardrail එකකම `preCall` හට `modifiedPayload` හරහා payload එක නැවත ලිවිය හැක.
   - පළමු `block: true` මඟින් දාමය කෙටි මාර්ගයෙන් නවතා, handler එක guardrail ප්රතික්ෂේප කිරීමේ ප්රතිචාරයක් ආපසු ලබා දෙයි.
3. (නැවත ලියා තිබිය හැකි) payload එක combo routing සහ upstream dispatch වෙත ගලා යයි.
4. ප්රතිචාරය එකලස් කිරීමෙන් පසු, `guardrailRegistry.runPostCallHooks(...)` එම දාමයම ප්රතිචාරය මත ක්රියාත්මක කරයි. මෙහිදී `block: true` මඟින් upstream ප්රතිචාරය ඉවත් කරයි.

දෝෂ නිකුත් කරන guardrails, `error: <message>` සමඟ සටහන් කර `logger.warn` හරහා log කරනු ලබන නමුත්, දාමය දිගටම ක්රියාත්මක වේ — සැලසුම අනුව මෙය fail-open වේ.

## අභිරුචි Guardrails

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

පියවර:

1. `BaseGuardrail` දිගු කරමින් `src/lib/guardrails/myGuardrail.ts` සාදන්න.
2. `preCall` සහ/හෝ `postCall` ක්රියාත්මක කරන්න.
3. එක්කෝ import කරන අවස්ථාවේදී ලියාපදිංචි කරන්න (`registerDefaultGuardrails` වෙතින් push කරන්න), නැතහොත්
   runtime හිදී `guardrailRegistry.register(...)` අමතන්න — registry එක එකම normalized නම සහිත
   ඕනෑම පෙර guardrail එකක් ප්රතිස්ථාපනය කරයි.
4. `tests/unit/` යටතේ පරීක්ෂණ එක් කරන්න (පවතින උදාහරණ:
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`).

## පරීක්ෂා කිරීම

දන්නා තත්ත්වයකින් ආරම්භ කිරීම සඳහා පරීක්ෂණ අතරතුර `resetGuardrailsForTests()` භාවිත කරන්න.
හිස් registry එකකින් ආරම්භ කිරීමට `{ registerDefaults: false }` යොමු කර,
පරීක්ෂණයට ලක් කරන guardrails පමණක් ලියාපදිංචි කරන්න. Vision Bridge dependency
injection (`deps.getSettings`, `deps.callVisionModel`) පිළිගනී; Audio Bridge මඟින්

## Injection-guard route ආවරණය සහ red-team (අදියර 8 · කොටස D)

පරිශීලක prompts පිළිගන්නා සියලුම routes injection-guard එක (`createInjectionGuard` / `withInjectionGuard`) මඟින් ආවරණය කෙරේ.
එය `INJECTION_GUARD_MODE` අනුගමනය කරයි (පෙරනිමි `warn` = log කිරීම පමණි;
`block` = HTTP 400 `SECURITY_001` ආපසු ලබා දෙයි).

| වර්ගය       | Routes                                                                                                                                               | පෙරනිමි ප්රකාරය |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| පෙළ (පවතින) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn            |
| උත්පාදක     | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn            |
| දත්ත        | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn            |

පෙළ උකහා ගැනීම (`extractMessageContents`) මඟින් `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` ආවරණය කෙරේ.

**Red-team (රාත්රී, `nightly-llm-security.yml`):** සෑම route එකක්ම
`INJECTION_GUARD_MODE=block` තුළ ඇති OWASP-LLM corpus එක අවහිර කරන බව promptfoo වලංගු කරයි; garak probes ධාවනය කරයි (secret එකක් නොමැතිව මඟ හරියි).
අනුකූලතාව සඳහා `moderations` ඇතුළත් කර ඇත — block-mode හි operators හට
`resolveDisabledGuardrails` හරහා එය නිදහස් කළ හැක.

රාත්රී workflow එකට (`.github/workflows/nightly-llm-security.yml`, cron + manual
dispatch) jobs දෙකක් ඇත:

- **`promptfoo-guard` (අවහිර කරන)** — `INJECTION_GUARD_MODE=block` සමඟ
  `promptfoo eval -c promptfooconfig.yaml` ධාවනය කරයි. සෑම ප්රතිවාදී අවස්ථාවක්ම (උදා: "පෙර සියලු
  උපදෙස් නොසලකා හරින්න…", DAN-ශෛලියේ jailbreaks) response එකෙහි
  `error.code === "SECURITY_001"` අඩංගු බව තහවුරු කරයි, එනම් guard එක ඇත්ත වශයෙන්ම ඉල්ලීම ප්රතික්ෂේප කළ බවයි.
- **`garak` (උපදේශාත්මක)** — දේශීය OmniRoute instance එකකට (`http://localhost:20128/v1`) එරෙහිව garak
  `--probes promptinject,dan,leakreplay` ධාවනය කරයි. provider secret එකක්
  (`PROMPTFOO_PROVIDER_KEY`) මත පදනම්ව සක්රීය වේ; එය නොමැති නම් නිසි ලෙස මඟ හැරෙන අතර
  `|| true` යොදා අවසන් කර ඇත, එබැවින් CI අසාර්ථක නොකර වාර්තා කරයි.
