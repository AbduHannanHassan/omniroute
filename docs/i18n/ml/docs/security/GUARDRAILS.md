> **അവസാനം അപ്ഡേറ്റ് ചെയ്തത്:** 2026-08-29 — v3.8.51 (വീഡിയോ ബ്രിഡ്ജ് ട്രാൻസ്ക്രിപ്റ്റ് പ്രൂവനെൻസ് കോളർ-പ്രഖ്യാപിച്ചതാണ്,
> ഇതുവരെ സെർവർ-പരിശോധിച്ചിട്ടില്ല — #11661 അനുസരിച്ച് വ്യക്തമാക്കിയത്)

OmniRoute-നും അപ്സ്ട്രീം പ്രൊവൈഡർമാർക്കും ഇടയിലുള്ള അതിർത്തിയിൽ സുരക്ഷ, നയം, ഉള്ളടക്ക പരിവർത്തനങ്ങൾ എന്നിവ ഗാർഡ്റെയിലുകൾ നടപ്പിലാക്കുന്നു. ഓരോ ഗാർഡ്റെയിലിനും അഭ്യർത്ഥന പേലോഡുകളും (`preCall`) അപ്സ്ട്രീം പ്രതികരണങ്ങളും (`postCall`) പരിശോധിക്കാൻ (ഓപ്ഷണലായി നിരസിക്കുകയോ, രൂപാന്തരപ്പെടുത്തുകയോ, വ്യാഖ്യാനിക്കുകയോ ചെയ്യാം) കഴിയും.

സിസ്റ്റം **ഫെയിൽ-ഓപ്പൺ** ആണ്: ഒരു ഗാർഡ്റെയിൽ പ്രവർത്തിക്കുമ്പോൾ പിശക് സംഭവിച്ചാൽ, രജിസ്ട്രി പിശക് രേഖപ്പെടുത്തുകയും അഭ്യർത്ഥന പരാജയപ്പെടുത്തുന്നതിന് പകരം അടുത്ത ഗാർഡ്റെയിലുമായി മുന്നോട്ട് പോകുകയും ചെയ്യുന്നു. തടയുന്നത് ഒരു വ്യക്തമായ തീരുമാനമാണ് (`block: true`), ഒരിക്കലും ഒരു അപകടമല്ല.

### വിസൻ ബ്രിഡ്ജ് (`visionBridge.ts`) — മോഡാലിറ്റി ബ്രിഡ്ജ് PR-1

**അന്യ-വിദ്യാഭ്യാസ മോഡലുകൾ** ലക്ഷ്യമിട്ടുള്ള ചിത്രം അടങ്ങിയ അഭ്യർത്ഥനകൾ തടയുന്നു
മൊത്തം അഭ്യർത്ഥന ഒരു ദൃശ്യ-ശേഷിയുള്ള മോഡലിലേക്ക് പുനർനിർദ്ദേശിക്കുന്നു അല്ലെങ്കിൽ ചിത്രം
ഭാഗങ്ങൾ ഒരു ക്രമീകരിക്കാവുന്ന ദൃശ്യ മോഡൽ നിർമ്മിച്ച ടെക്സ്റ്റ് വിവരണങ്ങളാൽ മാറ്റുന്നു
ഉപരിതല വിളിക്കലിന് മുമ്പ്. ഇത് ടെക്സ്റ്റ്-മാത്രം പ്രദാതാക്കൾക്ക് പരസ്പരം കൈകാര്യം ചെയ്യാൻ അനുവദിക്കുന്നു
മൾട്ടിമോഡൽ പേലോഡുകൾ.

പ്രവാഹം:

1. ലക്ഷ്യ മോഡൽ ഇതിനകം ദൃശ്യത്തെ പിന്തുണയ്ക്കുന്നുവെങ്കിൽ ഒഴിവാക്കുക (അല്ലെങ്കിൽ അത്
   നിർബന്ധിത-ബ്രിഡ്ജ് പട്ടികയിൽ പ്രത്യക്ഷപ്പെടുന്നില്ല `isVisionBridgeForcedModel`).
2. ചിത്രം ഭാഗങ്ങൾ എടുക്കുക `extractImageParts(messages)`
   (`visionBridgeHelpers.ts`), ഇത് **യൂണിഫൈഡ് മീഡിയ
   ഡിറ്റക്ടർ** `detectMediaParts()` ൽ委托 ചെയ്യുന്നു `open-sse/utils/mediaParts.ts` —
   കോമ്പോ സാങ്കേതികതാ ഫിൽട്ടറുമായി പങ്കുവെക്കുന്ന സത്യത്തിന്റെ ഏക ഉറവിടം.
   എടുക്കൽ `replaceImageParts` തിരിച്ചുവിടാൻ കഴിയുന്ന രൂപങ്ങളുടെ മുകളിലത്തെ ഭാഗങ്ങൾക്കായി അനുവദനീയമാണ്
   (എടുക്കൽ↔മാറ്റം കരാർ): OpenAI
   `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL
   `source.type:"url"`, and Responses API `input_image`. Nested hits and
   indicator-only shapes are combo-filter material and are never extracted.
   ഒന്നും കണ്ടെത്തിയില്ലെങ്കിൽ ഒഴിവാക്കുക.
3. റൺടൈം കോൺഫിഗറേഷൻ പരിഹരിക്കുക `resolveVisionBridgeRuntimeSettings()`
   (`src/shared/constants/modalityBridgeDefaults.ts`): പുതിയ `modalityBridge*`
   ക്രമീകരണ കീകൾ വിജയിക്കുന്നു; പാരമ്പര്യ `visionBridge*` കീകൾ ഒരു **ഒരു-ചക്രം
   പിന്‍വലിക്കൽ** (rollback window). ബ്രിഡ്ജ് അപ്രാപ്യമായപ്പോൾ ഏതെങ്കിലും മീഡിയ യാത്രയ്ക്കുമുമ്പ് ഒഴിവാക്കുക.
4. മോഡ് സെലക്ടർ (`modalityBridgeVisionMode`, താഴെ കാണുന്ന പട്ടിക കാണുക) തീരുമാനിക്കുന്നു
   പുനർനിർദ്ദേശം vs വിവരണം. പുനർനിർദ്ദേശം `modifiedPayload` തിരികെ നൽകുന്നു
   മാത്രം `model` മാറ്റിയ, കൂടാതെ മെറ്റാ `{ rerouted, fromModel, toModel, imagesKept }`.
5. വിവരണ പാത: ചിത്രങ്ങൾ `maxImages` ൽ പരിമിതപ്പെടുത്തുക, ടാസ്‌ക്-അറിയുന്ന പ്രോംപ്റ്റ് രൂപീകരിക്കുക,
   വിവരണം കാഷ് പരിശോധിക്കുക, ദൃശ്യ മോഡൽ വിളിക്കുക **സമാന്തരമായി**
   (`Promise.allSettled`), and inject `[Image N]: <description>` text parts in
   their place. A failed describe yields `null` and the original image part is
   **preserved** (#4012) — except on the combo describe path when every
   describe failed, where a confirmed non-vision upstream gets an
   `(unavailable — no vision-capable provider connected)` stub instead (#8430).
6. തിരികെ നൽകുക `modifiedPayload` + മെറ്റാ (`imagesProcessed`, `descriptions`,
   `processingTimeMs`, `visionModel`).

പ്രി-PR-1 ഗാർഡ്‌റെയിലിന് ബൈറ്റ്-ഐഡന്റിക്കൽ ആണ്.

#### ടാസ്‌ക്-അറിയുന്ന വിവരണം പ്രോംപ്റ്റ് (`modalityBridgeVisionTaskAware`)

ഡിഫോൾട്ട് **സത്യം**. `composeVisionPrompt()` (`visionBridgeHelpers.ts`) ചേർക്കുന്നു
**അവസാന ഉപയോക്തൃ സന്ദേശത്തിന്റെ** (500 അക്ഷരങ്ങൾക്ക് ചുരുക്കിയ) ടെക്സ്റ്റ് അടിസ്ഥാനത്തിൽ
വിവരണം പ്രോംപ്റ്റ്, വിവരണത്തെ ഉപയോക്താവ് യഥാർത്ഥത്തിൽ ചോദിച്ചതിലേക്ക് നയിക്കുന്നു
(codex-vision-proxy pattern) and asking the vision model to transcribe visible
text. With the flag off — or no user text — the base prompt is used unchanged.

The describe self-loop's own OpenAI-compatible request (`callVisionModelSingle()`
in `visionBridgeHelpers.ts`) always requests `image_url.detail: "high"` —
unconditionally, for every caller/provider, not gated on any client signal.
Low-detail sampling degrades OCR accuracy for exactly the text-transcription
task this prompt asks for, so the describe call itself always asks for high
detail regardless of what detail level the original inbound request used. This
only affects the internal describe request body; it does not change how
OmniRoute forwards the caller's own `image_url.detail` on the primary request —
that default is applied separately, and only for detected OpenCode clients, in
`defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`). The
Anthropic wire-format branch of the describe self-loop has no `detail` field
and is unaffected by either default.

#### Describe output cap (`modalityBridgeVisionMaxChars`)

| Key                            | Default | Range            |
| ------------------------------ | ------- | ---------------- |
| `modalityBridgeVisionMaxChars` | `0`     | `0` or 100–50000 |

`0` (default) means **no cap** — the description returned by
`callVisionModel()` is passed through unmodified, preserving the existing
behavior. Any value in the 100–50000 range truncates the description with a
`…` suffix before it is spliced back as `[Image N]: <description>`
(`VisionBridgeGuardrail.preCall()` in `src/lib/guardrails/visionBridge.ts`).
Raise this for detail-heavy OCR tasks where the downstream model needs the
full transcription; lower it to bound token usage on chatty vision models.
The dashboard field lives on the Vision tab's Advanced panel
(`modality-bridge-max-chars` in `ModalityBridgeVisionTab.tsx`) and clamps any
value between 1 and 99 up to the 100 floor while leaving an explicit `0`
untouched — `0` is a valid Zod value in its own right
(`z.union([z.literal(0), z.number().int().min(100).max(50000)])`), not merely
the "unset" default.

#### Describe cache (`modalityBridge/bridgeCache.ts`)

In-memory LRU + TTL cache for describe outputs, shared process-wide.
Key = `sha256(imageRef + composedPrompt + configuredBridgeModel)` with
length-prefix framing (no field-boundary collisions). The model component is
the **configured** bridge model, not the model that actually answered —
`callVisionModel` may fall back internally, and keying per attempt would
fragment the cache. Failed describes are never cached. Settings:

| Key                             | Default | Range   |
| ------------------------------- | ------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`  | —       |
| `modalityBridgeCacheTtlMinutes` | `60`    | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`   | 10–5000 |

#### Remote image normalization (self-loop describe/base64 fetch)

When the bridge fetches a **remote** image itself — the Anthropic describe
self-call and the claude-wire-format base64 conversion
(`ensureBase64ImagesForClaudeWire`), both via
`fetchRemoteImageAsDataUri()` in `visionBridgeHelpers.ts` — the resulting data
URI is passed through `normalizeDataUri()`
(`open-sse/utils/imageNormalize.ts`) before being embedded in the vision-model
request. Oversized images are downscaled to a **2048px long edge** (matching
the resize cap OpenAI/Anthropic already apply server-side), which cuts
upload bytes/latency without changing what the vision model sees. Resizing
uses `sharp`, loaded via dynamic import: on a platform where its native
binary fails to load, `normalizeDataUri()` **never throws** — it falls back
to a passthrough of the original bytes, so the describe/base64-conversion
path always keeps working. Non-image bytes (a fetch that did not return a
decodable image) are also passed through untouched. This normalization is
scoped to images the bridge fetches for its own self-call — it is never
applied to the caller's raw passthrough payload, consistent with the
opt-in-only mutation principle (Hard Rule #20).

#### Settings schema + migration

The new `modalityBridge*` keys are Zod-validated in `updateSettingsSchema`
(`src/shared/validation/settingsSchemas.ts`): `modalityBridgeVisionEnabled`,
`modalityBridgeVisionMode`, `modalityBridgeVisionModel`,
`modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`,
`modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`,
`modalityBridgeVisionMaxChars`, the `modalityBridgeCache*` trio, and the
`modalityBridgeAudio*` group used by the Audio Bridge. Migration
`141_modality_bridge_settings.sql` copies existing legacy
`visionBridge*` values to the matching new keys (idempotent, never overwrites
an operator-set `modalityBridge*` value); the legacy keys stay accepted as a
read fallback for one release cycle.

#### Transparency header + stats

Describe-transformed responses carry
`x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>`
(built by `buildModalityBridgeHeader()` in `modalityBridge/bridgeStats.ts`,
stamped by `withModalityBridgeHeader()` in `src/sse/handlers/chatHelpers.ts`).
Rerouted requests get **no** header — the payload was untouched and the model
swap is already visible in the response body's `model` field.

`GET /api/modality-bridge/stats` (management auth, same tier as
`GET /api/settings`) returns the in-memory per-modality counters
`{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs,
latencySamples, averageLatencyMs, lastUsedAt }` for `vision`, `audio`, and
`video`. `averageLatencyMs` uses `latencySamples`, not all attempts, as its
denominator; an operation without timing does not fabricate a zero-millisecond
sample. `bridged` remains the backward-compatible alias for successful
conversions; failed attempts do not increment it.
Counters reset on process restart by design
(telemetry, not accounting).

#### Dashboard configuration

ഡെഡിക്കേറ്റഡ് ഡാഷ്ബോർഡ് പേജ് ആണ്  
`/dashboard/settings/modality-bridge`. അതിന്റെ URL-ലഭ്യമായ `Vision`, `Audio`,  
മറ്റു `Video` ടാബുകൾ `tab` മൂല്യം മാറ്റുമ്പോൾ ക്വറി പാരാമീറ്ററുകൾ നിലനിര്‍ത്തുന്നു.  
Vision ടാബ് എനേബിൾമെന്റ്, മോഡ്, മോഡൽ തിരഞ്ഞെടുപ്പ് (സ്വയം ഡിഫോൾട്ട് ഉൾപ്പെടെ),  
ടാസ്‌ക്-അവെയർ പ്രോംപ്റ്റിംഗ്, ആധുനിക ടൈമൗട്ട്/ചിത്രം/വിവരണം-നീളം/കാഷ്  
പരിമിതികൾ, റൺടൈം കൗണ്ടറുകൾ, ഒരു ഗാർഡഡ് സാമ്പിൾ അഭ്യർത്ഥന എന്നിവ വെളിപ്പെടുത്തുന്നു.  
Audio ടാബ് കൂടി സജീവമാണ്: ഇത് എനേബിൾമെന്റ്, STT-മാത്രം മോഡൽ പിക്കർ  
Auto, ടൈമൗട്ട്/മാക്സ്-ക്ലിപ്പ് പരിധികൾ, ഓഡിയോ കൗണ്ടറുകൾ,  
മറ്റു `input_audio` സാമ്പിൾ ടെസ്റ്റ് എന്നിവ വെളിപ്പെടുത്തുന്നു. Video ടാബ് പ്രവർത്തനക്ഷമമാണ്:  
ഇത് FFmpeg/ffprobe റൺടൈം സ്ഥിതി റിപ്പോർട്ട് ചെയ്യുന്നു — probe പറക്കുമ്പോൾ  
അറിയപ്പെടാത്ത നാലു വ്യക്തമായ UI നിലകളിൽ ഒന്നാണ് (`unknown`, `restricted`,  
`unavailable`, അല്ലെങ്കിൽ `available` FFmpeg/ffprobe പതിപ്പുകൾ) —  
എനേബിൾ/മോഡൽ/ഫ്രെയിം/വീഡിയോ/ടൈമൗട്ട് പരിധികൾ നിലനിര്‍ത്തുന്നു,  
മോഡൽ പിക്കർ ദൃശ്യ-ശേഷിയുള്ള മോഡലുകൾക്കായി ഫിൽട്ടർ ചെയ്യുന്നു,  
മറ്റു വീഡിയോ കൗണ്ടറുകൾ വെളിപ്പെടുത്തുന്നു.

AI ക്രമീകരണങ്ങൾക്കുള്ള മുൻ Vision Bridge കാർഡ് പുതിയ പേജിലേക്ക്  
ഒരു അനുയോജ്യമായ ലിങ്കാണ്; ഇത് ഫോമിന്റെ രണ്ടാമത്തെ പകർപ്പ്  
കൈകാര്യം ചെയ്യുന്നില്ല. മീഡിയ പ്രൊവൈഡർ ഇമേജ്-ടു-ടെക്‌സ്‌റ്റ്  
മറ്റു സ്പീച്ച്-ടു-ടെക്‌സ്‌റ്റ് പ്രവൃത്തികളെ അനുബന്ധ മോഡാലിറ്റി  
ബ്രിഡ്ജ് ടാബുകളിലേക്ക് ബന്ധിപ്പിക്കുന്നു, നിലവിലുള്ള  
സ്പീച്ച്-ടു-ടെക്‌സ്‌റ്റ് പ്ലേഗ്രൗണ്ട് നീക്കം ചെയ്യാതെ.

**സ്വയം-ലൂപ്പ് പ്രവേശനം ബൈപാസ്:** വിവരണം വിളി OmniRoute-ന്റെ  
സ്വന്തം `/v1` സ്വയം-ലൂപ്പിലൂടെ റൂട്ടുചെയ്യുമ്പോൾ (അസാധാരണ  
പ്രൊവൈഡർ മോഡൽ), ഉപ-അഭ്യർത്ഥന `x-omniroute-admission-bypass: internal`  
അയയ്ക്കുന്നു, കൂടാതെ പരിഹരിച്ച സ്വയം-ലൂപ്പ് ക്രെഡൻഷ്യലുമായി  
അധികൃതമാക്കുന്നു — പ്രാദേശിക `sk_omniroute` സെന്റിനൽ പ്രാദേശിക  
മോഡിൽ, അല്ലെങ്കിൽ ഓപ്പറേറ്റർ-ക്രമീകരിച്ച `OMNIROUTE_API_KEY` /  
`ROUTER_API_KEY` env കീ (#1350) അതിനാൽ `REQUIRE_API_KEY=true`  
ഡിപ്ലോയ്മെന്റുകൾ വിവരണം വിളി നടത്താൻ കഴിയുന്നു.  
ബൈപാസ് ഈ കൃത്യമായ ക്രെഡൻഷ്യലുകൾക്കായാണ് മാത്രം  
ഗൗരവത്തോടെ സ്വീകരിക്കുന്നത്, അതിനാൽ ബാഹ്യ ക്ലയന്റുകൾ  
അഭ്യർത്ഥന ഒഴിവാക്കാൻ ഹെഡർ ഉപയോഗിക്കാൻ കഴിയുന്നില്ല.

പഴയ ഡിഫോൾട്ടുകൾ `src/shared/constants/visionBridgeDefaults.ts`-ൽ  
നിന്നു ജീവിക്കുന്നു; പുതിയ മോഡ്/ടാസ്‌ക്-അവെയർ/കാഷ്  
ഡിഫോൾട്ടുകളും ക്രമീകരണ പരിഹാരവും `src/shared/constants/modalityBridgeDefaults.ts`-ൽ  
നിന്നു ജീവിക്കുന്നു. ഗാർഡ്രെയിൽ ഒരു `deps` കൺസ്ട്രക്ടർ  
ഓപ്ഷൻ വെളിപ്പെടുത്തുന്നു, അതിനാൽ പരീക്ഷണങ്ങൾ വ്യാജ `getSettings`  
മറ്റു `callVisionModel` നടപ്പാക്കലുകൾ ഇഞ്ചെക്ട് ചെയ്യാൻ കഴിയും.

### Audio Bridge (`audioBridge.ts`) — Modality Bridge PR-3

ഓഡിയോ ഉൾക്കൊള്ളുന്ന ചാറ്റ് അഭ്യർത്ഥനകൾ ലക്ഷ്യത്തിലേക്ക് എത്തുന്നതിന് മുമ്പ്  
ഇത് തടയുന്നു, അത് ഓഡിയോ ഇൻപുട്ട് സ്വീകരിക്കാൻ അറിയപ്പെടുന്നില്ല.  
ഇത് ചാറ്റ് അഭ്യർത്ഥന വീണ്ടും റൂട്ടുചെയ്യുന്നില്ല: ഓഡിയോ ഭാഗങ്ങൾ  
നിലവിലുള്ള OpenAI-സമർത്ഥമായ മൾട്ടിപാർട്ട് എൻഡ്‌പോയിന്റ് വഴി  
ട്രാൻസ്ക്രൈബ് ചെയ്യുന്നു, തിരഞ്ഞെടുക്കപ്പെട്ട ചാറ്റ് മോഡൽ  
വിവരങ്ങൾക്കൊപ്പം തുടരുന്നു.

പ്രവാഹം:

1. `getResolvedModelCapabilities()` വഴി `supportsAudio` പരിഹരിക്കുക.  
   വ്യക്തമായ പ്രൊവൈഡർ-റെജിസ്ട്രി മെറ്റാഡാറ്റ വിജയിക്കുന്നു,  
   പിന്നീട് സ്റ്റാറ്റിക് മോഡൽ മെറ്റാഡാറ്റ, പിന്നീട്  
   സിങ്ക് ചെയ്ത `modalities_input`. `audio` ഇല്ലാത്ത  
   പ്രഖ്യാപിത ഇൻപുട്ട് പട്ടിക `false` ആണ്;  
   യാതൊരു ശേഷി തെളിവും `null` ആയി തുടരുന്നു.  
   `false`യും `null`യും സംരക്ഷിത ബ്രിഡ്ജ് സജീവമാക്കുന്നു,  
   എന്നാൽ `true` അത് ഒഴിവാക്കുന്നു.
2. `modalityBridgeAudio*` ക്രമീകരണങ്ങൾ പരിഹരിക്കുക  
   കൂടാതെ പങ്കുവെച്ച `detectMediaParts()`  
   ഡിറ്റക്ടർ വഴി ഓരോ സന്ദേശത്തിൽ നിന്നും  
   സ്പ്ലൈസുചെയ്യാവുന്ന ടോപ്പ്-ലവൽ ഓഡിയോ ഭാഗങ്ങൾ  
   എടുക്കുക. പിന്തുണയുള്ള വയർ രൂപങ്ങൾ  
   OpenAI `input_audio`, `audio_url`,  
   കൂടാതെ `source.media_type: "audio/*"` ആണ്.  
   റൂട്ടിംഗിന്_nested_ ഓഡിയോ കണ്ടെത്തുന്നു,  
   എന്നാൽ സ്പ്ലൈസ് പാത വഴി നീക്കം ചെയ്യപ്പെടുന്നില്ല.  
   ജോലി `modalityBridgeAudioMaxClips`-ൽ  
   പരിമിതമാണ്; പിന്നീട് ഭാഗങ്ങൾ  
   മാറ്റമില്ലാതെ തുടരുന്നു.
3. ഒരു ക്രമീകരിച്ച `provider/model`  
   മാന്യമായ `selectAudioBridgeModel()`  
   `AUDIO_TRANSCRIPTION_PROVIDERS`-ൽ  
   സ്ഥിരമായ കാറ്റലോഗ് ക്രമത്തിൽ നടക്കാൻ  
   അനുവദിക്കുക, ഉപയോഗിക്കാൻ കഴിയുന്ന  
   സജീവ പ്രൊവൈഡർ ക്രെഡൻഷ്യൽ ഉള്ള  
   ആദ്യ മോഡൽ തിരഞ്ഞെടുക്കുക.
4. `callAudioTranscription()` base64/data-URI  
   ഓഡിയോയെ ഒരു മൾട്ടിപാർട്ട് `file`-ലേക്ക്  
   മാറ്റുന്നു, അല്ലെങ്കിൽ ഒരു ദൂരസ്ഥ `audio_url`  
   പൊതുവായ ഔട്ട്‌ബൗണ്ട് ഗാർഡ് വഴി  
   DNS പിന്നിൽനിന്നും 25 MB പരിധിയോടെ  
   ഡൗൺലോഡ് ചെയ്യുന്നു. തുടർന്ന്,  
   ഫയലും തിരഞ്ഞെടുക്കപ്പെട്ട മോഡലും  
   പ്രാദേശിക `/v1/audio/transcriptions`  
   സ്വയം-ലൂപ്പിലേക്ക് POST ചെയ്യുന്നു,  
   `resolveSelfLoopBearer()`-ൽ  
   അഥവാ അധികൃതമാക്കുന്നു. നിലവിലുള്ള  
   ട്രാൻസ്ക്രിപ്ഷൻ റൂട്ടിൽ സാധാരണ  
   ക്രെഡൻഷ്യൽ ലുക്കപ്പ്, കൂൾഡൗൺ/റേറ്റ്-ലിമിറ്റ്  
   കൈകാര്യം ചെയ്യൽ, പ്രൊവൈഡർ ഡിസ്‌പാച്ച് എന്നിവ  
   നടത്തുന്നു.
5. വിജയകരമായ വിളികൾ അവരുടെ ഭാഗങ്ങൾ  
   `[Audio N]: <transcript>`-ൽ  
   മാറ്റുന്നു. വിളികൾ `Promise.allSettled`-ൽ  
   പ്രവർത്തിക്കുന്നു: ഒരു വ്യക്തിഗത പരാജയം  
   ആസ്വദിക്കുന്ന ഓഡിയോ ഭാഗത്തെ  
   നിലനിര്‍ത്തുന്നു (#4012 കരാർ).  
   എല്ലാ വിളികളും പരാജയപ്പെടുകയാണെങ്കിൽ  
   ലക്ഷ്യം `supportsAudio === false`  
   എന്ന് തെളിയിച്ചാൽ, ഭാഗങ്ങൾ

### Video Bridge (`videoBridge.ts`, `videoBridgePipeline.ts`)

Intercepts top-level video parts in Chat Completions `messages` and Responses
API `input` before a target without known native video support is called.
Supported shapes are `input_video`, `video_url`, `video_source`, HTTPS URLs,
and `data:video/*;base64,...` data URIs. Plain filenames in text are not treated
as video.

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) owns request traversal, the
capability/policy check, per-request aggregation, and the response payload.
Per-video work — acquisition, the whole-result cache, describing a frame
sequence (which fuses any caller-declared audio transcript), and per-attempt
metrics/abort/cleanup — is hidden behind `processVideoPart` in
`videoBridgePipeline.ts`, called once per video part inside `preCall`'s loop.
That module also defines the explicit port boundaries `VideoMediaBrokerPort`
(acquiring bytes and extracting sampled frames), `VideoAudioTranscriptionPort`
(fusing a caller-declared audio transcript with the sampled captions), and
`VideoDrilldownPort` (the legacy raw-store shape). Production STT and frame retention
are composed around the describing port through `createVideoSttAdapter` and
`createVideoDrilldownAdapter`; the latter uses the shared opaque-handle lifecycle.

The public `/v1` request path never imports or invokes a subprocess. Remote
videos are downloaded under a 50 MiB bound; inline base64 videos have a
conservative 36 MiB decoded per-video cap so the model/messages/framing envelope
can remain inside the public JSON request admission limit of 50 MiB. Inline
length and decoded-size estimates are checked before allocation. HTTPS is
required on the initial remote URL and every redirect, using the existing
public-only outbound guard with DNS pinning. The bytes then cross the exact internal
`POST /api/modality-bridge/video/extract` broker boundary. That route is both
`LOCAL_ONLY` and `SPAWN_CAPABLE`, accepts only a per-process authenticated,
trusted-loopback request, and never accepts a URL, filesystem path, executable,
or argument list. The API body-size pipeline and the handler's incremental body
reader independently enforce a 50 MiB broker input cap. Its bounded queue runs
one extraction at a time, allows four pending jobs, and caps pending input at
100 MiB.

Inside the broker, `ffprobe` reads a private local file; the fixed format
allowlist excludes playlist and manifest formats. For allowed MOV-family
containers, external MOV data references remain disabled by default, and the
fixed command does not opt in to them. Both `ffprobe` and `ffmpeg` use the
`file`-only protocol whitelist, one thread, fixed argument arrays, no shell,
and executables resolved from `PATH`. Attached-picture cover streams are not
playable candidates. All playable streams must satisfy the limits, and an
explicit default stream is preferred before the deterministic lowest-index
fallback. Videos are limited to 600 seconds, 8,192 pixels per dimension, and
33,554,432 source pixels. FFmpeg samples 1–16 midpoint JPEG frames, scales down
the long edge to at most 1,024 pixels without upscaling smaller inputs, and
never receives a URL. Sampling is `uniform` by default. The optional
`scene_aware` and experimental `segment_aware` policies perform one additional
fixed FFmpeg pass over the already validated local stream, select bounded
`showinfo` scene timestamps, and fall back deterministically to the same
uniform midpoints on detector failure, timeout, malformed output, or an empty
candidate set. Segment-aware mode allocates midpoint samples proportionally to
the validated scene intervals; segment-aware evidence and fallback behavior are
detailed below. The hard 16-frame cap is
applied after selection in every policy. When a scene-aware request has only a
one-frame budget, it uses the uniform midpoint of the active full-video or focus
window and reports `policyEffective: uniform`: a single selected scene frame
cannot preserve both temporal ends. A caller may optionally provide a
finite focus window (`start`/`end` seconds); bounds are clamped to the media
duration, reversed or non-finite windows are rejected, and all sampling
policies are performed only inside the normalized interval. The resulting
window is included in sampling metadata and in the untrusted description
prefix so downstream models can distinguish a focused excerpt from the full
timeline.

Semantic caption focus is a separate, explicit setting. The default `full`
analysis mode preserves the existing frame prompt and never forwards request
text to the caption model. In `focused` mode, the bridge reads only the latest
non-empty user-authored `text`/`input_text` from the same Chat or Responses
container, normalizes it to NFC, collapses control characters and whitespace,
and limits it to 500 Unicode code points. An empty result falls back to the
exact `full` prompt. A usable hint is serialized as JSON in a dedicated
untrusted-user-context block and may only prioritize observable details; it
cannot override the separate warning against following instructions visible
or audible in the media. Textual focus never infers `start`/`end` or changes
the temporal sampler.

#### FU-07 ഘടനാപരമായ സെഗ്മെന്റ് തെളിവുകൾ

`segment_aware` uses one bounded pre-analysis pass over the already validated
local video stream. The fixed filter chain first scales to at most 320 pixels
wide, detects scene changes and frozen intervals, then samples at 1 frame per
second for blur, average luma, and spatial/temporal information. The pass is
limited to 600 structural samples, one FFmpeg/filter thread, the same
`file`-only protocol and container allowlists, a 1 MiB process-output bound,
and at most 30 seconds inside the broker's shared abort/deadline. It never
accepts a command, filter, path, or URL from the request.

സംരചനാത്മക മൂല്യങ്ങൾ നിശ്ചിതമായ സാമ്പിളിംഗ് തെളിവുകളാണ്, അർത്ഥമാക്കുന്ന വീഡിയോ മനസ്സിലാക്കലല്ല. ഇവ വിഷയങ്ങൾ, പ്രവർത്തനങ്ങൾ, തലക്കെട്ടുകൾ, സംസാരണം, അല്ലെങ്കിൽ ഉപയോക്തൃ ഉദ്ദേശ്യം എന്നിവയെ സൂചിപ്പിക്കുന്നില്ല. ദൃശ്യവും ഫ്രീസ് ബൗണ്ടറികളും സെഗ്മെന്റുകൾ രൂപീകരിക്കുന്നു; ഫ്രീസ് കവർ, ബ്ലർ, എക്സ്പോഷർ, സ്ഥിതിവിവരം, കാലിക മാറ്റം എന്നിവ നിലവിലുള്ള 1–16 ഫ്രെയിം ബജറ്റ് എങ്ങനെ വിനിയോഗിക്കപ്പെടുന്നുവെന്ന് മാത്രം ബാധിക്കുന്നു. ഒരു പൂർണ്ണമായ ഫ്രീസുചെയ്ത സെഗ്മെന്റ് ഒരു ഫ്രെയിമിൽ പരിമിതമാണ്, എന്നാൽ ഫ്രീസുചെയ്തിട്ടില്ലാത്ത സെഗ്മെന്റുകൾ ശേഷിക്കുന്ന ബജറ്റിനായി മത്സരിക്കുന്നു. ബൗണ്ടറികൾ ഫ്രെയിമുകളെക്കാൾ കൂടുതലായാൽ, ഏകീകൃത ടൈംലൈൻ കവർജ്ജ് നിലനിൽക്കുന്നു, അതിനാൽ വേഗത്തിലുള്ള പ്രാരംഭ കട്ടുകൾ ഒരു ദീർഘമായ ട്രെയിലിംഗ് സെഗ്മെന്റ് മറയ്ക്കാൻ കഴിയില്ല. ഒരു ഫ്രീസ് ബൗണ്ടറിയുടെ 1-സെക്കൻഡ് വിശകലന പരിധിയിൽ ദൃശ്യ ബൗണ്ടറികൾ സംയോജിപ്പിക്കുന്നു.

കുറഞ്ഞ ഫിൽട്ടറുകൾ, തെറ്റായ/ശൂന്യമായ തെളിവുകൾ, ഒരു ഡിറ്റക്ടർ പിശക്, അല്ലെങ്കിൽ ബൗണ്ടഡ് പ്രീ-വിശകലന ടൈംഔട്ട് കൃത്യമായ ഏകീകൃത മധ്യനില നയം തുറക്കാൻ പരാജയപ്പെടുന്നു. ഒരു കോളർ അബോർട്ട് അല്ലെങ്കിൽ ബ്രോക്കർ ഡെഡ്‌ലൈൻ തുറക്കാൻ പരാജയപ്പെടുന്നില്ല: ഇത് ഇൻ-ഫ്ലൈറ്റ് സബ്‌പ്രോസസ്സ് അവസാനിപ്പിക്കുന്നു, പിന്നീട് ഫ്രെയിം എക്സ്ട്രാക്ഷൻ തടയുന്നു, കൂടാതെ സ്വകാര്യ താൽക്കാലിക മരച്ചീനി `finally`-ൽ നീക്കം ചെയ്യുന്നു.

`scripts/perf/video-bridge-fu07-eval.ts` പോസ്റ്റ്-ഡെഡ്യൂപ്പ് തലക്കെട്ട്-കാൾ സംരക്ഷണങ്ങൾ, കനത്ത-ചലന ബജറ്റ് വിനിയോഗം, ബ്ലർ/എക്സ്പോഷർ/SI-TI തെളിവുകൾ, ദീർഘമായ താലികയുള്ള വേഗത്തിലുള്ള കട്ടുകൾ, കൂടാതെ ക്രമാത്മക-ഫേഡ് തെറ്റായ പോസിറ്റീവുകൾക്കായി നിശ്ചിതമായ യാഥാർത്ഥ്യ FFmpeg ഫിക്ചറുകൾ സൃഷ്ടിക്കുന്നു. ഇത് പ്രീ-വിശകലന വാൾ ടൈം രേഖപ്പെടുത്തുന്നു, കൂടാതെ `/usr/bin/time` ലഭ്യമെങ്കിൽ, കുട്ടി CPUയും പീക്ക് RSS-യും രേഖപ്പെടുത്തുന്നു. അതിന്റെ ഗുണനിലവാര പരിശോധനകൾ ഘടനാപരമായ ഓറക്കിളുകളാണ് മാത്രം. യാഥാർത്ഥ്യ തലക്കെട്ട്-മോഡൽ ഗുണനിലവാരം `HOLD` ആയി തുടരുന്നു, കാരണം ഈ ഹാർനെസിന് അധികാരിതമായ എന്റ്പോയിന്റ് അല്ലെങ്കിൽ ഫ്രീസുചെയ്ത ജഡ്ജ് ഇല്ല. സാമ്പത്തിക സംരക്ഷണവും `HOLD` ആയി തുടരുന്നു, എങ്കിൽ `--caption-cost-per-call-usd` ഒരു വ്യക്തമായ പോസിറ്റീവ് പെർ-കാൾ അളവുകൾ നൽകുന്നില്ല; സ്ക്രിപ്റ്റ് ഒരിക്കലും ഫാബ്രിക്കേറ്റ് ചെയ്യുകയില്ല.

പ്രതിയൊരു ഫ്രെയിം 4 MiB-ൽ പരിമിതമാണ്, എല്ലാ റോ ഫ്രെയിമുകൾ ചേർന്ന് 23 MiB-ലും, സീരിയലൈസ്ഡ് ബ്രോക്കർ പ്രതികരണം 32 MiB-ലും പരിമിതമാണ്. ഒരു സ്വകാര്യ താൽക്കാലിക ഡയറക്ടറി `finally`-ൽ നീക്കം ചെയ്യുന്നു. OmniRoute FFmpeg-നെ ബണ്ടിൽ ചെയ്യുകയില്ല, കൂടാതെ ഒരു കസ്റ്റം എക്സിക്യൂട്ടബിൾ പാത്ത് സ്വീകരിക്കുന്നില്ല. തലക്കെട്ട് നൽകുന്നതിന് മുമ്പ്, ബ്രിഡ്ജ് ഒരു സംരക്ഷിത ദൃശ്യ ഡെഡ്യൂപ്ലിക്കേഷൻ പാസ് പ്രയോഗിക്കുന്നു: ഓരോ JPEG-യും 16×16 ഗ്രേസ്കെയിൽ ബഫറിലേക്ക് കുറയ്ക്കുന്നു, കൂടാതെ ഇത് നിലനിൽക്കുന്ന അവസാന ഫ്രെയിമുമായി മാത്രം താരതമ്യം ചെയ്യുന്നു. ഒരു ഫ്രെയിമിന് മുകളിൽ ആവശ്യമായ തലക്കെട്ട് ബജറ്റിനായി, എക്സ്ട്രാക്ഷൻ 16 ഫ്രെയിമുകളിൽ കൂടുതൽ അല്ലാതെ, ആ ബജറ്റിന്റെ ഇരട്ടിയോളം ബൗണ്ടഡ് കാൻഡിഡേറ്റ് പൂൾ നൽകുന്നു. ഡെഡ്യൂപ്ലിക്കേഷന്റെ ശേഷം മാത്രം ആവശ്യമായ ക്യാപ് പ്രയോഗിക്കുന്നു, ആദ്യവും അന്തിമവും തിരഞ്ഞെടുക്കപ്പെട്ട കാൻഡിഡേറ്റുകൾ അവസാന തിന്മയിൽ സംരക്ഷിക്കുന്നു, ബജറ്റ് കുറഞ്ഞത് രണ്ട് ആയിരിക്കുമ്പോൾ. പതിപ്പായ `grayscale-16x16-mean-cells-v2` നയം, ശരാശരി ലൂമ ഡെൽറ്റയും 0.05-ൽ കുറഞ്ഞത് നോർമലൈസ്ഡ് ഡെൽറ്റുള്ള തമ്പ്‌നെയിൽ സെല്ലുകളുടെ അനുപാതവും ഉപയോഗിക്കുന്നു. ഡ്യൂപ്ലിക്കേറ്റ് ത്രെഷോൾഡ് 0.04 എന്ന സ്ഥിരമായ മൂല്യമാണ്, പ്രവചനീയതക്കായി തിരഞ്ഞെടുക്കപ്പെട്ടത്, റൺടൈം സജ്ജീകരണമായി വെളിപ്പെടുത്തിയിട്ടില്ല. ഈ രണ്ടാം ഉയർന്ന-കോൺട്രാസ്റ്റ് സിഗ്നൽ ചെറിയ ചലനങ്ങളും ദൃശ്യ-ലേഖന മാറ്റങ്ങളും സംരക്ഷിക്കുന്നു, mean-only താരതമ്യം മറയ്ക്കാൻ കഴിയും. താരതമ്യക്കാരൻ അല്ലെങ്കിൽ ഡികോഡർ പിശകുകൾ തുറക്കാൻ പരാജയപ്പെടുന്നു, കവർജ്ജ് നിലനിൽക്കുന്നു. ഔട്ട്പുട്ട് മെറ്റാഡാറ്റ എക്സ്ട്രാക്റ്റ് ചെയ്ത കാൻഡിഡേറ്റുകൾ, വിജയകരമായി ഉപയോഗിച്ച ഫ്രെയിമുകൾ, കൂടാതെ വീക്ഷണ ഡ്യൂപ്ലിക്കേറ്റുകൾ ഒഴിവാക്കുന്നു.

ഒരു വ്യക്തമായി അടയാളപ്പെടുത്തിയ വീഡിയോ ഭാഗം timestamped കോൺടാക്റ്റ് ഷീറ്റ് ആവശ്യപ്പെടാം. ബ്രിഡ്ജ് പരമാവധി 4-കോളം, 16-ഫ്രെയിം JPEG ഗ്രിഡ് നിർമ്മിക്കുന്നു. ഓരോ 512-പിക്സൽ സെല്ലും അതിന്റെ ഉറവിട timestamp-നെ ഉയർന്ന-കോൺട്രാസ്റ്റ് താഴ്ന്ന ബാന്റിൽ കത്തിക്കുന്നു, അതേ timestamps താഴെയുള്ള അസോസിയേഷൻക്കും ഓഡിറ്റിനും ടെക്സ്റ്റ് മെറ്റാഡാറ്റയിൽ നിലനിൽക്കുന്നു. സമ്പൂർണ്ണ JPEG 32 MiB-ൽ പരിമിതമാണ്. `sharp` ഗ്രിഡ് ഡികോഡ് ചെയ്യാൻ അല്ലെങ്കിൽ രൂപകൽപ്പന ചെയ്യാൻ കഴിയുന്നില്ലെങ്കിൽ, ബ്രിഡ്ജ് വ്യക്തിഗത JPEG ഫ്രെയിമുകളിലേക്ക് വീണ്ടെടുക്കുന്നു; ഒരു ക്ലയന്റ് അബോർട്ട് ഷീറ്റ് പ്രവർത്തനത്തിലൂടെ ഇപ്പോഴും വ്യാപിക്കുന്നു.

പ്രമോഷൻ തെളിവുകൾ സിന്തറ്റിക് ഘടനാ മൈക്രോബഞ്ച്മാർക്കിൽ നിന്ന്故意മായി വേർതിരിച്ചിരിക്കുന്നു. `scripts/perf/video-bridge-contact-sheet-eval.ts` യാഥാർത്ഥ്യ OpenAI-സഹിത ദൃശ്യ മോഡലുകൾക്കായി ഒരു സ്കീമാ-വർഷം A/B ഹാർനെസ് നിർവചിക്കുന്നു. ഇത് പ്രൊവൈഡർ-റിപ്പോർട്ടുചെയ്ത ടോക്കണുകൾ, എണ്ട്-ടു-എണ്ട് വാൾ ലാറ്റൻസി (ഷീറ്റ് ഘടന ഉൾപ്പെടെ), മോഡൽ-കാൾ എണ്ണം, കൂടാതെ മാനിഫസ്റ്റ്-നിർവചിതമായ വസ്തുത സംരക്ഷണം അളക്കുന്നു. റോ മോഡൽ പ്രതികരണങ്ങൾ റിപ്പോർട്ടിൽ എഴുതുന്നില്ല; SHA-256 ഡിജസ്റ്റുകൾ മാത്രമാണ് നിലനിൽക്കുന്നത്, കൂടാതെ പൊരുത്തമുള്ള വസ്തുത ID-കൾ മാത്രം സൂക്ഷിക്കുന്നു. ഹാർനെസ് നെറ്റ്‌വർക്കിലോ പെയ്ഡ് മോഡൽ കോളിലോ പ്രവേശിക്കുകയില്ല, എങ്കിൽ `--execute-real` പാസ്സ് ചെയ്യുന്നു, കൂടാതെ `--model`, `OMNIROUTE_BASE_URL`, `OMNIROUTE_API_KEY` എന്നിവ ക്രമീകരിച്ചിരിക്കണം. ആ വ്യക്തമായ യാഥാർത്ഥ്യ പ്രവർത്തനം ഇല്ലാതെ, അതിന്റെ മെഷീൻ-വായനയോഗ്യമായ വിധി `HOLD` ആയി തുടരുന്നു; സിന്തറ്റിക് പേലോഡ്/കാൾ-കൗണ്ട് അളവുകൾ മാത്രം പ്രമോഷൻ തെളിവുകൾ അല്ല.

വേർതിരിച്ച `scripts/perf/video-bridge-promotion-eval.ts` FU-07 അല്ലെങ്കിൽ FU-09 നിരീക്ഷണങ്ങൾ ഉപയോഗിക്കുന്നു. പ്രമോഷൻ പ്രവേശനം എട്ട് സിന്തറ്റിക് സീനാരിയോ തരം മുഴുവൻ ആവശ്യമാണ്, കൂടാതെ ഒരു ശുദ്ധമായ യാഥാർത്ഥ്യ ക്ലിപ്പ്, ഓരോ വേഷത്തിനും കേസിനും കുറഞ്ഞത് മൂന്ന് അളക്കപ്പെട്ട ആവർത്തനങ്ങൾ, എല്ലാ പത്ത് പ്രഖ്യാപിത മെട്രിക്‌സ്, ഫ്രീസുചെയ്ത മീഡിയ/പ്രോംപ്റ്റ്/പ്രതീക്ഷിച്ച-വസ്തു/സജ്ജീകരണ ഡിജസ്റ്റുകൾ, ഏകീകൃത നിരീക്ഷണ ID-കൾ, കൂടാതെ സ്ഥിരീകരിച്ച വിത്ത് A/B ക്രമം. എക്സിക്യൂഷൻ റിസീറ്റ് കോർപ്പസ് ഡിജസ്റ്റ്, കൃത്യമായ കാൻഡിഡേറ്റ് SHA, മോഡൽ പരിഷ്കരണം എന്നിവ ബന്ധിപ്പിക്കുന്നു. കുറവായ അല്ലെങ്കിൽ അസാധുവായ അളവുകൾ `HOLD` ആയി തുടരുന്നു, 30 സെക്കൻഡിന് മുകളിൽ CPU, 512 MiB-ൽ മുകളിൽ പീക്ക് RSS അല്ലെങ്കിൽ 30 സെക്കൻഡിന് മുകളിൽ പ്രീ-വിശകലനം ഉൾപ്പെടുന്നു. ഇവ തെളിവ്-പ്രവേശന ക്യാപ്‌സാണ്, പുതിയ റൺടൈം RSS നടപ്പാക്കൽ ഉറപ്പില്ല.

FU-07 കുറഞ്ഞത് 98% ഗുണനിലവാര സംരക്ഷണം ആവശ്യമാണ്, p95 ലാറ്റൻസി അടിസ്ഥാനത്തിൽ 1.2x-ൽ കൂടുതൽ അല്ല, കൂടാതെ സമാനമായ ശരാശരി തലക്കെട്ട് കോളുകളിൽ 0.05-ന്റെ ആബ്സോല്യൂട്ട് കേസ്-ബാലൻസഡ് ശരാശരി റിക്കാൾ മെച്ചപ്പെടുത്തലോ, അല്ലെങ്കിൽ കുറഞ്ഞത് 10% കുറവായ ശരാശരി പോസ്റ്റ്-ഡെഡ്യൂപ്പ് തലക്കെട്ട് കോളുകൾ. FU-09 കുറഞ്ഞത് 0.85 ഗുണനിലവാരം, 95% സംരക്ഷണം, 20% p95 ലാറ്റൻസി കുറവ്, 10% ടോക്കൺ കുറവ് ആവശ്യമാണ്. ക്രിറ്റിക്കൽ-വസ്തു നഷ്ടം, ഇൻജക്ഷൻ അനുസരണം അല്ലെങ്കിൽ കുറവായ ഉപയോഗം പ്രമോഷനെ തടയുന്നു. ഒരു എക്സിക്യൂഷൻ ഒന്നും പ്രമോട്ട് ചെയ്യാൻ കഴിയില്ല: `--previous-report` സമാന നയം/മോഡൽ പരിഷ്കരണം/കാൻഡിഡേറ്റ്/കോർപ്പസ് എന്നിവയുടെ രണ്ട് വ്യത്യസ്ത, ഒത്തുചേർന്ന, തുടർച്ചയായ യോഗ്യതയുള്ള എക്സിക്യൂഷനുകൾ സ്ഥിരീകരിക്കുന്നു. ഒരു സാമ്പിളിംഗ് പരീക്ഷണം കോൺടാക്റ്റ്-ഷീറ്റ് പരീക്ഷണം സ്ഥിരീകരിക്കാൻ കഴിയില്ല.

കോളക്ടർമാർ മറുപടികൾ മെമ്മറിയിൽ സ്കോർ ചെയ്യണം, `responseDigest` കൂടാതെ മെട്രിക്‌സ്, നിരീക്ഷണ ബൈൻഡിംഗുകൾ സംരക്ഷിക്കണം, മറുപടി ടെക്സ്റ്റ് ഒരിക്കലും ഇല്ല. ഉപഭോക്താവ് പഴയ കച്ചവട നിരീക്ഷണങ്ങൾ വായിക്കുന്നു, എന്നാൽ ആ ടെക്സ്റ്റ് തന്റെ റിപ്പോർട്ടുകളിൽ ഒരിക്കലും പകർന്നെടുക്കുന്നില്ല. ഓരോ നിരീക്ഷണത്തിനും `responseDigest` അല്ലെങ്കിൽ `rawResponseText` എന്നതിൽ ഒരൊറ്റത് മാത്രം സ്വീകരിക്കപ്പെടുന്നു. പതിപ്പായ അനുവദനീയ പട്ടിക ശൂന്യമായിരിക്കുകയാണ്, മാറ്റം വരാത്ത `hold` ഡിഫോൾട്ടുമായി. യോഗ്യമായ ഒരു എൻട്രിക്ക് അതിന്റെ തെളിവിന്റെ റഫറൻസ്, നയം, മോഡൽ പരിഷ്കരണം, കൃത്യമായ സ്ഥാനാർത്ഥി SHA, മാനിഫസ്റ്റ് ഡിജസ്റ്റ്, രണ്ട് വ്യത്യസ്ത റൺ ഐഡികൾ ആവശ്യമാണ്; തർക്കിക്കുന്ന സാഹചര്യങ്ങൾ നിരസിക്കപ്പെടുന്നു. ഈ മെറ്റാഡാറ്റ ഒരു ഓഡിറ്റ് കരാറാണ്, ഒരു റഫറൻസുചെയ്ത ഫയൽ യഥാർത്ഥ അളവുകൾ അടങ്ങിയിരിക്കുന്നതിന്റെ തെളിവല്ല. ഏതെങ്കിലും എൻട്രി ചേർക്കുന്നതിന് മുമ്പ് യഥാർത്ഥ റസീറ്റ് പരിശോധിക്കുക. മാനേജ്മെന്റ് സ്റ്റാറ്റ്സ് എൻഡ്പോയിന്റ്, വീഡിയോ ഡാഷ്ബോർഡ് സംരക്ഷിതമായ തയ്യാറെടുപ്പുകൾ വെളിപ്പെടുത്തുന്നു. ഒരു ക്രമീകരിച്ച മോഡൽ അലൈസ് മാത്രം അതിന്റെ പരിഷ്കരണം അല്ലെങ്കിൽ പ്രവർത്തനത്തിലെ സ്ഥാനാർത്ഥി SHA സ്ഥാപിക്കുന്നില്ല, അതിനാൽ നിലവിലെ ഡാഷ്ബോർഡ് `HOLD` റിപ്പോർട്ട് ചെയ്യുന്നു, മറ്റൊരു പ്രവർത്തന സാഹചര്യത്തിൽ നിന്ന് യോഗ്യത പുനരുപയോഗിക്കുന്നതിന് പകരം. വ്യക്തമായ പരീക്ഷണ തിരഞ്ഞെടുപ്പ് പ്രമോഷനിൽ നിന്ന് വേർതിരിച്ചിരിക്കുന്നു; യാതൊരു ഡിഫോൾട്ടും സ്വയം മാറ്റപ്പെടുന്നില്ല.

കോളർമാർക്ക് ഇതിനകം പൊരുത്തപ്പെടുന്ന ടെക്സ്റ്റ് ഉള്ള supported video ഭാഗത്തേക്ക് ഒരു ഓപ്ഷണൽ `transcript.cues` അറേ ചേർക്കാൻ കഴിയും. ഓരോ ക്യൂയും `text`, പ്രോബഡ് ദൈർഘ്യത്തിനുള്ള ഒരു പരിമിതമായ `start`/`end` ഇടവേള, ഒരു വൈറ്റ്‌ലിസ്റ്റ് ചെയ്ത `source` (`client`, `embedded`, അല്ലെങ്കിൽ `audio-bridge`) എന്നിവ കൈവശം വഹിക്കണം; `confidence` ഡിഫോൾട്ടായി `1` ആണ്, `0`നും `1`നും ഇടയിൽ നിലനിൽക്കണം. കൃത്യമായ ഡുപ്ലിക്കേറ്റ് ക്യൂകൾ ചുരുക്കപ്പെടുന്നു. ഒമ്നി റൂട്ടിൽ ഈ മെറ്റാഡാറ്റയിൽ നിന്ന് ട്രാൻസ്ക്രിപ്ഷൻ ആരംഭിക്കുകയില്ല: സ്ഥിരീകരിച്ച ക്യൂകൾ ഉറവിടം, ആത്മവിശ്വാസം, ഇടവേള എന്നിവയോടെ വിവരണത്തിലുള്ള ഫലത്തിലേക്ക് പകർന്നെടുക്കുന്നു, ഫ്രെയിം ക്യാപ്ഷനുകൾക്കൊപ്പം വിശ്വസിക്കാത്ത നിരീക്ഷണങ്ങളായി അവതരിപ്പിക്കുന്നു. അസാധുവായ, പരിധി പുറത്തുള്ള, അല്ലെങ്കിൽ ഉത്ഭവമില്ലാത്ത ടെക്സ്റ്റ് ക്യാപ്ഷൻ സ്ട്രീമിൽ മിശ്രിതമാക്കുന്നതിന് പകരം നിരസിക്കപ്പെടുന്നു. രണ്ട് അഭ്യർത്ഥന-ബോഡി ട്രാൻസ്ക്രിപ്റ്റ് ചാനലുകൾ നൽകിയ ഉത്ഭവത്തെ `client` എന്നതിലേക്ക് സാധാരണവത്കരിക്കുന്നു, സ്വയം-അവകാശപ്പെട്ട `embedded` അല്ലെങ്കിൽ `audio-bridge` ലേബലുകൾ ഉൾപ്പെടുന്നു. വിശ്വസനീയമായ ലേബലുകൾ കോഡ്-മാത്രമായ `trustedSource` വാദം വഴി ഒരു സർവർ-ഉടമയുള്ള അഡാപ്റ്റർ മാത്രമേ നിയോഗിക്കാവൂ; ഒരു അഭ്യർത്ഥന JSON ഫീൽഡ് ആ വാദത്തിലേക്ക് എത്താൻ കഴിയില്ല. ട്രാൻസ്ക്രിപ്റ്റ് ടെക്സ്റ്റ് വിശ്വസിക്കാത്ത മീഡിയ-ഉത്ഭവ ഉള്ളടക്കമാണ്, അതിന്റെ ഉത്ഭവം എത്രമാത്രം ആയാലും, അതു ഒരിക്കലും അധികാരത്തെ നിശ്ചയിക്കരുത്.

ഒരു പുരോഗമന കോളർ സമാനമായ വീഡിയോയ്ക്ക് `audioTranscript` ട്രാക്ക് നൽകാൻ കഴിയും; ഇത് സർവർ ട്രാൻസ്ക്രിപ്ഷന്റെ തെളിവല്ല, ക്ലയന്റ്-വിതരണമായ ടെക്സ്റ്റ് ആയി പരിഗണിക്കുന്നു. ഫ്യൂഷൻ സീം ഒരു ഡെഡ്‌ലൈൻ, അഭ്യർത്ഥന സിഗ്നലിന്റെ കീഴിൽ ദൃശ്യവും ശബ്ദവും നിരീക്ഷണങ്ങൾ നടത്തുന്നു, അവയെ ഒരു പൊതുവായ ടൈംലൈൻയിൽ ഓർഡർ ചെയ്യുന്നു, കൃത്യമായ ഡുപ്ലിക്കേറ്റുകൾ ചുരുക്കുന്നു, ഒരു ഭാഗം മാത്രം വിജയിച്ചാൽ ഭാഗിക ഫലം റിപ്പോർട്ട് ചെയ്യുന്നു. അസാധുവായ `audioTranscript` ആ ഭാഗിക ഫലത്തിലേക്ക് താഴ്ന്നു — ദൃശ്യ വിവരണം നിലനിൽക്കുന്നു, ശബ്ദ ശാഖ ഒരു ശുദ്ധീകരിച്ച പരാജയ കോഡ് രേഖപ്പെടുത്തുന്നു — മുഴുവൻ വീഡിയോ പരാജയപ്പെടുന്നതിന് പകരം. ഓരോ ശാഖയുടെ ലഭ്യത, ഭാഗിക പതാക, ശുദ്ധീകരിച്ച പരാജയ കോഡുകൾ എന്നിവ വിവരണത്തിലുള്ള ഫലത്തിൽ, ഗാർഡ്‌റെയിൽ മെറ്റാഡാറ്റയിൽ (`audioFusionRuns`/`audioFusionPartials`/`audioFusionFailureCodes`), ഫല-കാഷ് മെറ്റാഡാറ്റയിൽ, ബ്രിഡ്ജ് ഫ്യൂഷൻ കൗണ്ടറുകളിൽ സംരക്ഷിക്കപ്പെടുന്നു. ഡിഫോൾട്ട് വീഡിയോ ബ്രിഡ്ജ് പാത സംസാരത്തെ എഴുത്തിലേക്ക് മാറ്റുകയോ രണ്ടാമത്തെ മീഡിയ പകർപ്പ് ഡൗൺലോഡ് ചെയ്യുകയോ ചെയ്യുകയില്ല; ആ വ്യക്തമായ ട്രാക്ക് ഇല്ലാതെ, അത് വീഡിയോ മാത്രം ആയി തുടരുന്നു.

**ട്രാൻസ്ക്രിപ്റ്റ് നിലനിൽപ്പ് (#12150 P1).** ഇത് സ്വയം-ഓപ്റ്റ്-ഇൻ ആയ വീഡിയോ ബ്രിഡ്ജ് ഒരു ട്രാൻസ്ക്രിപ്റ്റ് ക്യൂ അവതരിപ്പിക്കുമ്പോൾ സ്വയമേവ പ്രയോഗിക്കുന്നു — ഒരു വ്യത്യസ്ത നിലനിൽപ്പ് പതാക ഇല്ല. ഒരു അഭ്യർത്ഥന ഏതെങ്കിലും ട്രാൻസ്ക്രിപ്റ്റ് ക്യൂ (ഒരു കോളർ-പ്രഖ്യാപിത `transcript` അല്ലെങ്കിൽ ഒരു ഫ്യൂസ്ഡ് `audioTranscript`) അവതരിപ്പിക്കുമ്പോൾ, ഗാർഡ്‌റെയിൽ അത് `videoBridgeObserved` എന്നതിൽ അടയാളപ്പെടുത്തുന്നു, വീഡിയോ വിവരണത്തിന്റെ ഒരു റെഡാക്ടഡ് ഷാഡോ ഉൽപ്പാദിപ്പിക്കുന്നു — ഓരോ ക്യൂയുടെ ഫ്രീ-ടെക്സ്റ്റ് ബോഡി `[redacted-video-transcript]` എന്നതാൽ മാറ്റപ്പെടുന്ന സമാനമായ ഒരു രൂപീകരണം, ഘടനാപരമായ ക്യൂ ഫീൽഡ് സ്ട്രിംഗ് സമാഹരിക്കുന്നതിന് മുമ്പ് മാറ്റാൻ ഉപയോഗിച്ച് നിർമ്മിക്കപ്പെടുന്നു (ചുരുക്കിയ ടെക്സ്റ്റ് പാഴ്സിംഗ് വഴി അല്ല, അതിനാൽ യാതൊരു ക്യൂ ഉള്ളടക്കവും — എതിരാളി അല്ലെങ്കിൽ സാധാരണ, `]` അടങ്ങിയ ബോഡികൾ ഉൾപ്പെടെ, `[inaudible]`/`[music]` പോലുള്ളവ — നിലനിൽക്കാൻ കഴിയില്ല). നിലനിൽക്കുന്ന കോള്ലോഗ് അഭ്യർത്ഥന ബോഡി ഓരോ വീഡിയോ-ഉത്ഭവമുള്ള ടെക്സ്റ്റ് ഭാഗവും ആ റെഡാക്ടഡ് ഷാഡോയ്ക്ക് മാറ്റുന്നു, ഉള്ളടക്ക സമാനതയാൽ പൊരുത്തപ്പെടുന്നു; `fullText` ആങ്കർ പൂർത്തിയായ പ്രീ-കാൾ ഗാർഡ്‌റെയിൽ പേലോഡിൽ നിന്ന് വീണ്ടും വായിക്കുന്നു, അതിനാൽ പിന്നീട് ശൃംഖല ഗാർഡ്‌റെയിലുകൾ (PII, ക്രെഡൻഷ്യൽ മാസ്കറുകൾ, പ്രാധാന്യങ്ങൾ 10/95) വിവരണ ടെക്സ്റ്റ് സ്ഥലം മാറ്റുമ്പോഴും പൊരുത്തം വിജയിക്കുന്നു. മോഡലിലേക്ക് മുകളിൽ അയക്കുന്ന ബോഡി മാറ്റമില്ല. ഒരു നിരീക്ഷിച്ച അഭ്യർത്ഥനയും സ്ഥിരമായ മെമ്മറിയിൽ ഒന്നും നിറയ്ക്കുന്നില്ല (അഭ്യർത്ഥന-യും മറുപടി-ഉത്ഭവമുള്ള എക്സ്ട്രാക്ഷൻ skipped ചെയ്യുന്നു), അതിനാൽ മോഡലിന്റെ സ്വന്തം മറുപടി മെമ്മറിയിലേക്ക് ട്രാൻസ്ക്രിപ്റ്റ് ടെക്സ്റ്റ് പ്രതിഫലിപ്പിക്കാൻ കഴിയില്ല.

**റോ വീഡിയോ ഫീൽഡുകൾ (#12430).** ബ്രിഡ്ജ് സജീവമാകുമ്പോഴും നാടിവീഡിയോ പിന്തുണ അറിയാത്തതും ഇല്ലാത്തതും ആയപ്പോൾ, നിർവചിച്ച `transcript`/`audioTranscript` ഫീൽഡുകൾ `videoBridgeObserved`-നെ സജീവമാക്കുന്നു, വിവരണ പരാജയം അല്ലെങ്കിൽ `maxVideos` പരിധി കഴിഞ്ഞാലും. `null`യും ശൂന്യമായ സ്ട്രിംഗുകളും എണ്ണപ്പെടുന്നു; അഭാവമുള്ള ഫീൽഡുകളും non-video മെറ്റാഡാറ്റയും ഇല്ല. നിലനിൽക്കുന്ന പകർപ്പുകൾ ഈ ഫീൽഡുകൾ റെഡാക്റ്റ് ചെയ്യുന്നു അല്ലെങ്കിൽ അഭ്യർത്ഥന ഒഴിവാക്കുന്നു, കാഷുകൾ/മെമ്മറി ഒഴിവാക്കുന്നു. പ്രൊവൈഡർ പേലോഡ് മാറ്റമില്ലാതെ തുടരുന്നു.

കൂടുതൽ നിലനിൽക്കുന്ന പകർപ്പുകൾ ഒരേ നിരീക്ഷിച്ച-അഭ്യർത്ഥന സിഗ്നലിനെ ഉപയോഗിക്കുന്നു. റോ പ്രീ-ഗാർഡ്‌റെയിൽ ക്ലയന്റ്-അഭ്യർത്ഥന സ്നാപ്ഷോട്ട്, മെമ്മറിയിൽ_PENDING_REQUEST_, പ്രാരംഭ നിരസിച്ച-അഭ്യർത്ഥന ലോഗ് ഘടനാപരമായി ട്രാൻസ്ക്രിപ്റ്റ് ഫീൽഡുകൾ വീഡിയോ ഭാഗങ്ങളിൽ മാറ്റുന്നു; പൈപ്പ്‌ലൈൻ ഘട്ടങ്ങൾക്കും സാഹചര്യ കൈമാറ്റത്തിനും സിന്തസൈസ് ചെയ്ത സ്ട്രിംഗ് പ്രോംപ്റ്റുകൾ നിലനിൽക്കുന്ന-അഭ്യർത്ഥന-ബോഡി സിങ്കിൽ റെഡാക്റ്റ് ചെയ്യുന്നു. നിലനിൽക്കുന്ന `video_content_removed` മാർക്കർ `previous_response_id` തുടർച്ച പരാജയപ്പെടുന്നത് അടച്ചുപൂട്ടുന്നു, ഉദ്ദേശിച്ചും ഒഴിവാക്കപ്പെട്ട ടെക്സ്റ്റ് പുനർനിർമ്മിക്കാൻ പകരം. ഒരു നിരീക്ഷിച്ച അഭ്യർത്ഥന ലോഗ് ചെയ്യുന്നതിന് മുമ്പ് അതിന്റെ ഓരോ ഭാഗത്തെയും റെഡാക്ഷൻ ഷാഡോ നഷ്ടപ്പെടുകയോ, അല്ലെങ്കിൽ പിന്നീട് അഭ്യർത്ഥന മാറ്റങ്ങൾക്കുശേഷം നിരവധി വീഡിയോ ഷാഡോകളിൽ ഒന്നും പൊരുത്തപ്പെടുന്നില്ലെങ്കിൽ, നിലനിൽക്കുന്ന അഭ്യർത്ഥന ബോഡി ഭാഗികമായി റെഡാക്റ്റ് ചെയ്ത ട്രാൻസ്ക്രിപ്റ്റ് നിലനിൽക്കുന്നതിന് പകരം മുഴുവനായും ഒഴിവാക്കപ്പെടുന്നു.

ഒരു നിരീക്ഷിച്ച അഭ്യർത്ഥനയ്ക്ക്, ഒരു മോഡൽ പ്രതികരണം ട്രാൻസ്ക്രിപ്റ്റിന്റെ ഏതെങ്കിലും ഭാഗം ഒരു ഘടനാപരമായ സൂചനാ അതിരില്ലാതെ ഉദ്ധരിക്കാം. അതിന്റെ നിലനിൽക്കുന്ന കോൾ-ലോഗ് `responseBody` അതിനാൽ ഒരു ഒഴിവാക്കൽ മാർക്കർ കൊണ്ട് മാറ്റപ്പെടുന്നു; വിശദമായ പൈപ്പ്‌ലൈൻ ആർട്ടിഫാക്റ്റ് (ഉപരിതല/ക്ലയന്റ് ബോഡികൾക്കും സ്ട്രീം ചങ്കുകൾക്കും ഉൾപ്പെടാം) നിലനിര്‍ത്തുന്നില്ല. അർത്ഥപരമായ, ഐഡമ്പോടൻസി, reasoning-replay കാഷുകൾ ആ അഭ്യർത്ഥനയ്ക്ക് വായനകളും എഴുതലുകളും ഒഴിവാക്കുന്നു. പ്രൊവൈഡർ അഭ്യർത്ഥനയും ക്ലയന്റ്-ദൃശ്യമായ പ്രതികരണവും മാറ്റമില്ലാതെ തുടരുന്നു. വിശദമായ ആർട്ടിഫാക്റ്റ് ഒഴിവാക്കുമ്പോൾ താൽക്കാലിക ബഫറിൽ നിന്ന് പ്രാരംഭ_KEEPALIVE ബൈറ്റുകൾ ഒഴുക്കുന്നു. കിറോയുടെ തെറ്റായ EventStream മുന്നറിയിപ്പ് payload ബൈറ്റ് എണ്ണത്തെ മാത്രം റിപ്പോർട്ട് ചെയ്യുന്നു, അതിന്റെ ഉള്ളടക്കം അല്ലെങ്കിൽ JSON പാഴ്സറിന്റെ കച്ചവട പിശക് ഒരിക്കലും കാണിക്കുന്നില്ല.
ഈ രേഖപ്പെടുത്തുന്നത് എല്ലാ ബന്ധമില്ലാത്ത പ്രൊവൈഡർ/പ്ലഗിൻ ഡയഗ്നോസ്റ്റിക്‌സ് പരിശോധിച്ചിട്ടില്ല എന്ന് അവകാശപ്പെടുന്നില്ല; വ്യാപകമായ നിലനിൽക്കുന്ന-സിങ്ക് സ്വീപ്പ് #11658-ൽ ട്രാക്ക് ചെയ്യുന്നു.

ആന്തരിക `/api/modality-bridge/video/drilldown` ജീവിതചക്രം ഒരു വ്യത്യസ്തമായ, ലൂപ്പ്ബാക്ക്/ടോക്കൺ-അധികൃതമായ കാഷ് സബ്സ്ട്രേറ്റ് ആണ്. ഓരോ പ്രവർത്തനത്തിനും ഒരു കാനോണിക്കൽ ഒപാക് പ്രിൻസിപ്പൽ ഐഡി ആവശ്യമാണ്. ഒരു പ്രൊഡക്ഷൻ കോളർ സജീവമാക്കുന്നതിന് മുമ്പ്, അത് അതിന്റെ ഐഡി അംഗീകരിച്ച ടെനന്റിൽ നിന്ന് ഉത്പാദിപ്പിക്കണം, ക്ലയന്റ്-തിരഞ്ഞെടുത്ത മൂല്യം ഒരിക്കലും മുന്നോട്ട് നൽകരുത്. കാഷ് കീകൾ ആ പ്രിൻസിപ്പലിനെ കാനോണിക്കൽ സെഷൻ, വീഡിയോ-റഫറൻസ് ഐഡികളുമായി ബന്ധിപ്പിക്കുന്നു, അവയുടെ SHA-256-ഉൽപ്പന്ന കീകൾ മാത്രം സൂക്ഷിക്കുന്നു, വായനകളും ഇല്ലാതാക്കലും ഒരേ പ്രിൻസിപ്പലിലേക്ക് പരിധി ചെയ്യുന്നു. കാഷ് ഓരോ എൻട്രിക്ക് 16 ഉൽപ്പന്ന JPEG ഫ്രെയിമുകൾ വരെ സൂക്ഷിക്കുന്നു, പത്ത് മിനിറ്റുകൾക്ക് ശേഷം അവ expire ചെയ്യുന്നു, ബൗണ്ടഡ് `start`/`end` വായനകൾ അല്ലെങ്കിൽ വ്യക്തമായ സെഷൻ ഇല്ലാതാക്കലുകൾ പിന്തുണയ്ക്കുന്നു.

ഓരോ പ്രിൻസിപ്പലും 16 എൻട്രികൾക്കും 64 MiB കാനോണിക്കൽ JPEG ഡാറ്റയ്ക്കും പരിമിതമാണ്. ആ പരിധികൾ ആഗോള 64-എൻട്രി/256 MiB മേൽക്കൂരയിൽ നിന്ന് സ്വതന്ത്രമാണ്: പ്രിൻസിപ്പൽ ക്വോട്ടാ സമ്മർദം ആ പ്രിൻസിപ്പലിന്റെ ഏറ്റവും-കഴിഞ്ഞ-ഉപയോഗിച്ച എൻട്രികൾ മാത്രം ഒഴിവാക്കുന്നു, ആഗോള LRU ഒഴിവാക്കലിന് മുമ്പ്. കാലഹരണപ്പെട്ട എൻട്രികൾ കാഷ് പ്രവർത്തനത്തിൽ പ്രിൻസിപ്പലും ആഗോള അക്കൗണ്ടിംഗും നിന്ന് നീക്കം ചെയ്യുന്നു, റദ്ദാക്കലും സ്ഥിരീകരണ പരാജയവും ഭാഗിക മാറ്റം പ്രതിജ്ഞാബദ്ധമാക്കുന്നില്ല.

കാഷ് കാനോണിക്കൽ ബേസ്64, അധിക പാഡിംഗ്, നോൺ-JPEG മീഡിയ, തെറ്റായ അല്ലെങ്കിൽ ചുരുക്കിയ JPEGകൾ, ബൗണ്ടഡ് ഫുൾ-ഇമേജ് `sharp` ഡികോഡിങ്ങിൽ മുന്നറിയിപ്പ് നൽകുന്ന JPEGകൾ എന്നിവ നിരസിക്കുന്നു. ഇത് സ്വീകരിച്ച ഓരോ ചിത്രത്തെയും ഒരു കാനോണിക്കൽ JPEG ആയി വീണ്ടും എൻകോഡ് ചെയ്യുന്നു, ഡികോഡ് ചെയ്ത ബൈറ്റുകളിൽ നിന്ന് വീതിയും ഉയരവും ഉത്പാദിപ്പിക്കുന്നു, കോളർ ഫീൽഡുകൾക്ക് വിശ്വാസം വയ്ക്കാതെ, പിന്നിലെ പോളിഗ്ലോട്ട് ബൈറ്റുകൾ നിലനിര്‍ത്തുന്നതിന് പകരം തള്ളുന്നു. ബൗണ്ടഡ് കാനോണിക്കൽ കംപ്രസ്സ് ചെയ്ത ബഫർ മാത്രമാണ് ഇരുവരുടെയും ക്വോട്ടാസിന് ചാർജ് ചെയ്യുന്നത്. JSON വയർ പരിധി 32 MiB ഡികോഡ് ചെയ്ത-ഇൻപുട്ട് മേൽക്കൂരയ്ക്കായി ബേസ്64 ഓവർഹെഡ് ഉൾക്കൊള്ളുന്നു. ഓരോ സൂക്ഷിച്ച ഉൽപ്പന്നവും അതിന്റെ സ്ഥിരീകരിച്ച JPEG ഫോർമാറ്റ്/റിസൊല്യൂഷൻ, സാമ്പ്ലിംഗ് നയം, ഉൽപ്പന്ന പതിപ്പ്, സൃഷ്ടി സമയം, സർവർ-കണക്കാക്കിയ ഉള്ളടക്കം ഹാഷ്, ഹാഷ് ചെയ്ത മാതൃകാ റഫറൻസ് കൂടാതെ വിശ്വസനീയമായ കോളറിന്റെ മാതൃകാ-ഉള്ളടക്കം ഹാഷ് രേഖപ്പെടുത്തുന്നു. അസിങ്ക്രണസ് ഡികോഡ്/ഹാഷ് ഘട്ടങ്ങൾക്കിടയിൽ റദ്ദാക്കൽ പരിശോധിക്കുന്നു, ആറ്റോമിക് കാഷ് പ്രതിജ്ഞാബദ്ധമാക്കുന്നതിന് മുമ്പ്.

പ്രൊഡക്ഷൻ പ്രൊഡ്യൂസർ വിജയകരമായ ദൃശ്യ വിശകലനത്തിന് ശേഷം മാത്രമേ ഇതിനകം ഉൽപ്പന്നമായ ബ്രോക്കർ ഫ്രെയിമുകൾ പുനരുപയോഗിക്കുകയുള്ളു, രണ്ടാം വീഡിയോ ഡൗൺലോഡ്/എക്സ്ട്രാക്ഷൻ ഇല്ല. ഇത് ഓപ്പറേറ്റർ `modalityBridgeVideoDrilldownEnabled=true`, കർശനമായ ഭാഗം-പ്രതി `drilldown: true`, ഒരു അംഗീകരിച്ച API-കീ റെക്കോർഡ് ഐഡി ആവശ്യമാണ്. ക്ലയന്റ്-പ്രഖ്യാപിത പ്രിൻസിപ്പൽ/സെഷൻ മൂല്യങ്ങൾ ഒരിക്കലും ഉടമസ്ഥത സ്ഥാപിക്കുന്നില്ല. ഈ മൂന്ന് വ്യവസ്ഥകളും ഇല്ലാതെ, ഇത് ഹാഷ് ചെയ്യുകയോ, പുനർവലിച്ചോ, അധിക ഫ്രെയിമുകൾ നിലനിര്‍ത്തുകയോ ചെയ്യില്ല. നിലനിര്‍ത്തൽ പരാജയം ഉപയോഗയോഗ്യമായ ദൃശ്യ പ്രതികരണം സംരക്ഷിക്കുന്നു. സമ്മതിച്ച അഭ്യർത്ഥനകൾ മുഴുവൻ-വീഡിയോ ഫല കാഷ് ഒഴിവാക്കുന്നു, അതിനാൽ കാഷ് ചെയ്ത ഫലങ്ങൾ ഒരിക്കലും കൈകാര്യം ചെയ്യുകയില്ല.

വിജയകരമായ JSON, SSE പ്രതികരണങ്ങൾ പരമാവധി നാല് ഒപാക് കൈകാര്യം ചെയ്യലുകൾ `x-omniroute-video-drilldown` ഹെഡറിൽ വെളിപ്പെടുത്തുന്നു. അധികൃതമായ ബ്രൗസർ ഉറവിടങ്ങൾ ആ ഹെഡർ വായിക്കാൻ കഴിയും, CORS ഉറവിട നയം വ്യാപിപ്പിക്കാതെ. പുതിയ കൈകാര്യം ചെയ്യലുകൾ `v1.<32-byte random base64url token>` ഉപയോഗിക്കുന്നു, രജിസ്ട്രി അവയുടെ SHA-256 ഹാഷുകൾ മാത്രം നിലനിര്‍ത്തുന്നു. വായനക്കാരൻ/ഹെഡർ പാഴ്സർ പഴയ 64-ഹെക്‌സ് കൈകാര്യം ചെയ്യലുകൾക്കും സ്വീകരിക്കുന്നു. അംഗീകരിച്ച പൊതു ഉപഭോക്താവ് `GET /api/v1/video-bridge/drilldown?handle=...`, സ്വതന്ത്രമായി `modalityBridgeVideoDrilldownRemoteEnabled=true` എന്നതാൽ ഗേറ്റുചെയ്യുന്നു. വ്യക്തമായ നിലനിൽക്കുന്ന തെറ്റായത്, പഴയ `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_REMOTE_ENABLED` env ഫാൾബാക്ക് സജീവമായിട്ടും പ്രവേശനം റദ്ദാക്കുന്നു. പ്രൊഡക്ഷൻ നിലനിര്‍ത്തലിന് സമാനമായ പഴയ `OMNIROUTE_VIDEO_BRIDGE_DRILLDOWN_ENABLED` ഫാൾബാക്ക് ഉണ്ട്. ഇരുവിധം ഫാൾബാക്കുകളും ഡിഫോൾട്ട് ഓഫ് ആണ്.

ഉപഭോക്താവ് അംഗീകരിച്ച കീയിൽ നിന്ന് ഉടമസ്ഥത ഉത്പാദിപ്പിക്കുന്നു, കീ നയം പ്രയോഗിക്കുന്നു, അറിയപ്പെടാത്ത, കാലഹരണപ്പെട്ട, മറ്റൊരു കീയുടെ കൈകാര്യം ചെയ്യലുകൾക്കായി ഒരേ 404 തിരികെ നൽകുന്നു. ഇത് `variant=preview|standard|detail` (പരമാവധി JPEG അളവ് 320/640/1280, ഒരിക്കലും ഉയർത്തുന്നില്ല), `limit=1..8` (അല്ലെങ്കിൽ പഴയ `frames` ഉപനാമം, ഒരിക്കലും ഇരുവരും അല്ല), ശൂന്യ-അടിസ്ഥാന `page`, ഓപ്ഷണൽ `start`/`end` ഫോകസ് സെക്കൻഡുകൾ സ്വീകരിക്കുന്നു. പുനരാവൃതമായ
ക്വറി കീകൾക്കും മറിച്ചുള്ള ഫോകസ് വിൻഡോകൾക്കും നിരസിക്കുന്നു. ഓരോ തിരികെ ലഭിച്ച വകഭേദത്തിനും അതിന്റെ യഥാർത്ഥ ഉള്ളടക്കം, യഥാർത്ഥ റിസൊല്യൂഷൻ മെറ്റാഡാറ്റയുടെ ഹാഷ് ഉണ്ട്, നിലനിൽക്കുന്ന ഉറവിടവുമായി ബന്ധിപ്പിച്ചിരിക്കുന്നു. വകഭേദങ്ങൾ വായനയിൽ ഉത്പാദിപ്പിക്കപ്പെടുന്നു, അധികമായി നിലനിര്‍ത്തുന്ന പകർപ്പുകളായി സൂക്ഷിക്കുന്നില്ല. JSON പ്രതികരണം, ബേസ്64/എൻവലപ്പ് ഉൾപ്പെടെ, 32 MiB-ൽ പരിമിതമാണ്; ഒരു വലിയ പേജ് 413 തിരികെ നൽകുന്നു, ക്ലയന്റ് കുറച്ച് ഫ്രെയിമുകൾക്കായി അഭ്യർത്ഥിക്കണം. വായനകൾ ഓരോ പുനർവലിച്ചും കൈകാര്യം ചെയ്യലിന്റെ സാധുത വീണ്ടും പരിശോധിക്കുന്നു. ഉടമസ്ഥനായ `DELETE` ഐഡമ്പോടൻറ് ആണ്; ഇല്ലാതാക്കലോ TTL കാലഹരണപ്പെടലോ നിലനിൽക്കുന്ന ഉറവിടവും ഉപയോഗ അക്കൗണ്ടിംഗും റിലീസ് ചെയ്യുന്നു.

പങ്കിടുന്ന സ്റ്റോർ പ്രോസസ്-ലോകൽ ആണ്: കൈകാര്യം ചെയ്യലുകൾ പുനരാരംഭിക്കുമ്പോൾ കാലഹരണപ്പെടുന്നു, സ്വതന്ത്ര OmniRoute പ്രോസസുകൾക്കിടയിൽ കൈമാറാൻ കഴിയുന്നില്ല. മാനേജ്മെന്റ് സ്റ്റാറ്റുകൾ ഫലപ്രദമായ നിലനിര്‍ത്തൽ/അവശ്യ നയം, സമാഹൃതമായ എൻട്രികൾ/ബൈറ്റുകൾ മാത്രം വെളിപ്പെടുത്തുന്നു, മീഡിയ, റഫറൻസുകൾ, പ്രിൻസിപ്പൽ ഐഡികൾ അല്ലെങ്കിൽ കൈകാര്യം ചെയ്യലുകൾ ഒരിക്കലും ഇല്ല. വീഡിയോ ക്രമീകരണങ്ങൾ പാനലിൽ ആ മൂല്യങ്ങൾ കാണിക്കുന്നു, ഇരുവരുടെയും സമ്മത സ്വിച്ച് നിലനിര്‍ത്താൻ കഴിയും. ഈ നടപ്പാക്കൽ ഡോക്യുമെന്റേഷൻ ജീവിച്ചിരിക്കുന്ന വിന്യാസം അല്ലെങ്കിൽ പ്രചാരണം തെളിവാണ്; യഥാർത്ഥ-മോഡൽ അംഗീകരണം വ്യത്യസ്തമായി ട്രാക്ക് ചെയ്യുന്നു.

ഫ്രെയിമുകൾ ക്രമീകരിച്ച വീഡിയോ മോഡലുമായി അനുസൃതമായി ക്രമീകരിക്കപ്പെട്ടിരിക്കുന്നു. ഒരു ശൂന്യമായ വീഡിയോ ഓവർറൈഡ് ദൃശ്യ ക്രമീകരണം പാരമ്പര്യമായി inherits ചെയ്യുന്നു; രണ്ടും ശൂന്യമായാൽ, ദൃശ്യ ഓട്ടോ-റൂട്ടർ ഫലപ്രദമായ ദൃശ്യ-ശേഷിയുള്ള മോഡൽ തിരഞ്ഞെടുക്കുന്നു. വിജയകരമായ ക്യാപ്ഷനുകൾ `[Video description:` മുൻപോകുന്ന ഒരു സ്ഥിരമായ പ്രിഫിക്‌സ് ഉപയോഗിച്ച് മുടിഞ്ഞ ഭാഗം മാറ്റുന്നു, ഇത് ടെക്സ്റ്റ് ഒരു വിശ്വസിക്കാത്ത മീഡിയ-ഉല്പന്നമായ നിരീക്ഷണം എന്ന് അടയാളപ്പെടുത്തുകയും മീഡിയയിൽ കണ്ടെത്തിയ നിർദ്ദേശങ്ങൾ പിന്തുടരാൻ താഴെയുള്ള മോഡലുകൾക്ക് പറയുകയും ചെയ്യുന്നു. ഫ്രെയിം-ക്യാപ്ഷൻ കാഷ് കീകൾ JPEG ബൈറ്റുകൾ, പ്രോംപ്റ്റ്, ടൈംസ്റ്റാമ്പ്, ഫലപ്രദമായ മോഡൽ എന്നിവ ഉൾക്കൊള്ളുന്നു; വിജയകരമായ ക്യാപ്ഷനുകൾ മാത്രം കാഷ് ചെയ്യപ്പെടുന്നു. കാഷ് എൻട്രികൾ യഥാർത്ഥ വിജയകരമായ ഉല്പന്ന മോഡൽ, ഒരു ഫാൾബാക്ക് മോഡൽ ഉൾപ്പെടെ, നിലനിർത്തുന്നു; വ്യത്യസ്ത മോഡലുകൾ വ്യത്യസ്ത ഫ്രെയിമുകൾ ഉല്പന്നമായപ്പോൾ ബ്രിഡ്ജ് `mixed` റിപ്പോർട്ട് ചെയ്യുന്നു. ഒരു കാഷ് ഹിറ്റ് ആ ഉല്പന്ന ഐഡന്റിറ്റിയെ പുനരുപയോഗിക്കുന്നു, അതിനെ ആവശ്യമായ റൂട്ടിംഗ് പ്ലാനായി പുനർലേബൽ ചെയ്യുന്നതിന് പകരം. മുഴുവൻ-വീഡിയോ ഫല കാഷ് ഔട്ട്‌പുട്ട് മാറ്റുന്ന ഓരോ ഇൻപുട്ടിലും കീ ചെയ്യപ്പെടുന്നു — പ്രോംപ്റ്റ്, ഫലപ്രദമായ മോഡൽ, സാമ്പിളിംഗ് നയം, ഫ്രെയിം എണ്ണം, സെമാന്റിക് വിശകലന മോഡ്, നോർമലൈസ്ഡ് ഫോകസ് ഹിന്റിന്റെ SHA-256 ഫിംഗർപ്രിന്റ്, ഫോകസ് വിൻഡോ, `transcript`, `audioTranscript`, കൂടാതെ കോൺടാക്റ്റ്-ഷീറ്റ് ഫ്ലാഗ് — അതിനാൽ ആ ഡിമൻഷനുകളിൽ ഏതെങ്കിലും മാറ്റം ഒരു കാഷ് മിസ് ആണ്, ഒരിക്കലും പഴയ പുനരുപയോഗം അല്ല. ദൃശ്യ ഡിഡ്യൂപ്പ് നയം പതിപ്പ്, ത്രെഷോൾഡ്, ബൗണ്ടഡ് കാൻഡിഡേറ്റ്-ഫ്രെയിം എണ്ണം എന്നിവ ഫല-കാഷ് കീയും മെറ്റാഡാറ്റയും വ്യക്തമാക്കുന്നു; അതിനാൽ ഒരു നയം മാറ്റം പഴയ മുഴുവൻ-വീഡിയോ വിവരണം പുനരുപയോഗിക്കാൻ കഴിയില്ല. ഫല-കാഷ് v4 മെറ്റാഡാറ്റ മോഡ്, ഫിംഗർപ്രിന്റ് എന്നിവ നിലനിർത്തുന്നു, ഒരിക്കലും കച്ചവട ഉപയോക്തൃ ജോലി. ഗാർഡ്‌റെയിൽ മെറ്റാഡാറ്റ ആവശ്യമായതും ഫലപ്രദമായതുമായ വിശകലന മോഡുകൾ റിപ്പോർട്ട് ചെയ്യുന്നു; ഉപയോഗിക്കാവുന്ന ഉപയോക്തൃ ടെക്സ്റ്റ് ഇല്ലാത്ത ഒരു ആവശ്യമായ `focused` മോഡ് ഫലപ്രദമായി `full` എന്ന നിലയിൽ റിപ്പോർട്ട് ചെയ്യുന്നു.

ഗാർഡ്‌റെയിൽ എല്ലാ പിന്തുണയുള്ള വീഡിയോ ഭാഗങ്ങളും എടുക്കുന്നു, എന്നാൽ `modalityBridgeVideoMaxVideos` ൽ കൂടുതൽ വിവരിക്കുകയില്ല. `supportsVideo === false` എന്ന് തെളിയിച്ച ലക്ഷ്യത്തിന്, പരാജയപ്പെട്ടതും അതിരുകൾക്കപ്പുറം ഉള്ള വീഡിയോകൾ വ്യക്തമായ സുരക്ഷിത ടെക്സ്റ്റ് മാർക്കറുകളായി മാറുന്നു, അതിനാൽ ഒരു കച്ചവട വീഡിയോയും നിലനിൽക്കുകയില്ല. ശേഷി അറിയാത്തപ്പോൾ, ആ ഭാഗങ്ങൾ അഴിച്ചുവിടപ്പെടുന്നില്ല. `supportsVideo === true` ഉള്ള ലക്ഷ്യങ്ങൾ ബ്രിഡ്ജ് ഒഴിവാക്കുന്നു. ക്ലയന്റ് അഭ്യർത്ഥന ഉപേക്ഷണ സൂചന ഡൗൺലോഡ്, ബ്രോക്കർ ക്യൂ, ഉപപ്രക്രിയകൾ, ക്യാപ്ഷൻ വിളികൾ എന്നിവയിലൂടെ പ്രചരിക്കുന്നു; ഉപേക്ഷണങ്ങൾ വീഡിയോകൾക്കിടയിൽ നിർത്തുന്നു, ഒരിക്കലും കച്ചവട മീഡിയയിലേക്ക് തുറക്കുകയില്ല.

റൺടൈം ക്രമീകരണങ്ങൾ DB-ബാക്ക് ചെയ്തതും Zod-വാലിഡേറ്റഡ്:

| കീ                                  | ഡിഫോൾട്ട്   | പരിധി / പെരുമാറ്റം                                                                                                             |
| ----------------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `modalityBridgeVideoEnabled`        | `false`     | ഐച്ഛിക റൺടൈം, ഓപ്റ്റ്-ഇൻ                                                                                                       |
| `modalityBridgeVideoAnalysisMode`   | `"full"`    | `full` പൊതുവായ ക്യാപ്ഷനുകൾ നിലനിർത്തുന്നു; `focused` ബൗണ്ടഡ്, വിശ്വസിക്കാത്ത ഏറ്റവും പുതിയ ഉപയോക്തൃ സാഹചര്യങ്ങൾ ഉപയോഗിക്കുന്നു |

120 സെക്കൻഡുകൾക്കു മുകളിൽ പാരമ്പര്യമായി നിലനിൽക്കുന്ന വീഡിയോ ടൈംഔട്ട് മൂല്യങ്ങൾ ബ്രോക്കർ ഡെഡ്‌ലൈൻ വരെ ക്ളാമ്പ് ചെയ്യപ്പെടുന്നു; ആ പരിധി മുകളിൽ പുതിയ ക്രമീകരണങ്ങൾ എഴുതുന്നത് നിരസിക്കപ്പെടുന്നു. `GET /api/modality-bridge/video/runtime` വിശ്വസനീയമായ സ്റ്റാമ്പ് ചെയ്ത ലൂപ്പ്ബാക്ക് ലോക്കാലിറ്റി ആവശ്യമാണ്, അതിന് മുമ്പ് അംഗീകാരം അല്ലെങ്കിൽ റൺടൈം പ്രോബിംഗ്, പിന്നീട് മാനേജ്മെന്റ് ഓത്തentication ആവശ്യമാണ്. ഇത് `available`, ശുദ്ധീകരിച്ച FFmpeg/ffprobe പതിപ്പുകൾ, റൺടൈം ലഭ്യമല്ലെങ്കിൽ ഒരു സ്ഥിരമായ കാരണം മാത്രമേ തിരികെ നൽകുകയുള്ളു. ആന്തരിക എക്സ്ട്രാക്ഷൻ എൻഡ്പോയിന്റ് ഒരു പൊതു അപ്‌ലോഡ് API അല്ല: ക്യൂ saturation `503` കൂടാതെ `Retry-After` തിരികെ നൽകുന്നു, ഒരു വിളിക്കാരൻ ബന്ധം വിച്ഛേദിക്കുന്നത് `499` നൽകുന്നു, സ്ഥിരമായ ബ്രോക്കർ ഡെഡ്‌ലൈൻ `504` നൽകുന്നു. പരിവർത്തനമായ പ്രതികരണങ്ങൾ കേന്ദ്ര `x-omniroute-modality-bridge` ഹെഡറിലേക്ക് `video->text;model=<visionModel>;parts=<videos>` ചേർക്കുന്നു, ദൃശ്യ അല്ലെങ്കിൽ ഓഡിയോ സെഗ്മെന്റുകൾ നീക്കം ചെയ്യാതെ.

### PII Masker (`piiMasker.ts`)

**രണ്ടു** ഘട്ടങ്ങളിലും പ്രവർത്തിക്കുന്നു.

- **`preCall`** പേലോഡ് ക്ലോൺ ചെയ്യുന്നു, `system`, `messages`, `input`, കൂടാതെ `prompt` (സാധാരണ സ്ട്രിംഗ് ഇനങ്ങൾ ഉൾപ്പെടെ) നടന്നു, `processPII()` ( `@/shared/utils/inputSanitizer` ൽ നിന്ന്) സ്ട്രിംഗ് `content`/`text` ഫീൽഡുകൾക്ക് പ്രയോഗിക്കുന്നു. `PII_REDACTION_ENABLED=true` ആയപ്പോൾ, കണ്ടെത്തിയ PII ഔട്ട്‌ബൗണ്ട് പേലോഡിൽ മൂടുന്നു. ഇത് `INPUT_SANITIZER_MODE` (പ്രോംപ്റ്റ്-ഇൻജക്ഷൻ നയം മാത്രം നിയന്ത്രിക്കുന്നു) ന്റെ സ്വതന്ത്രമാണ്. മൂടൽ ഇല്ലെങ്കിൽ, വിളി കണ്ടെത്തൽ എണ്ണങ്ങൾ രേഖപ്പെടുത്തുന്നു, ഉള്ളടക്കം പുനരാഖ്യാനം ചെയ്യാതെ.
- **`postCall`** പ്രതികരണത്തെ ആഴത്തിൽ ക്ലോൺ ചെയ്യുന്നു, `sanitizePIIResponse()` പ്രവർത്തിപ്പിക്കുന്നു കൂടാതെ Responses-API-രൂപം മസ്കർ (`maskResponsesOutput` — `output_text` കൂടാതെ `output[].content[].text` ഉൾക്കൊള്ളുന്നു). ഏതെങ്കിലും മൂടൽ സംഭവിച്ചാൽ, മാറ്റിയ പ്രതികരണം യഥാർത്ഥത്തെ മാറ്റുന്നു.

ഗാർഡ്‌റെയിൽ ഒരിക്കലും തടയുന്നില്ല; ഇത് വെറും അടയാളപ്പെടുത്തുന്നു (`meta.detections`, `meta.redacted`) അല്ലെങ്കിൽ പുനരാഖ്യാനം ചെയ്യുന്നു.

### Prompt Injection (`promptInjection.ts`)

ഉപയോക്തൃ-നൽകിയ ഉള്ളടക്കത്തിൽ എതിരാളി ഘടനകൾ കണ്ടെത്തുകയും ക്രമീകരിച്ച നയം നടപ്പിലാക്കുകയും ചെയ്യുന്നു. പെരുമാറ്റം പരിസ്ഥിതി വ്യത്യാസങ്ങൾക്കും നിർമ്മാതൃ ഓപ്ഷനുകൾക്കും അനുസൃതമാണ്:

| ക്രമീകരണം          | പരിസ്ഥിതി മാറ്റം                                                                                       | ഡിഫോൾട്ട് | ഫലങ്ങൾ                                                                                                                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------ | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| സജീവമായ            | `INPUT_SANITIZER_ENABLED`                                                                              | `true`    | `false` ആയാൽ, ഗാർഡ്‌റെയിൽ ഷോർട്ട്-സർക്യൂട്ടുകൾ.                                                                                                                                                                   |
| മോഡ്               | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                        | `warn`    | ഇൻജക്ഷൻ നയം: `block`, `warn`, അല്ലെങ്കിൽ `log`. (`redact` ബാക്ക്-കമ്പാറ്റിന് സ്വീകരിക്കപ്പെടുന്നു, പക്ഷേ ഇൻജക്ഷൻ ടെക്സ്റ്റ് നീക്കം ചെയ്യുകയില്ല; PII പുനരാഖ്യായനം `PII_REDACTION_ENABLED` വഴി നിയന്ത്രിക്കുന്നു.) |
| ബ്ലോക്ക് ത്രെഷോൾഡ് | `blockThreshold` ഓപ്ഷൻ / `INPUT_SANITIZER_BLOCK_THRESHOLD` (അലിയാസ് `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`    | ബ്ലോക്ക് ചെയ്യാൻ ആവശ്യമായ കുറഞ്ഞ ഗുരുത്വം. മധ്യത്തിൽ ഡിഫോൾട്ടിൽ നിരീക്ഷണം മാത്രം.                                                                                                                                 |

**മോഡ് മുൻഗണന** (`getMode`): caller `options.mode` →
`INJECTION_GUARD_MODE` **ഡാറ്റാബേസ് ഫീച്ചർ-ഫ്ലാഗ് ഓവർറൈഡ്** (ഡാഷ്ബോർഡ് → ക്രമീകരണങ്ങൾ →
ഫീച്ചർ ഫ്ലാഗുകൾ) → `INJECTION_GUARD_MODE` പരിസ്ഥിതി → `INPUT_SANITIZER_MODE` പരിസ്ഥിതി →
`warn`. അതിനാൽ, ഒരു ഡാഷ്ബോർഡ് ഓവർറൈഡ് പരിസ്ഥിതി മാറ്റങ്ങൾക്കു മേൽ വിജയിക്കുന്നു, അതിനാൽ ഫീച്ചർ
ഫ്ലാഗുകൾ UI പ്രവർത്തനക്ഷമമായ ഗാർഡ് നിയന്ത്രിക്കുന്നു (പുതുക്കൽ ഇല്ല). ഡാറ്റാബേസ് വായന ഫെയിൽ-സേഫ് ആണ്:
അത് പിഴവുണ്ടായാൽ, ഗാർഡ് പരിസ്ഥിതിയിലുള്ള പെരുമാറ്റത്തിലേക്ക് വീഴുന്നു, കൂടാതെ ഒരു
ഓവർറൈഡ് സജ്ജീകരിച്ചിട്ടില്ലെങ്കിൽ പെരുമാറ്റം പരിസ്ഥിതി മാത്രം പരിഹാരത്തിന് സമാനമാണ്.

കണ്ടെത്തൽ ഉറവിടങ്ങൾ:

1. `sanitizeRequest()` from `@/shared/utils/inputSanitizer` (pipeline-ൽ മറ്റിടങ്ങളിൽ ഉപയോഗിക്കുന്ന പങ്കുവെച്ച ഡിറ്റക്ടർ സെറ്റ്).
2. ബിൽറ്റ്-ഇൻ `DEFAULT_GUARD_PATTERNS` (ഇപ്പോൾ `system_override_inline` and
   `markdown_system_block`, രണ്ടും `high` ഗുരുത്വം).
3. നിർബന്ധമായ `customPatterns` കൺസ്ട്രക്ടർ ഓപ്ഷനുകൾ വഴി കൈമാറുന്നു (സ്ട്രിംഗുകൾ, regex,
   അല്ലെങ്കിൽ `{ name, pattern, severity }` റെക്കോർഡുകൾ).

`mode === "block"` **മറ്റു** കുറഞ്ഞത് ഒരു കണ്ടെത്തൽ ഗുരുത്വം ത്രെഷോൾഡ് നിറവേറ്റുമ്പോൾ, `preCall` `{ block: true, message: "Request rejected:
suspicious content detected" }` തിരികെ നൽകുന്നു. `warn`/`log` മോഡുകളിൽ ഗാർഡ്‌റെയിൽ ലോഗ് ചെയ്യുന്നു, പക്ഷേ വിളി അനുവദിക്കുന്നു. പങ്കുവെച്ച സഹായി `evaluatePromptInjection()`
അവസാനിക്കുന്നവർക്കായി പ്രോംപ്റ്റുകൾ വിലയിരുത്താൻ എക്സ്പോർട്ട് ചെയ്യുന്നു, രജിസ്ട്രിയിൽ കടക്കാതെ.

**സ്കാൻ ബൗണ്ട് (v3.8.20):** ഡിറ്റക്ടർ **ആദ്യ 16 KB** മാത്രം പരിശോധിക്കുന്നു
ചേരുന്ന പ്രോംപ്റ്റ് ടെക്സ്റ്റ് — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 ബൈറ്റുകൾ)
`src/shared/utils/inputSanitizer.ts`-ൽ. `detectInjection()`
മറ്റു `evaluatePromptInjection()` `slice(0, MAX_INJECTION_SCAN_BYTES)`
പാറ്റേൺ ലൂപ്പിൽ പ്രവർത്തിക്കുന്നതിന് മുമ്പ്. ഇൻജക്ഷൻ ഡയറക്ടീവ്‌കൾ ഒരു ഇൻപുട്ടിന്റെ മുകളിൽ ഇരിക്കുന്നു, അതിനാൽ ഇത്
മൾട്ടി-ഹണ്ട്രഡ്-KB പേലോഡുകളിൽ regex CPU/GC-നെ ക്യാപ് ചെയ്യുന്നു, കണ്ടെത്തലിനെ ദുർബലമാക്കാതെ (cf.
#3932, #4041).

### ക്രെഡൻഷ്യൽ മാസ്കർ (`credentialMasker.ts`)

**രണ്ടു** ഘട്ടങ്ങളിലും പ്രവർത്തിക്കുന്നു, ഡിഫോൾട്ട് ശൃംഖലയിൽ അവസാനത്തേയ്ക്ക് (പ്രാധാന്യം `95`).
ഔട്ട്‌ബൗണ്ട് പേലോഡിൽ നിന്ന് (സന്ദേശം ഉള്ളടക്കം, ടൂൾ-കാൾ ആർഗ്യുമെന്റുകൾ, ടൂൾ ഫലങ്ങൾ)
ശ്രദ്ധേയമായ API-കീ / രഹസ്യ-ടോക്കൺ പാറ്റേണുകൾ **മറ്റു** പ്രൊവൈഡർ പ്രതികരണത്തിൽ നിന്ന്
മാസ്ക് ചെയ്യുന്നു, അതിനാൽ ഒരു പ്രോംപ്റ്റിൽ പേസ്റ്റ് ചെയ്ത ക്രെഡൻഷ്യൽ (അല്ലെങ്കിൽ ഒരു ടൂൾ ഫലത്തിലൂടെ തിരിച്ചറിയപ്പെടുന്നത്)
അപ്പ്സ്ട്രീം പ്രൊവൈഡർ അല്ലെങ്കിൽ ക്ലയന്റിലേക്ക് തിരിച്ചുപോകുന്നില്ല.

- **ഓപ്റ്റ്-ഇൻ മാത്രം**, PII പുനരാഖ്യായനത്തിന് സമാനമായ സമാനമായ നിയമം (Hard Rule #20-അടുത്തത്):
  `settings.credentialRedactionEnabled === true` **അല്ലെങ്കിൽ**
  `CREDENTIAL_REDACTION_ENABLED=true` ഇല്ലാതെ അപ്രാപ്യമാണ്. ഇത് ഓഫ് ചെയ്താൽ, ഗാർഡ്‌റെയിൽ ഒരു നോ-ഓപ്പ് ആണ് —
  ഇത് ഒരിക്കലും ബ്ലോക്ക് ചെയ്യുകയില്ല, ഒരിക്കലും പുനരാഖ്യായനം ചെയ്യുകയില്ല.
- `redactCredentials()` മുഴുവൻ പേലോഡ്/പ്രതികരണ വൃക്ഷം നടന്നു (`walkValue()`,
  പ്രോട്ടോട്ടൈപ്പ്-പോള്യൂഷൻ-സേഫ്, `WeakSet` വഴി സൈക്കിൾ-സേഫ്)
  പൊരുത്തങ്ങൾ `[REDACTED:<type>]` പ്ലേസ്‌ഹോൾഡറുമായി മാറ്റുന്നു, യഥാർത്ഥത്തിൽ
  മാറ്റം വന്ന ശാഖകൾ മാത്രം ക്ലോൺ ചെയ്യുന്നു.
- `CREDENTIAL_PATTERNS` LLM പ്രൊവൈഡർ കീകൾ (OpenAI, OpenAI-proj,
  Anthropic, Google, Hugging Face, Replicate), VCS/SaaS ടോക്കൺ (GitHub, Slack,
  Linear, Notion, npm, Postman, Discord), പേയ്മെന്റ് കീകൾ (Stripe, Square), ക്ലൗഡ്
  കീകൾ (AWS access key, Twilio, SendGrid, Mailgun), സ്വകാര്യ കീകൾ / JWTs,
  ക്രെഡൻഷ്യൽ-ഉള്ള കണക്ഷൻ സ്ട്രിംഗ് (`mongodb://user:pass@...`, തുടങ്ങിയവ),
  ഒരു ജനറിക് `Authorization`/`x-api-key`/`api-key`/`apikey` ഹെഡർ-വാല്യു
  പാറ്റേൺ. ഹെഡർ-രൂപത്തിലുള്ള കീകൾ (`authorization`, `x-api-key`, `api-key`,
  `apikey`) ഘടനാപരമായി (വാല്യു മാത്രം, സ്കീം പ്രിഫിക്സ് പോലുള്ള)
  പുനരാഖ്യായനം ചെയ്യുന്നു, ജനറിക് ടെക്സ്റ്റ് regex വഴി അല്ല.
- ഗാർഡ്‌റെയിൽ ഒരിക്കലും ബ്ലോക്ക് ചെയ്യുകയില്ല; ഇത് മാത്രം പുനരാഖ്യായനം ചെയ്യുന്നു (`modifiedPayload` /
  `modifiedResponse`) കൂടാതെ അടയാളപ്പെടുത്തുന്നു (`meta.credentialsRedacted`, `meta.count`).

റിഗ്രഷൻ ഗാർഡ്: `tests/unit/credential-masker-guardrail.test.ts`.

## അടിസ്ഥാന കരാർ (base.ts)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true short-circuits the chain
  message?: string; // തടയുമ്പോൾ ഇത് ദൃശ്യമാകും
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // അഭ്യർത്ഥന മാറ്റിയെഴുതാൻ preCall തിരികെ നൽകുന്നത്
  modifiedResponse?: TValue; // പ്രതികരണം മാറ്റിയെഴുതാൻ postCall തിരികെ നൽകുന്നത്
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ഒരു ഗാർഡ്റെയിൽ "മാറ്റമില്ല" എന്ന് സൂചിപ്പിക്കുന്നത് ``void`, `{}`, അല്ലെങ്കിൽ `{ block: false }`തിരികെ നൽകിക്കൊണ്ടാണ്.`modifiedPayload`/`modifiedResponse`തിരികെ നൽകുന്നത്, താഴെയുള്ള ഗാർഡ്റെയിലുകൾക്കായി ചെയിനിലൂടെ ഒഴുകുന്ന മൂല്യത്തെ മാറ്റിസ്ഥാപിക്കുന്നു.`signal?: AbortSignal` കോളർ ലൈഫ്സൈക്കിളിനെ ഗാർഡ്റെയിലുകളിലേക്ക് എത്തിക്കുന്നു. ഒരു അഭ്യർത്ഥന റദ്ദാക്കൽ എന്നത് മനഃപൂർവമായ ഒരു ഫെയിൽ-ഓപ്പൺ അപവാദമാണ്: മീഡിയ ബ്രിഡ്ജുകൾ പ്രവർത്തിക്കുന്നത് നിർത്തുകയും, അസംസ്കൃത മീഡിയയെ പിന്തുണയ്ക്കാത്ത ഒരു ലക്ഷ്യസ്ഥാനത്തേക്ക് പുനഃസ്ഥാപിക്കാതെ വൃത്തിയാക്കുകയും ചെയ്യുന്നു.

## രജിസ്ട്രി (registry.ts)

സിംഗിൾട്ടൺ `guardrailRegistry` താഴെ പറയുന്നവ നൽകുന്നു:

- `register(guardrail)` — ഒരു ഗാർഡ്റെയിൽ ചേർക്കുന്നു (അല്ലെങ്കിൽ സാധാരണമാക്കിയ പേര് ഉപയോഗിച്ച് മാറ്റിസ്ഥാപിക്കുന്നു) കൂടാതെ ആരോഹണ ക്രമത്തിൽ `priority` അനുസരിച്ച് വീണ്ടും ക്രമീകരിക്കുന്നു.
- `clear()` / `list()` — അഡ്മിനിസ്ട്രേറ്റീവ് സഹായികൾ.
- `runPreCallHooks(payload, context)` — സജീവ ഗാർഡ്റെയിലുകളിലൂടെ ആവർത്തിക്കുന്നു, `modifiedPayload` വഴി പേലോഡിനെ കടത്തിവിടുന്നു, കൂടാതെ ആദ്യത്തെ `block: true` വരുമ്പോൾ നിർത്തുന്നു.
- `runPostCallHooks(response, context)` — പ്രതികരണ ഭാഗത്തും ഇതേ പ്രവാഹം.
- `resetGuardrailsForTests({ registerDefaults })` — നിലവിലെ അവസ്ഥ മായ്ക്കുന്നു കൂടാതെ വൃത്തിയുള്ള ടെസ്റ്റ് ഐസൊലേഷനായി ഡിഫോൾട്ടുകൾ ഓപ്ഷണലായി വീണ്ടും രജിസ്റ്റർ ചെയ്യുന്നു.

രണ്ട് റണ്ണറുകളും `{ blocked, payload|response, results, guardrail?, message? }` തിരികെ നൽകുന്നു, ഇവിടെ `results` എന്നത് `GuardrailExecutionResult` റെക്കോർഡുകളുടെ ഒരു നിരയാണ്, അതിൽ ഓരോ ഗാർഡ്റെയിലിനുമുള്ള `blocked`, `skipped`, `modified`, `error`, `meta` ഫീൽഡുകൾ ഉൾപ്പെടുന്നു, ഇത് ട്രേസിംഗിന് ഉപയോഗപ്രദമാണ്.

### ഓരോ അഭ്യർത്ഥനയ്ക്കും ഗാർഡ്റെയിലുകൾ പ്രവർത്തനരഹിതമാക്കുന്നു

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })` നിലവിലെ അഭ്യർത്ഥനയ്ക്കായി ഒഴിവാക്കേണ്ട ഗാർഡ്റെയിൽ പേരുകളുടെ ഡ്യൂപ്ലിക്കേഷൻ ഒഴിവാക്കിയ ഒരു ലിസ്റ്റ് ശേഖരിക്കുന്നു. ഉറവിടങ്ങൾ (എല്ലാം ഓപ്ഷണൽ, എല്ലാം ലയിപ്പിച്ചത്):

- `apiKeyInfo.disabledGuardrails`
- അഭ്യർത്ഥന ബോഡി `disabledGuardrails` (ടോപ്പ്-ലെവൽ)
- അഭ്യർത്ഥന ബോഡി `metadata.disabledGuardrails`
- ഹെഡർ `x-omniroute-disabled-guardrails` (അല്ലെങ്കിൽ പഴയ `x-disabled-guardrails`)

മൂല്യങ്ങൾ സ്ട്രിംഗുകളുടെ നിരകളോ കോമയാൽ വേർതിരിച്ച സ്ട്രിംഗോ ആകാം; പേരുകൾ ലോവർകേസ് കെബാബ്-കേസിലേക്ക് സാധാരണമാക്കുന്നു (`pii_masker` → `pii-masker`). ഫലം `context.disabledGuardrails` വഴി രജിസ്ട്രിയിലേക്ക് കൈമാറുന്നു, ഇത് പൊരുത്തപ്പെടുന്ന ഗാർഡ്റെയിലുകളെ ഒഴിവാക്കുന്നു (`results`-ൽ `skipped: true`).

## എക്സിക്യൂഷൻ ഓർഡർ

`src/sse/handlers/chat.ts`, `open-sse/handlers/chatCore.ts` എന്നിവയിലൂടെ ഒഴുകുന്ന ഓരോ അഭ്യർത്ഥനയ്ക്കും:

1. `resolveDisabledGuardrails(...)` API കീ, ബോഡി, ഹെഡറുകൾ എന്നിവയിൽ നിന്ന് സ്കിപ്പ് ലിസ്റ്റ് നിർമ്മിക്കുന്നു.
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ഗാർഡ്റെയിലുകൾ ആരോഹണ മുൻഗണനാ ക്രമത്തിൽ പ്രവർത്തിപ്പിക്കുന്നു:
   - പ്രവർത്തനരഹിതമാക്കിയ ഗാർഡ്റെയിലുകൾ `skipped` എന്ന് രേഖപ്പെടുത്തുന്നു.
   - ഓരോ ഗാർഡ്റെയിലിന്റെയും `preCall` `modifiedPayload` വഴി പേലോഡ് മാറ്റിയെഴുതിയേക്കാം.
   - ആദ്യത്തെ `block: true` ചെയിൻ ചുരുക്കുകയും ഹാൻഡ്ലർ ഒരു ഗാർഡ്റെയിൽ നിരസിക്കൽ പ്രതികരണം നൽകുകയും ചെയ്യുന്നു.
3. (സാധ്യതയുള്ള മാറ്റിയെഴുതിയ) പേലോഡ് കോംബോ റൂട്ടിംഗിലേക്കും അപ്സ്ട്രീം ഡിസ്പാച്ചിലേക്കും ഒഴുകുന്നു.
4. പ്രതികരണം കൂട്ടിച്ചേർത്ത ശേഷം, `guardrailRegistry.runPostCallHooks(...)` പ്രതികരണത്തിൽ അതേ ചെയിൻ പ്രവർത്തിപ്പിക്കുന്നു. ഇവിടെ `block: true` അപ്സ്ട്രീം പ്രതികരണം ഒഴിവാക്കുന്നു.

തെറ്റ് വരുത്തുന്ന ഗാർഡ്റെയിലുകൾ `error: <message>` എന്ന് രേഖപ്പെടുത്തുകയും `logger.warn` വഴി ലോഗ് ചെയ്യുകയും ചെയ്യുന്നു, പക്ഷേ ചെയിൻ തുടരുന്നു — രൂപകൽപ്പന പ്രകാരം ഫെയിൽ-ഓപ്പൺ.

## കോൺഫിഗറേഷൻ

ബിൽറ്റ്-ഇൻ ഗാർഡ്റെയിലുകൾ വായിക്കുന്ന എൻവയോൺമെന്റ് വേരിയബിളുകൾ:

| വേരിയബിൾ                              | ഉപയോഗിക്കുന്നത്           | പ്രഭാവം                                                                                                             |
| ------------------------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `INPUT_SANITIZER_ENABLED`             | `prompt-injection`        | കണ്ടെത്തൽ പൂർണ്ണമായും പ്രവർത്തനരഹിതമാക്കാൻ `false` എന്ന് സജ്ജമാക്കുക.                                               |
| `INPUT_SANITIZER_MODE`                | `prompt-injection`        | ഇൻജക്ഷൻ പോളിസി: `warn`, `block`, അല്ലെങ്കിൽ `log`. പഴയ മൂല്യം `redact` ഇൻജക്ഷൻ ടെക്സ്റ്റ് മാറ്റിയെഴുതുന്നില്ല.      |
| `INJECTION_GUARD_MODE`                | `prompt-injection`        | ഇൻജക്ഷൻ ഗാർഡിനായുള്ള മോഡ്; എൻവയോൺമെന്റ് വേരിയബിളുകളെ **അസാധുവാക്കുന്ന** ഒരു DB ഫീച്ചർ ഫ്ലാഗ് കൂടിയാണിത് (DB > ENV). |
| `INPUT_SANITIZER_BLOCK_THRESHOLD`     | `prompt-injection`        | `MODE=block` നിരസിക്കുന്ന ഏറ്റവും കുറഞ്ഞ തീവ്രത: `high` (സ്ഥിരസ്ഥിതി), `medium`, അല്ലെങ്കിൽ `low`.                  |
| `INJECTION_GUARD_BLOCK_THRESHOLD`     | `prompt-injection`        | `INPUT_SANITIZER_BLOCK_THRESHOLD` എന്നതിന്റെ പഴയ പേര്.                                                              |
| `PII_REDACTION_ENABLED`               | `pii-masker`              | `true` ആയിരിക്കുമ്പോൾ, അഭ്യർത്ഥന PII റെഡാക്ട് ചെയ്യപ്പെടുന്നു (ഇൻജക്ഷൻ മോഡിൽ നിന്ന് സ്വതന്ത്രമായി).                 |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (ഡൗൺസ്ട്രീം) | പ്രതികരണ-വശത്തുള്ള മാസ്കർ സ്വഭാവം നിയന്ത്രിക്കുന്നു.                                                                |

മോഡാലിറ്റി ബ്രിഡ്ജ് ഗാർഡ്റെയിലുകൾ DB-ബാക്ക്ഡ് സെറ്റിംഗ്സ് സ്റ്റോറിൽ നിന്ന് (`getSettings()`) റൺടൈം കോൺഫിഗറേഷൻ വായിക്കുന്നു, എൻവയോൺമെന്റ് വേരിയബിളുകളിൽ നിന്നല്ല. വിഷന്റെ പ്രാഥമിക കീകൾ `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, `modalityBridgeCacheMaxEntries` എന്നിവയാണ്. പഴയ `visionBridge*` കീകൾ ഡോക്യുമെന്റ് ചെയ്ത വൺ-സൈക്കിൾ റീഡ് ഫാൾബാക്കായി മാത്രമേ സ്വീകരിക്കുകയുള്ളൂ; ഡാഷ്ബോർഡ് റൈറ്റുകൾ പ്രാഥമിക കീകൾ ഉപയോഗിക്കുന്നു. സ്ഥിരസ്ഥിതികളും ഫാൾബാക്ക് റെസല്യൂവറും `src/shared/constants/modalityBridgeDefaults.ts` എന്നതിലാണ്, പഴയ സ്ഥിരാങ്കങ്ങൾ `src/shared/constants/visionBridgeDefaults.ts` എന്നതിൽ നിലനിർത്തുന്നു.

ഓഡിയോ `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout`, `modalityBridgeAudioMaxClips` എന്നിവയും പങ്കിട്ട `modalityBridgeCache*` ക്രമീകരണങ്ങളും ഉപയോഗിക്കുന്നു. മോഡാലിറ്റി ബ്രിഡ്ജ് സ്കീമയോടൊപ്പം ഈ കീകൾ അവതരിപ്പിച്ചതിനാൽ ഓഡിയോയ്ക്ക് പഴയ-കീ ഫാൾബാക്ക് ഇല്ല.

വീഡിയോ `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos`, `modalityBridgeVideoTimeout` എന്നിവയും പങ്കിട്ട `modalityBridgeCache*` ക്രമീകരണങ്ങളും ഉപയോഗിക്കുന്നു. FFmpeg/ffprobe ഓപ്ഷണൽ ഓപ്പറേഷണൽ ഡിപൻഡൻസികളും ഫ്രെയിം ക്യാപ്ഷനിംഗ് ലേറ്റൻസിയും മോഡൽ ചെലവും വർദ്ധിപ്പിക്കുന്നതിനാൽ ഇത് സ്ഥിരസ്ഥിതിയായി പ്രവർത്തനരഹിതമാക്കിയിരിക്കുന്നു.

## കസ്റ്റം ഗാർഡ്റെയിലുകൾ

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

ഘട്ടങ്ങൾ:

1.  `BaseGuardrail` വികസിപ്പിച്ച് `src/lib/guardrails/myGuardrail.ts` ഉണ്ടാക്കുക.
2.  `preCall`, `postCall` എന്നിവ നടപ്പിലാക്കുക.
3.  ഇറക്കുമതി ചെയ്യുന്ന സമയത്ത് ( `registerDefaultGuardrails` ൽ നിന്ന് പുഷ് ചെയ്യുക) അല്ലെങ്കിൽ റൺടൈമിൽ `guardrailRegistry.register(...)` വിളിക്കുക — രജിസ്ട്രി, അതേ സാധാരണവൽക്കരിച്ച പേരുള്ള മുൻ ഗാർഡ്റെയിലിനെ മാറ്റിസ്ഥാപിക്കും.
4.  `tests/unit/` ന് കീഴിൽ ടെസ്റ്റുകൾ ചേർക്കുക (നിലവിലുള്ള ഉദാഹരണങ്ങൾ: `tests/unit/guardrails-registry.test.ts`, `tests/unit/prompt-injection-guard.test.ts`, `tests/unit/guardrails/visionBridge.test.ts`).

## പരിശോധന

അറിയപ്പെടുന്ന അവസ്ഥയിൽ നിന്ന് ആരംഭിക്കാൻ ടെസ്റ്റുകൾക്കിടയിൽ `resetGuardrailsForTests()` ഉപയോഗിക്കുക. ശൂന്യമായ ഒരു രജിസ്ട്രിയിൽ നിന്ന് ആരംഭിച്ച്, പരിശോധനയിലുള്ള ഗാർഡ്റെയിലുകൾ മാത്രം രജിസ്റ്റർ ചെയ്യാൻ `{ registerDefaults: false }` നൽകുക. വിഷൻ ബ്രിഡ്ജ് ഡിപൻഡൻസി ഇൻജക്ഷൻ (`deps.getSettings`, `deps.callVisionModel`) സ്വീകരിക്കുന്നു; ഓഡിയോ ബ്രിഡ്ജ് ക്രമീകരണങ്ങൾ, കഴിവുകൾ, STT മോഡൽ തിരഞ്ഞെടുക്കൽ, ക്രെഡൻഷ്യൽ പരിശോധനകൾ, ട്രാൻസ്ക്രിപ്ഷൻ എന്നിവയ്ക്കായി സമാനമായ സീമുകൾ നൽകുന്നു. അതിനാൽ, ഡാറ്റാബേസ് അല്ലെങ്കിൽ നെറ്റ്വർക്ക് ആക്സസ് ഇല്ലാതെ തന്നെ ടെസ്റ്റുകൾക്ക് രണ്ട് ഫ്ലോകളും പ്രവർത്തിപ്പിക്കാൻ കഴിയും.

## ഇൻജക്ഷൻ-ഗാർഡ് റൂട്ട് കവറേജ് & റെഡ്-ടീം (ഘട്ടം 8 · ബ്ലോക്ക് D)

ഇൻജക്ഷൻ-ഗാർഡ് (`createInjectionGuard` / `withInjectionGuard`) ഉപയോക്തൃ പ്രോംപ്റ്റുകൾ സ്വീകരിക്കുന്ന എല്ലാ റൂട്ടുകളെയും ഉൾക്കൊള്ളുന്നു. ഇത് `INJECTION_GUARD_MODE` നെ മാനിക്കുന്നു (സ്ഥിരസ്ഥിതി `warn` = ലോഗ് മാത്രം; `block` = HTTP 400 `SECURITY_001` തിരികെ നൽകുന്നു).

| തരം             | റൂട്ടുകൾ                                                                                                                                      | സ്ഥിരസ്ഥിതി മോഡ് |
| :-------------- | :-------------------------------------------------------------------------------------------------------------------------------------------- | :--------------- |
| Text (existing) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                       | warn             |
| Generative      | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn             |
| Data            | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                               | warn             |

ടെക്സ്റ്റ് എക്സ്ട്രാക്ഷൻ (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` എന്നിവയെ ഉൾക്കൊള്ളുന്നു.

**റെഡ്-ടീം (രാത്രികാല, `nightly-llm-security.yml`):** `INJECTION_GUARD_MODE=block` ആയിരിക്കുമ്പോൾ ഓരോ റൂട്ടും OWASP-LLM കോർപ്പസിനെ തടയുന്നുവെന്ന് promptfoo സാധൂകരിക്കുന്നു; garak പ്രോബുകൾ പ്രവർത്തിപ്പിക്കുന്നു (രഹസ്യമില്ലാതെ ഒഴിവാക്കുന്നു). സ്ഥിരതയ്ക്കായി `moderations` ഉൾപ്പെടുത്തിയിട്ടുണ്ട് — ബ്ലോക്ക്-മോഡിലുള്ള ഓപ്പറേറ്റർമാർക്ക് `resolveDisabledGuardrails` വഴി ഇതിനെ ഒഴിവാക്കാം.

രാത്രികാല വർക്ക്ഫ്ലോ (`.github/workflows/nightly-llm-security.yml`, cron + മാനുവൽ ഡിസ്പാച്ച്) ന് രണ്ട് ജോലികളുണ്ട്:

- **`promptfoo-guard` (തടയുന്നത്)** — `INJECTION_GUARD_MODE=block` ഉപയോഗിച്ച് `promptfoo eval -c promptfooconfig.yaml` പ്രവർത്തിപ്പിക്കുന്നു. ഓരോ പ്രതികൂല സാഹചര്യവും (ഉദാഹരണത്തിന്, "മുമ്പത്തെ എല്ലാ നിർദ്ദേശങ്ങളും അവഗണിക്കുക...", DAN-ശൈലിയിലുള്ള ജയിൽബ്രേക്കുകൾ) പ്രതികരണത്തിൽ `error.code === "SECURITY_001"` ഉണ്ടെന്ന് ഉറപ്പാക്കുന്നു, അതായത് ഗാർഡ് യഥാർത്ഥത്തിൽ അഭ്യർത്ഥന നിരസിച്ചു.
- **`garak` (ഉപദേശക)** — ഒരു പ്രാദേശിക OmniRoute ഇൻസ്റ്റൻസിനെതിരെ (`http://localhost:20128/v1`) garak `--probes promptinject,dan,leakreplay` പ്രവർത്തിപ്പിക്കുന്നു. ഒരു പ്രൊവൈഡർ രഹസ്യം (`PROMPTFOO_PROVIDER_KEY`) വഴി നിയന്ത്രിക്കപ്പെടുന്നു; ഇത് ഭംഗിയായി ഒഴിവാക്കുകയും `|| true` എന്ന് ചേർക്കുകയും ചെയ്യുന്നു, അതിനാൽ CI പരാജയപ്പെടാതെ റിപ്പോർട്ട് ചെയ്യുന്നു.

ഗാർഡ് ഹെൽപ്പറിന്റെ (`createInjectionGuard` / `withInjectionGuard`) കവറേജ് എല്ലാ പ്രോംപ്റ്റ്-ഉൾക്കൊള്ളുന്ന `/v1` റൂട്ടുകളിലും വ്യാപിക്കുന്നു; പ്രോംപ്റ്റ് ടെക്സ്റ്റ് `src/shared/utils/inputSanitizer.ts` ലെ `extractMessageContents()` വഴി `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` എന്നിവയിൽ നിന്ന് വലിച്ചെടുക്കുന്നു.
